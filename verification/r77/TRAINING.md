# R77 training changes and verification

Product ownership: `ResearchDirectorR952` and `DevelopmentProductionCP12` only. No REAL eligibility, statistical thresholds, labels, quality receipts, or forecast authority are relaxed.

The Director alternates a ready modern training reservation with its persistent six-owner wheel. The normal cursor advances only on normal turns. A reservation requires the same 350 ms admission as TRAIN; with 125–349 ms remaining, an ordinary POST/MATRIX owner still runs. An empty modern queue uses the original wheel. The existing worker, slice, writer, queue and leases remain the owners.

Feature materialization now stops at 64 rows **or** a conservatively accounted 128 KiB retained byte bound. Four process-local prepared pages at most reserve 512 KiB through the existing shared memory budget. The former 1 MiB work scratch reservation remains. A failed publication or P0 interruption retains only a recomputable completed prefix. Publication still requires the new current lease, exact protocol/input identity, previous durable prefix and queue cursor in the existing atomic transaction. Restart loses this cache and resumes the durable prefix. Nothing publishes under P0 and the cache is not a receipt.

## Scope of evidence

`training_final/summary.json` and its logs record the final sealed 3,421-class release replay (classset `cacfd80efeb17c3ad48a6ae9b61f1d0a6c94ff45c57429c9338467ad1f1e6266`), with zero product overlays and byte-for-byte class verification after testing. From zero feature rows through two independent process restarts, all 16 modern tasks reached 21,120 feature rows, 16 development receipts, 16 artifact identities and 16 completed freezes. The isolated publication/P0/cache-bound/fairness/low-budget and synthetic online recovery tests also passed. These remain host tests, not phone timing or quality proof. The earlier `training_receipt.json` records development checks. Tests call actual product owners and real SQLite through the host Android API adapter. `training_ContinuityR77` calls the complete 22-lane continuity entry, records all Director owners and feature progress, verifies P0 produces no training publication and requires injected write failures/slow reads to actually occur. Callbacks are **not** lottery periods. The 77-callback tests do not claim that 77 fresh draws were captured.

`training_PreparedPageR77` injects a failed real feature INSERT or mid-publication P0, verifies rollback, reclaims a newer lease generation, temporarily hides the CAS file and proves the retained page commits without another decode. Original code fails with `TRAIN_CAS_MISSING`. `training_CacheBoundR77` fails five real publications and proves retained memory is bounded to four pages / 512 KiB. `training_DirectorFairnessR77` verifies restart, all other owners, empty queues, P0, unusable tails and the short-budget POST/MATRIX regression. `training_OnlineContinuityR77` uses explicitly synthetic valid legacy labels: after mid-prepare P0 and a crashed lease, the full continuity entry commits 13 numerical artifacts and feedback receipts, including 12 chronological updates, exactly once. These synthetic records never become phone observations, certificates or REAL.

Use the canonical `android.os.SystemClock` backed by `System.nanoTime`, never the old call-count test clock. The continuity harness fails if repeated clock calls themselves advance time. Earlier exploratory scratch runs `full-entry-v2`, `full-entry-faults-v3`, and `whole-*` used the wrong clock and are **INVALID** for acceptance. Their apparent numerical stall was a fixture defect, not a product defect, and did not justify a dataset cache or a larger budget.

## Report reconstruction boundaries

The new phone report contains 16 modern immutable input identities. Reconstruction generates their original CAS bytes and verifies the original SHA-256 and byte counts. Feature blobs are omitted in the report, so tests start from zero feature prefixes; this is a controlled reconstruction, not a copy of the phone database.

Eleven of the twelve exported historical feature-prefix hashes match recomputation. The oldest 15-row prefix does not: task `cc62a6dd090cd9452b6eddb453f30f94306122e02bef3c9f4deb8b442414f7ee`, candidate `CP12-FAMILY-274334c38654068cd68962c4`, target `202610130328`. The phone reports `f7ab099c…`; both the R76 product-source rebuild and R77 compute `cf54379a…`. This predates R76. Its feature payload was not exported, so its precise original contents cannot be inferred. This is not a passed historic-prefix compatibility check. Existing `readPrefix` verifies stored-row contiguity and the hash chain against the durable cursor; it does not recompute old feature values under the current program. A matching stored old prefix alone cannot prove feature-semantic compatibility.

The report also omits `r967_numeric_training_run` and `r967_numeric_training_input`. Its V2 online stream cannot be authentically replayed without those sidecars. A reconstruction error caused by the missing run is not evidence that the phone has the same error. The independent synthetic online recovery test proves owner recovery, not the missing phone sidecar's validity.

The R76 negative source build exports all 834 controlled product Java files from `2e82e9834a081be2a0e0f4ec326572df634e0543`, plus the R76 generated semantic identity matching the delivered build receipt. Its generated source/build metadata is host support, not a claim to original R76 APK bytecode or toolchain provenance.
