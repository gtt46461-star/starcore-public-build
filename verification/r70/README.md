# R70 报告核验与运行修复

本次输入为 R69 的 `检测报告.zip`。外层 ZIP 可完整读取，内部 39 个成员的原始字节数与 SHA-256 全部一致；96 项检测有执行结果。导出完整不等于软件通过验收：原报告包含 6 FAIL、6 WARN、20 NOT_PROVEN。原始 SQLite 与训练载荷按报告既定范围未导出，不能据此在主机恢复用户整个运行库。

## 已修改的具体问题

1. **后台恢复**：`AutoFetchService` 的低内存回调不再在 Android 主线程写数据库。先释放可重建缓存，再由已有 runtime guard 去重执行持久化、循环修复和分析补发。继续尊重用户停止状态。
2. **倒计时/出号停滞**：`BusinessReconcilerR36` 将已识别的请求持久化锁超时交给已有 watchdog 重试，保留原期号和开奖前截止时间，并继续排队结算。数据库/哈希错误仍向外报告。倒计时不制造新的一分钟；没有新开奖时不会伪造循环。
3. **研究链路**：`ResearchCaptureQueueR946` 把正式预约纳入未完成判断与重启恢复，旧版已审核训练流也使用同一兼容性谓词。`ResearchPredrawCaptureR923` 优先完成已接纳的连续观察，再做原子发现；不增加另一个研究线程。中断续接复核进一步将研究续跑改为单个可取消 Runnable，避免外部开奖触发与匿名延时续跑叠加出多个重试链。
4. **逐期训练/迭代**：保留 TRAIN、POST、MATRIX、RESEARCH、EVOLVE、IMPORT 原有责任划分和逐期标签隔离。审核 R65–R69 的精确训练续接；不继承旧证书或伪造未来样本。新一代须经独立未来验证，不能保证每代必然更强。
5. **程序调用冲突**：修复主线程写库与研究任务完成状态不一致；本版在真实 SQLite 上验证事务、任务轮转、矩阵水位、重复提交与竞态拒绝。
6. **O01–O09**：保留完整生产源、目录及原施工台账；本次不是把旧台账的未核验项改写成通过。当前 830 个 Java 生产源实际编译，重新冻结真实编译调用索引，执行标准 O09 构建入口。手机整机验收仍须设备数据。
7. **挑战者/证书/主链为零**：报告有 58 次连续采集断档、253 个校准研究、0 校准模型及 0 正式窗口。将正式采集的 50ms 估算预算改为最多 400ms 执行片段，仍受总计 1200ms 与关键任务抢占约束。界面短期正收益不等于独立校准及正式证书。
8. **结算**：保持唯一 SettlementEngine。实际 OOS 写入路径验证了无 owner 拒绝、事务回滚、精确重放、重复结算去重和输入漂移拒绝。
9. **内存/存储**：`LanePolicyCompiler` 与 `CompiledActionContract` 在新期开始时清除旧期缓存；10,000 期 × 40 候选定向回归保持 40 条。存储回收不再等待研究全部结束，也不被普通轮询的安静等待窗口无限推迟；回收失败不再记成完成。未完成保留任务 5 秒后续作，仅无可清理数据时等待 60 秒。保持 5000 条开奖热数据和未完成消费者的精确输入，不直接删除保护中的证据。
10. **合格算法进入主链**：用实际证书发布器验证 241 条独立校准观察、360 条合成正式观察、16 个矩阵视图，证书可发布。实际主链 owner 能选中该证书；重复调用不重复选取，撤销/开奖竞态正确拒绝。全部测试位于隔离数据库，不向用户库注入合成证书，也不放宽 REAL 闸门。
11. **诊断与自检**：报告补充校准失败、校准模型、存储回收和低内存恢复状态；快照时间在备份结束立即记录，不把后续哈希耗时算成业务停滞。测试命令与日志随本目录保存。
