# Default-budget memory integration review

The committed E96 Gradle run executed 428 tests with 17 failures. Its receipt shows 15 direct MEMORY_DECLARED_CAPACITY failures, one BORN/REJECTED assertion (resource misclassification was separately repaired), and one H15 source-preservation mismatch. The later fix5 direct same-JVM diagnostic executed 427 tests, explicitly excluding H15, with 19 failures: 18 resource-wait failures (one wrapped by assertThrows), plus the expected stale generated-source identity of the temporary overlay. These are different source/run scopes; neither result is a passing full Gradle suite.

Fresh isolated runs copied seven actual production sources plus the two unchanged math test sources, compiled them against the existing app/test support classes, and launched each class in its own real `java -Xmx512m`. Actual maxMemory was 536,870,912; ordinary JUnit test methods executed on `main`, thread id 1. R27Evolution was 3 tests / 2 failures; R30NullPipeline was 3 / 2. Therefore those failures were not solely contamination from preceding test classes. The passing planted-signal method detected its synthetic signal in 2 generations; its name's 50-generation upper limit does not establish a 50-generation endurance run or natural strategy quality.

JUnit creates ordinary test instances per method but keeps the worker process and static stores alive. The repository does not configure test forkEvery, test heap, or method timeout for these two classes. The same-JVM harness records the previous Gradle XML class order, but method scheduling and telemetry overhead still make it a diagnostic rather than a Gradle-equivalent acceptance run. Normal static shared feature storage is bounded (32MiB at this heap); weak registries do not on their own prove immediate physical reclamation. The replay thread-local retains one Freeze with tiny K3/probability arrays; its evolution limit is removed in finally. No evidence identified those thread-locals as the large-object root.

The real resource boundary is lower than the soft-pressure label: optional work reserves 15% headroom below a 75% heap high-water limit, leaving roughly 60% before outstanding allocation promises. Waits near 322MiB at a 512MiB max can therefore occur while the separate soft-pressure state still says NORMAL. Later source now reports this optional admission denial explicitly. Clearing a cache reference is not permission to subtract its bytes from measured heap, and a heap dump made after failure unwinds/trims cannot establish the heap's strong roots at the earlier admission instant.

Kernel/cache methods should report a typed RESOURCE_WAIT after bounded reclamation attempts. The actual task/continuation scheduler owns later retries from the committed snapshot, with current owner/fence and input checks. It must wait for a real observable capacity change, retain fair scheduling and cancellation, and avoid replaying partial uncommitted state as if it were committed. A direct mathematical fixture has no such scheduler; catching a wait and blindly re-running its partly mutated loop would not reproduce that contract. One successful 128-candidate generation or injected pause/resume does not establish indefinitely progressing multi-generation research.

The review found real production lifecycle defects in temporary control caches, replacement contexts, and abandoned Q08 workspaces. Root authorized a five-file lifecycle repair (three production owners and the two old fixtures), while another owner repaired per-budget ReferenceQueue accounting for truly collected private primitive backings. All source and results are recorded in `../memory-owned-lifecycle/`. No fake probe, heap increase, forced GC, threshold change, or mathematical assertion deletion was used.

After the production close integration and lifecycle-only fixture adaptation, all 11 R27 and 20 Q08 assertion calls remain byte-identical to E96, and every numerical token is unchanged. The fixed eleven-source snapshot again measured the default heap. H06 and the complete 18-step H12 restore/event-identity assertions pass; all four original bounded-replay tests, including exact serial/parallel 128-candidate output comparison, also passed on the earlier fixed source snapshot. New actual-body lifecycle checks prove that close defers context retirement until both helper bodies exit and that caller-owned caches remain usable. These are specific passing contracts.

The final two old classes still contain three real resource-wait failures: the 100x3 negative control and both complete Q08/control-resume scenarios. Their original logs remain intact. Thus process isolation or correct fixture closure alone cannot be represented as resolving continuous research capacity. Final source freezing, unexcluded Gradle, actual Runtime teardown integration, long-running default-budget progression and device evidence remain root's separate gates.
