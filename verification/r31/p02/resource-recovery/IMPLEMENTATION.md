# Aged optional-heap recovery

This increment contributes to R31-B05-C11/P02. The only owned production change is `MemoryBudgetR31.java`. The root agent owns and separately verifies the `RuntimeCoordinatorR26` consumer. It does not establish complete card acceptance, a device result, continuous 24/72-hour operation or natural model quality.

The optional Java ceiling is the 0.75 heap waterline less at least 0.15 realtime reserve, pending allocation promises and applicable UI reserve. At measured heap near 0.64 of maximum, actual optional admission may fail while the heap watermark remains NORMAL. Dropping references/closing declarations does not decrement that measured heap. With no subsequent allocations there may be no automatic collector trigger. Earlier code recorded this aged wait without requesting an action. Ordinary bounded reference trim and real remeasurement remain first; this increment supplies the explicit aged-controller fallback.

The public synchronous interface is `recoverAgedOptionalHeapR31(String controllerOwner, BooleanSupplier safeBackgroundWindow)`. Only the background resource controller may call it; the predicate must establish no cancellation, no interrupted caller, no transaction, no writing task and no realtime critical window. The interface checks this predicate again after acquiring the process gate and immediately before requesting collection, and rejects Android's main Looper (or an unavailable Android UI-thread observation). The interface has no hard collector timeout. Android GC pauses and realtime latency still need device calibration.

It independently requires the actual `RuntimeProbe`, an actual active optional Java refusal with at least 120 seconds on the real monotonic clock, and a request that could fit if measured heap were reclaimed. Native/cancellation/unknown-capacity waits and debt caused by pending promises or an oversized request are not collectible heap problems. In particular, if the request cannot fit even with heap=0, collection is skipped and the live promises remain owned.

One process-wide gate allows at most one in-flight collector request. An actual request starts a five-minute monotonic cooldown. Budget and process gate locks never nest in the inverse order; a competing caller's skipped receipt is built after releasing the process gate. There is exactly one explicit `Runtime.getRuntime().gc()` site, in this controller interface. Admission, cache trim, model mathematics, normal tests and checkpoint writers do not call it. The original mathematical test iterations and assertions must pass separately without using the controller collector interface.

An actual result distinguishes `attempted`, `outcome`, `reason`, compact immutable before/after measurements, request/control duration, observed GC counters and count delta, the next allowed request time, `capacityDebt` and `businessProgress=false`. `optionalHeapRecovery` in ordinary sample/snapshot exposes `lastDecision` separately from `lastActualAttempt`, so a subsequent cooldown/unsafe skip cannot erase actual before/after evidence. These records do not recursively retain prior samples, arbitrary closures, model arrays or an unbounded history.

JMX counters/time are actual HOST readings. On Android the API reads available ART runtime statistics through reflection; count/time are explicit unknown/unsupported if missing, and raw ART time is not labeled as milliseconds. RuntimeProbe native/PSS/RSS observations retain the existing at-most-1-Hz sampler and do not enter Java heap arithmetic. A collector request can be ignored or finish later. Observed heap differences may include concurrent allocations and are not attributed owner-release bytes. Only a fresh actual admission check permits work; admission recovery is not a model checkpoint, business progress or natural quality.

`RECEIPT.json` binds the exact production/test/tool sources and records four guard JUnit tests plus two separate default-512m host JVMs. Neither a Probe nor a clock is substituted. Both workloads wait more than 120 actual seconds. The unreachable-garbage workload observed heap 345,717,936 to 1,321,768 bytes with GC count +1 and an actual successful new admission. The strongly-held workload observed heap 345,483,960 to 345,569,840 bytes with GC count +1 but correctly retained CAPACITY_WAIT, its payload and its live leases. Real competing callers exercised the single-flight gate and budget snapshot lock path; the held case also tested cooldown and preservation of `lastActualAttempt`. These are labeled engineering owner/garbage fixtures, not model datasets or quality results.
