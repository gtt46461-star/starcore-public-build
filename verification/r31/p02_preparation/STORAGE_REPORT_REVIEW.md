## Non-negotiable process and lock boundaries

`AndroidManifest.xml` declares `ReportExportServiceCP4` in `:diagnostics`. Its `requireDiagnosticProcess()` enforces this. Report SQLite/native work is intentionally isolated and opens the business DB read-only. Keep that arrangement.

A static Java MemoryBudget object in RuntimeCoordinator is not shared with `:diagnostics`. Report Java heap, native heap and PSS/RSS by PID/process and measured time. PSS is not the sum of heap and native counters. A cross-process total requires an actual IPC or file protocol; do not claim that a static singleton supplies it.

Use the existing cross-process file-lock pattern for disk reservations; do not open another business SQLite writer from diagnostics. `ReportInputsLeaseCP12` deliberately keeps one descriptor per path because closing a second descriptor may release process-level POSIX locks. Preserve that property in the new reservation handles.

Suggested storage coordination:

1. One canonical app-private `r31-storage` namespace and one short exclusive admission lock, serialized within each JVM as well as across processes. Keep metadata small, bounded, atomic and fsynced. File traversal must not hold the business DB write lock.
2. Each reservation records fixed category, request/job/task owner, fence/generation, PID/boot/session, maximum growth, charged/remaining bytes, path scope, phase and exact close/recovery reason. Requests return a structured storage WAIT or protected-debt result; no silent expansion.
3. A reservation's OS lifetime lock prevents recovery while its actual writer is alive. Wall-clock expiry alone must not free it. After process death, take its lock, reconcile actual files/bytes, then recover unused allowance with a compare-and-set generation. An old handle cannot release a replacement reservation.
4. `beforeChunk` rejects exceeding the admitted bound and the minimum free-space floor before output is extended. Failure/cancel releases only unused allowance after the actual writer/resources have exited. Physical bytes still count until measured unlink/reuse; moving them elsewhere is not reclamation.
5. Keep declared peak reservation and measured bytes distinct. Avoid double-counting consumed reservation as both new physical bytes and remaining allocation; when a measurement boundary is uncertain, report a conservative overlap explicitly instead of inventing exact totals.

The normative totals are 1536MiB soft, 2048MiB normal admission, 3072MiB transient target and 4096MiB transient admission, with at least 256MiB OS free reserve. Category allocations in docs11 are refinements; `acceptance_config.json` has final precedence. Preserve a separate critical draw/freeze/settlement reserve and stop optional work when protected debt exceeds budget.

## Output admission seams that must be implemented, not assumed

`ReportArchiveCP4.Parts.write` currently writes directly to FileOutputStream. `ReportPublicationCP12.prepareSingleZip` and `boundZipR30` also create output streams directly. Neither currently accepts a per-chunk budget contract. A service-level free-space check is not equivalent to write-before-admission for these writers.

`ReportNativeCP4.Control.shouldContinue()` is called before each native `sqlite3_backup_step(...,100)`; `onBackupProgress` is called after it. Compression/decompression write through a Java OutputStream, allowing an admitted wrapper. Strict backup chunk accounting needs an explicit known page bound / pre-step hook. A post-step progress callback cannot honestly be described as pre-write admission. If these existing lower-level files need a compatibility overload, assign one file owner and record them as necessary interface changes; do not weaken native or archive verification.

`ReportExportServiceCP4.publish` currently runs inside the outer ReportInputsLease try block. SQLite readers and archive streams are closed by then, but the input pin is still live. The cleanup work item should be processed after that outer lease closes, still under the sole report journal owner. On user cancellation, the existing catch is outside the resource try block, so its current release ordering can be retained.

`DiagnosticReportProviderR923.openFile` acquires a ReportPublication lease for published job volumes. Recovery ZIPs currently resolve to `job=null` and return an ordinary descriptor. If recovery pruning is allowed while such a file is being read, that path needs a corresponding reader lease; do not pretend the published-job lease already covers it.

## Bounded sampling and memory handoff

StorageLedgerR31 should persist fixed category records for 288 five-minute samples and 30 days of hourly aggregates. Include phase, owner, boot, wall and monotonic start/end, method, completeness, physical/reusable/allocated/free/reserved/pending-cleanup bytes. A live directory walk is a measurement interval, not an atomic single-instant snapshot. Store unknown quantities as unknown.

Preserve the census's conservative no-symlink behavior and tests. `File.listFiles()` allocates its directory array before the current entry budget is applied; the existing traversal budget alone does not prove a memory bound for an enormous single directory. Any stronger claim needs a bounded directory enumerator or measured/explicit unsupported boundary.

Root owns MemoryBudgetR31, SharedFeatureStoreR31 and Runtime integration. Existing report native caps are 4MiB decoder/compression and 32MiB backup; preserve them and account actual simultaneous phases. Each PID's reservation owner and actual measured Java/native/PSS must be separate fields. Report summary buffers, chart refresh queues and cancellation closure references need explicit lifetime integration, not only a new sampler.
