## 故障证据

- 781 期开奖时间 21:01:03（北京时间）；HTTP 21:01:23.152 收到响应，开奖记录 21:01:30.949 写入，随后结算于 21:01:31.103 完成。HTTP 与写库之间约 7.8 秒，结算任务自身约 98 毫秒。
- 782 期 HTTP 21:02:07.977 收到，21:02:08.057 写入，21:02:09.318 完成结算；结算任务自身 62 毫秒。不能把所有延迟归为接口速度，也不能承诺全设备一秒完成。
- 下一期 782 的正式 canonical 记录在 21:01:34.8 左右已提交，截图仍显示当前目标期等待分析；首页队列存在慢诊断阻塞，健康标识使用了未与当前目标匹配的旧业务快照。
- 现有最新开奖预算是每分钟 45 次；项目配置的提供方上限是 50 次。实时循环最小等待 800ms，另加 HTTP 与本地处理时间，因此不是固定一秒一次。此版保留配置限额，不提高请求频率绕开限流。
- 报告仍有 75 个研究采集断档、310 个校准研究、0 校准模型和 0 正式证书。历史显示正收益本身不能证明未来资格；此版本不伪造训练结果、证书或授权。

## 产品修改

1. `AutoFetchService`：去除每轮抓取状态更新中的全表统计；最新开奖持久化后立即递交下一期分析及当前期结算，放在状态写入和历史读取之前；抓取回执合并事务；历史兜底移到既有 backfill 单队列并单次入队，不占用 latest 抓取线程。历史页先写最新一期再回补。
2. `DbStore`：实时 UI 使用 62 个固定键的索引查询，值限定 1024 字符；在 UI 快照范围内用已持久化摘要替代教师/画像全量统计。完整诊断仍可在独立队列读取。
3. `MainActivity`：实时刷新间隔 1 秒；历史与诊断独立 HandlerThread；滚动不暂停倒计时与当前预测刷新；完整诊断缓存完成写入后才发布，避免跨线程读到半成品缓存。
4. `ApiTransportGovernanceEngine`：完整 HTTP 但开奖过旧的响应继续拒绝并尝试备用接口，区别于网络断路；真实传输故障和不合法开奖结果仍触发原熔断。
5. `ServiceHeartbeatStore`：首页正常标识必须匹配当前开奖、下一期 canonical、当前结算/OOS，并且心跳不超过 15 秒；过期或错期快照不能显示健康。该显示谓词不授予交易资格。
6. `ReportExportServiceCP4`：诊断时间固定在原生备份开始前，匹配原生读取快照；避免两分钟备份耗时导致快照内容被误判滞后两分钟。
7. 精确审核 R65–R70 的数值训练续接；不修改评分、损失、数据角色、证书标准、唯一下单与结算责任方。
