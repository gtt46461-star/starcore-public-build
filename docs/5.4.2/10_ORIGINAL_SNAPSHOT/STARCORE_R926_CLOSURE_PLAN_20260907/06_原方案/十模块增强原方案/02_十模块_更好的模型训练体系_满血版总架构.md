# 十模块更好的模型训练体系：满血版总架构

目标：把“训练很多模型”升级为“严格PIT、完全同语义、分阶段可证明、可回滚”的生产模型工厂。

## 总流水线
M1 数据/PIT工厂
→ M2 NumberQ + Expert Gate
→ M3 完整1200动作Groupwise Ranker
→ M4 SelectedHitP Calibration + Uncertainty
→ M5 Regime/状态路由与稳定性
→ M6 Champion/Challenger配对证书
→ M7 Family去重/互补/FDR
→ M8 反事实消融/失败聚类/定向创造
→ M9 原子质量图/自动降噪
→ M10 精英修复/动态生命周期
→ Artifact Bundle
→ Python↔Java↔Android parity
→ Shadow
→ Future OOS
→ 受控主链接入

## 每个模块统一必须产出的七件套
1. `*_dataset_manifest.json`：输入期号、时间边界、字段、hash、schema。
2. `*_train_config.json`：超参数、种子、折数、资源预算。
3. `*_artifact.bin/java/json`：冻结模型。
4. `*_metrics.json`：分折、分块、分Regime、置信区间。
5. `*_parity.json`：Python/Java/Android逐输出对齐。
6. `*_certificate.json`：PIT、无泄漏、OOS、校准、资源、parity。
7. `*_rollback.json`：上一Champion hash及回退条件。

## 统一统计单元
- 单位永远是 target_issue。
- 1200动作是“同一期一个group”的内部候选，不能把1200行当1200个独立样本。
- 所有显著性、Wilson、FDR、block、Regime、Paired均按issue计算。
- 同一期最多一个最终selected action。
- 任何开奖后字段禁止作为本期赛前特征。

## 数据分层
- Train：最早时间段。
- Tune/Inner OOS：只用于模型/超参数选择。
- Calibration：在冻结selection mechanism后拟合。
- Policy：只从交叉拟合后的selected probability学习。
- Sealed Final：一次性最终证明，不参与调参。
- Future Live：安装/冻结后新增真实期，唯一可用于生产晋级。

## Champion/Challenger规则
- Champion不可被训练过程覆盖。
- Challenger必须拥有独立artifact hash。
- 只有paired Future-OOS非劣/优越才可晋级。
- 任意失败：保持Champion不变。
- 不允许“最新=最好”。

## 不允许的捷径
- 不允许把开发回放算Future OOS。
- 不允许把子代继承父代命中证据。
- 不允许为了15%频率降低质量门硬凑出手。
- 不允许用同一sealed final反复调参。
- 不允许把训练/校准/选择数据互相污染。
- 不允许用只有10位置候选的ranker证明1200动作ranker。
