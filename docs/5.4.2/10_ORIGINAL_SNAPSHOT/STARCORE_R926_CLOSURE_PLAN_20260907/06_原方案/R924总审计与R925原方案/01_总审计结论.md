# STARCORE 5.4.0 R924 全问题总审计结论

## 一句话
R924不是空壳：工程链、研究链、四大能力、导出、后台恢复入口都真实存在；但它仍不是“满血封板版”。当前最大的矛盾不是“再创造更多算法”，而是 **生产模型仍未训练证明 + Research证书漏斗长期为0 + 淘汰/覆盖口径有设计缺陷 + 后台真机未验收 + 用户看不到逐期流水**。

## 当前必须承认的真值
- B01-B15工程实现存在。
- 最近快照业务心跳HEALTHY，最新连续冻结预测可见。
- 物理设备后台：未完成，电池无限制=NO，T29-T34仍RETEST_REQUIRED。
- 严格OOS：N=1967，596中，HR=30.299949%，Wilson下界约28.31%。
- 当前创造：算法153、创生资产252、公式1852，但算法证书=0、资产证书=0、挑战者=0、生产贡献=0。
- 当前实时出号：100% Production fallback；9专家研究型号码面 + Sinkhorn + 手工researchScore Ranker。不是已证明生产模型。
- 旧101条REAL：当前严格合同全部SOURCE_NOT_REALTIME无效，不能作为真实胜率证明。
- Deferred=2216，CORE可用但FULL仍有 backlog。
- 当前报告很长且研究清单很完整，但没有真正覆盖 AndroidManifest、全部按钮/布局变体、全部资源、545 Java逐文件静态健康的独立章节。

## 为什么“创造不出高胜率高稳定高品质”
1. 不能凭小样本55%/100%判高胜率；Wilson/FDR会正确阻止。
2. 生产基础模型本身仍UNTRAINED，Research是在一个未证明baseline上做补充，难以稳定产生大幅配对增益。
3. 候选数量过多且高度相关，FDR惩罚大。
4. Future-OOS捕获受运行/压力/容量影响，样本积累慢。
5. 现有不可逆淘汰把`coverage<60%`当算法缺陷，但coverage可能部分来自系统漏捕获/暂停，存在误杀风险。
6. 已淘汰算法的原始淘汰原因会被`IRREVERSIBLE_EVIDENCE_PRUNE`覆盖，造成看起来“乱七八糟”。
7. 真实随机或近随机数据本身未必存在可持续40%+信号；软件可以把研究做严谨，但不能保证凭复杂度创造不存在的预测信息。

## 为什么0挑战者/0证书
- 算法挑战者同时要求 N>=240、HR>=36%、Wilson>30%、Block>=25%、Regime>=22%、MaxMiss<=16、Brier<=.24、ECE<=.12、Coverage>=80%、PairedN>=120、PairedDelta>=2%、FDR<=20%。
- 资产R906证书又有更严的95% coverage、Brier<=.21、ECE<=.06、BlockStability>=.70等。
- 当前活跃候选Future样本普遍个位数/十几，旧高样本候选多数已被不可逆淘汰，故自然长期为0。
- 这不是把证书门简单放宽就能解决；必须先修捕获、训练baseline、淘汰口径、族级FDR和证书漏斗可视化。

## 一分钟还是五分钟
当前证据不支持现在就换5分钟：
- R36真正compute约1.5秒级，说明60秒理论上足够。
- 39.6秒壁钟P95很大一部分来自约34.8秒数据库critical冷启动，而不是每期算法本身。
- 换5分钟会把Future-OOS样本积累速度直接拖慢，并掩盖后台/调度缺陷。
决策：先把1分钟版做到**稳态P95<=5秒、连续120期预测覆盖>=99%、息屏/划掉/24h全PASS**。如果这些完成后，稳态仍无法在60秒内稳定闭环，再建立独立5分钟分支做对照，不直接改当前游戏身份。
