# 挑战者 / 证书 / 淘汰机制重构

## 为什么现在一直是0
活跃算法Future样本只有个位数/十几，挑战者合同又要求多指标全部通过；旧高样本候选已经多数PRUNED。创生资产同样没有通过更严格的R906证书。

## 发现的淘汰设计问题
`AlgorithmEvidencePolicyR912` 在N>=120时：
- rate<30% / block<20% / supported-regime<18% / maxMiss>24 / Brier>.30 / ECE>.20 / coverage<60% / paired harm<-3% 都可PRUNE。
`AlgorithmEvolutionLifecycleR912` 对已PRUNED候选后续把reason改成`IRREVERSIBLE_EVIDENCE_PRUNE`，因此报告丢失“第一次到底因为什么淘汰”。

其中coverage尤其危险：coverage=n/eligible draws，而n受predraw capture、MAX_RUNNABLE、系统压力、版本启动时间影响；基础设施漏捕获不等于算法质量差。

质量PRUNE：Wilson上界低于随机、长期率低于随机、严重Brier/ECE、配对明确伤害。
证据暂停：系统capture不足、regime支持不足、容量不足、后台中断。
证据暂停不得永久淘汰。

## 证书漏斗
在UI和报告输出每项差距，并给预计“还需多少Future样本”，但不承诺一定通过。
证书一旦通过先只进入SHADOW重排，权重12%；独立新窗口继续非劣后可逐步到20%/30%，任何漂移自动回0。
