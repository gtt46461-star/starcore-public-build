# UI / 按钮 / 状态框 / 可观察性施工

## 静态资源结果
- 生产Java：545个；资源文件：71个。
- R924既有APK资源合同：0资源ID错配、Main bindings PASS、签名/zipalign/zip integrity PASS。
- 本次额外检查发现：`layout-sw600dp/activity_main.xml` 比phone布局少 `btn_background_reliability`，且状态标题仍为R906而phone为R919，说明资源变体没有完全同步。
- 13个XML Button均被Java引用；不是“按钮完全没接线”的问题。
- 真正问题是**信息可见性**：后台、fetch、analysis、settlement、shadow、research被压成综合长文本。

## 必须重做首页信息架构
### A. 后台运行总灯
固定在顶部，不滚动：
- 进程：RUNNING/STARTING/DEAD
- 前台Service：YES/NO
- 业务链：HEALTHY/STALE
- 电池豁免：YES/NO
- 精确闹钟：YES/NO
- 通知权限：YES/NO
- 最近fetch age
- 最近analysis commit age
- 最近settlement age
- 最近research tick age
- 最近自动恢复原因
任何一个关键项缺失=黄色/红色，不允许只写“服务运行中”。

### B. 最近20期实时流水
每行：
`issue | draw fetched | provider | fetch ms | analysis request | queue ms | compute ms | commit | P# | K3 | SHADOW/REAL/HOLD | settle | hit | research capture | FULL`
这样用户不用检测报告就能看出每一期到底跑没跑。

### C. 独立影子观察卡
永远显示：
- Shadow总数/已结算/待结算/命中/未中
- HR + Wilson
- 最近30/60/120
- 实际开奖预测覆盖
- 最新20条影子动作
绝不再混在3行真实盈亏文本里。

### D. 四大能力卡
1. 深度学习：模型名、训练截止、更新数、最近损失、OOS贡献、是否接主链、权重。
2. 动态迭代：本轮评估/保留/淘汰/变异/交叉/新生、失败向量、下一次迭代。
3. 创造能力：算法/资产/公式数量不是主KPI，主KPI改为“候选→观察→挑战者→证书→贡献”漏斗。
4. 分子原子因子：240登记分层，明确165生产赛前语义、40研究代理、20开奖后、15审计；显示本期实际使用了哪些原子。

### E. 挑战者/证书漏斗
每个候选一行显示：
N/240、HR/36%、Wilson/30%、Brier/.24、ECE/.12、Block/.25、Regime/.22、Coverage/.80、PairedN/120、Delta/2%、FDR/.20、MaxMiss/16。
把“还差多少”直接显示，0挑战者就能看明白原因。
