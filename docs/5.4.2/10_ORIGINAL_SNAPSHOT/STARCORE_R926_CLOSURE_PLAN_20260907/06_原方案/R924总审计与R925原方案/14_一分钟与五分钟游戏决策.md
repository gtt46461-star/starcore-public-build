# 1分钟 vs 5分钟游戏工程决策

## 现在不建议直接换5分钟
当前证据显示真正R36 compute约1.5秒级，60秒足够；39.6秒壁钟P95与约34.8秒critical database startup高度重叠，首先应修冷启动和调度遥测，而不是换玩法。

## 换5分钟的代价
- Future-OOS和证书样本积累约慢5倍。
- 会掩盖“后台没有持续运行、进程经常重启、启动Schema太慢”的根因。
- 需要重新定义Game identity、issue cadence、provider endpoint、TargetIssueResolver距离、倒计时、历史数据和模型证书，不能只把timer从60改300。

## 正确决策门
先保持1分钟并完成：
- warm P95<=5s
- continuous 120 issues prediction coverage>=99%
- screen-off/taskRemoved/24h PASS
- no duplicate settle/predict
如果仍有稳态超时，再做独立5分钟branch A/B，不覆盖当前数据库，不复用旧证书。
