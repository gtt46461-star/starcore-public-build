## 4. 满血真实代码施工方法

### 4.1 先审计，再修改

每批开工先冻结 Git tree、release manifest、数据库版本、签名和任务集合。扫描全部生产源码，记录文件职责、类/方法、调用者、被调用者、DB、线程、Owner、异常处理与处置状态。

### 4.2 该删除就删除，该重写就重写

禁止只在旧逻辑后继续叠第 N 层补丁。对重复 Owner、不可达实现、已被新主链完全替代的历史主体，允许并要求删除；巨型文件职责混杂时抽取真实职责；核心算法或事务模型错误时直接重写错误主体，同时保留明确兼容薄委托。

### 4.3 禁止空壳、无效占位、垃圾文件

以下情况不得计为完成：

- 新建类没有真实生产调用者；
- 方法只有常量返回、TODO、假数据或 `UnsupportedOperationException`；
- 只写接口/DTO却没有实现和消费者；
- 只增加日志/UI文本，没有状态变化或数据持久化；
- 只写“深度学习/动态进化/创造能力”名称，没有训练、推理、生命周期、持久化、主链消费和可失败测试；
- 为凑“几千行”重复粘贴无效代码。

短接口、DTO、受控 delegate 可以很短；“满血”由真实调用链、数据合同、持久化、失败处理、测试和消费者证明，不由机械行数证明。

### 4.4 唯一 Owner 与真实接线

任何新增能力必须找到真实入口和消费者；同一职责只允许一个最终 Owner。新实现完成后必须搜索并治理所有旧入口，禁止第二套旁路继续存在。

### 4.5 事务、崩溃、重复和重启优先测试

数据库/事件/结算/学习等必须测试：重复10次 exactly-once、乱序、killpoint、事务回滚、进程重启、outbox replay、projection rebuild、坏备份拒绝、同版本迁移重入等。

### 4.6 编译成功不等于完成

“完成”至少要求：源码存在 → 有真实调用 → 状态真实变化 → 数据真实持久化 → 重启/重复不破坏 → 错误可观察 → 可失败 Harness 通过 → APK真实构建/反解验证。

## 5. 每批必须输出

每批最终总包必须真实包含：

1. `01_APK/`：同签名可覆盖安装 APK。
2. `02_COMPLETE_SOURCE/`：该批最终完整源码、res、assets，不是 patch-only。
3. `03_CHANGE_LEDGER/`：逐文件 before/after SHA256、行数、字符数、增删、任务、调用者、DB/线程/Owner、处置方式。
4. `04_VERIFICATION/`：compile、SQL、Host、fault、APK、DEX、resource、signature、manifest 证据。
5. `05_PROGRESS/`：42项状态、总进度、本批进度、BLOCKED/NOT_RUN边界。
6. `06_ROLLBACK/`：源码/数据库/版本回退方案。
7. `07_BUILD_REPRO/`：构建脚本和工具链。

“整个软件全量总包”默认采用**全量继承型**：上一完整总包资产不擅自丢失，当前源码/APK替换为最新，历史与回滚证据归档保留；不得通过复制垃圾文件人为凑体积。

## 6. 分段回复与真实进度

- 用户说“继续第 X 批”时必须从当前真实工作树继续，不重置。
- 百分比只能随真实代码、测试、APK、GitHub证据推进，不按回复次数推进。
- 超时既不是 PASS 也不是代码 FAIL，必须拆成独立门重新执行。
- 未通过的门明确写 PARTIAL / BLOCKED / NOT_RUN；不得拿半成品冒充100%。
- 每次至少报告：总施工进度、本批进度、任务状态、修改文件、build/Host/SQL/APK/真机/Future边界。

## 7. GitHub / PR / CI / 预发行 / 正式发行

正确顺序固定为：

**完整源码分支 → PR → CI → 同commit APK → PRE-RELEASE → 最终实证门 → 5.4.2正式RELEASE**。

- GitHub必须保存完整展开源码，不允许只保存报告、patch或聊天附件来冒充源码同步。
- PR说明必须记录本批任务、版本关系、红线、差异和未完成实证门。
- CI必须实际运行，不允许“测试被跳过但统计为PASS”。
- 第一至第六批可以制作明确标识的中间/RC预发行，但不得称最终5.4.2。
- 只有全部批次与最终Q门完成后，才创建正式 **5.4.2** Release。

## 8. 第一批B06最终补充合同

- CANONICAL / SETTLED / FULL：事件必须与各自业务数据处在同一个业务事务。
- 其他外部事件：必须先提交 durable PENDING outbox，再由唯一 `RuntimeExternalEventWriterR926` 驱动 outbox → immutable event + projection。
- 外部 hook 必须返回真实持久化结果；Recovery 的 `eventWritten` 禁止无条件写 true。
- 启动必须能够重放 PENDING outbox。
- 生产代码不得绕过唯一外部事件Writer直接写非事务事件。
