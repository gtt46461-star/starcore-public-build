## 本次不是界面换字，而是五条闭环重构

### 1. 开奖任务与预测结算双分母

旧界面把“所有开奖任务”和“存在赛前预测的任务”混为一个分母，导致 3315 个开奖任务中
2764 个历史无赛前预测排除项也被看成“没结算”。R919 保留两套不可混写的统计：

- 开奖任务：合法开奖是否获得任务并到达 `COMPLETED / NO_PREDRAW_TERMINAL / FAILED_TERMINAL`；
- 预测结算：存在同一期不可变赛前冻结记录的预测是否获得 exact draw 标签。

核心结算永远先提交。算法、资产、公式、Teacher 或 UI 侧路失败不能回滚核心结算；侧路可由
`SettlementPostCommitSidecarR909.drain()` 重放修复。没有赛前预测的旧期开奖明确写入
`R919_AUDITED_NO_IMMUTABLE_PREDRAW`，不伪造预测，也不永久占用待结算队列。

### 2. 为什么中、为什么不中与 Teacher 反哺

赛前新增不可变 Teacher/正向推理/反推/因果/趋势/形态/关系上下文。开奖后由 exact draw 与同一期
赛前 hash 生成独立的 `v57_legacy_postsettlement_context_r919`：

- 命中：展示实际号码落入冻结 K3、赛前 Teacher/矩阵证据和量化贡献；
- 未中：展示实际号码落在 K3 外、第三边界、熵风险、稳定性、窗口和跨位支持失败向量；
- 反哺：只允许更新 `t+1` 以后状态，禁止把开奖信息倒灌成本期赛前理由；
- 首写冲突：同一期第二次写入只有 hash 完全一致才幂等，否则立即拒绝。

### 3. 240 个底层因子/原子与严格时间阶段

原子不再只有 ID 和名词。每项都登记：类型、值域、窗口、最大滞后、最小支持、泄漏策略、更新时点、
证据阶段、移动端成本和版本。

- 总数 240，分 12 组；
- 当前 205 项可进入赛前程序；
- A9 共 20 项为开奖后 Future-OOS/血统/证书证据，永远不能进入本期评分；
- 72 个导航家族用于组织创造方向，不作为固定模型模板；
- 任何 Genesis Genome 的选原子、修复、变异、交叉都再次执行 `predrawComputable()` 硬检查。

### 4. 从随机公式搜索升级为失败向量驱动的算法结构创造

算法家族必须同时具有 State、Score Program 和 Settlement Update Program。R919 在底层指令空间上
新增七类结构创造意图：

1. `CALIBRATION_SHAPE`：改造输出非线性并记忆概率残差；
2. `LONG_MISS_MEMORY`：增加长连挂状态记忆和条件分流；
3. `REGIME_ROUTER`：增加区制输入、全局记忆和分路更新律；
4. `BLOCK_STABILITY`：利用跨位置记忆形成稳定混合；
5. `MAINLINE_COMPLEMENT`：创造迁移×残差互补交互，而非复制主链；
6. `RESOURCE_SIMPLIFY`：删除冗余结构并由合同恢复必要原语；
7. `OPEN_EXPLORATION`：从最低级原语开放搜索。

每次创造把父代真实 Future-OOS 的 N、Wilson、ECE、最大连挂、分块、Regime、覆盖、相对主链、复杂度
组成失败向量，再选择结构意图。子代结构哈希、行为哈希、中文机制名、父代、创造原因和意图全部落库；
子代 Future-OOS 从 0 开始，绝不继承父代胜率。

### 5. 主界面可见性与唯一真值

旧实现统一把创造能力框限制为 6 行并强制省略号，因此数据库已经存在的原子、中文名和 Future-OOS
看起来仍像空壳。R919 将创造卡改为 16 行、不省略，并直接显示：

- Legacy 注册/锁定/完整性；
- 240 原子、205 赛前可计算、20 开奖后证据、12 组、72 家族；
- 创生资产、冻结、应结算/已结算、证书、淘汰、主链贡献；
- 最佳创生资产和算法的中文名、N、HR、Wilson、ECE/Brier、覆盖、配对主链与 FDR；
- 本轮失败向量、结构创造意图、未运行精确原因。

点击后显示全部 240 项原子合同、资产榜、算法榜、新原子提案和生产贡献。主界面、学习页和完整检测报告
统一读取 `RuntimeTruthSnapshotR906` 的同一事务快照；删除两个重复旧真值 Owner。

## 仍不能伪称已经证明的项目

- 主机测试不能证明 vivo 设备退出界面后连续两小时每分钟均运行，必须装机复测；
- 当前历史最佳算法约 30% 左右不等于目标胜率，R919 没有把它伪造为 45% 或 70–80%；
- 动态迭代实现的是“以更好证据为选择方向、退化即淘汰/回滚”，随机数据不允许承诺每代单调上升；
- 无有效证书时 Genesis/算法对 Production 的贡献严格为 0，原主链 100% 接管；
- 真实出手仍必须逐期通过唯一 DecisionGate 的精确受控候选门，Research 不能强制下注。
