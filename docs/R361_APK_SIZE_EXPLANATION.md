# APK 体积与源码完整度说明

## 本次实测

- 生产 Java 文件：387
- 展开物理行：365,462
- UTF-8 源码字节：14,519,829
- 方法声明近似计数：11,116
- 最终 APK：3,048,302 字节
- APK 内 `classes.dex` 解压后：5,966,148 字节

APK 是 ZIP 容器。Java 源码中的空格、缩进、注释、长类名和重复字符串在编译后都会被移除、折叠或压缩；387 个源码文件也不会在 APK 中按 387 份 `.java` 原样保存。因此“源码十四多 MB、DEX 约 5.97MB、压缩 APK 约 3.05MB”是可以同时成立的。

旧 AIDE 手工 APK 约 4.5MB，可能来自不同资源压缩、调试信息、多 dex、未对齐、不同编译器或额外资源，不能单独证明代码更多。旧总包约 164MB 更可能包含源码、Gradle/SDK/构建工具、缓存、历史 APK、PDF 和证据；总包与可安装 APK 不是同一个体积概念。

本次不以 APK 体积判定满血度，而使用可复核指标：

1. B01–B15 合同文件 114/114 存在。
2. 387 个生产 Java 文件逐文件记录 SHA-256、行数、字节、方法、引用、决策点、语句、占位和空方法。
3. TODO/FIXME/XXX 注释为 0，占位标记为 0。
4. 两个原先过薄的合并核心已重建：B14 诊断编排器 2769 行，B15 报告核心 2012 行。
5. Java 17 全源码实际编译通过，主机合同回放实际执行通过。
6. 最终 DEX 反编译后验证关键类、Android 调用描述符和 PendingIntent 常量。

审计也明确保留事实：47 个文件低于原方案给出的“物理行数代理”。这些文件按 Android 入口、纯数学算法、唯一 Owner 桥、失败关闭治理等职责评估，不能为凑 1000 行而复制无效代码。逐文件依据在 `R361_SOURCE_INTEGRITY_PER_FILE.csv` 和 `R361_B01_B15_CONTRACT_TRACEABILITY.csv`。

总包包含本次真实使用的离线工具和全部原始方案，体积会显著大于 APK；没有添加随机数据或空文件来伪造“大包”。
