# STARCORE 天枢 R919 / R5.3.5 硬性施工与验收合同

## 1. 版本与覆盖安装

- applicationId 固定为 `com.ethk3.novaonepro`。
- 数据库固定为 `binance_k3_nova_one_pro_v57.db`，沿用 DB_VERSION=36 的加法迁移，不删除用户数据。
- 版本升级为 `V57.20.5-R5.3.5-919`，versionCode=`577240919`。
- 发布 APK 必须沿用上一可覆盖安装版本的签名证书；不得以卸载重装冒充升级成功。
- API 凭据只从上一签名 APK 的 BuildConfig 继承到临时构建目录，不写入源码、日志或报告。

## 2. 不可变业务红线

- Binance1-PK10、单位置、固定 K=3、每期最多一个 REAL。
- 禁止 K4、动态 K、多位置 REAL、追期、马丁、加倍和频率债务补单。
- `DecisionGateEngine_ONLY`、`SettlementEngine_ONLY`、`TargetIssueResolver_ONLY`、
  `AnalysisSingleFlightR36_ONLY` 的唯一 Owner 关系不得改变。
- Legacy 策略、趋势、形态、号码属性、位置关联、Teacher 及各矩阵保持只读固定资产；
  Genesis 可以读取，不得替换、变异、删除或绕开原主链。
- Research/Genesis/算法家族没有直接创建 REAL 的权限；只能在证书完整时限幅影响动作评分，
  最终仍经过唯一 DecisionGate。

## 3. 运行闭环硬门

- 每个已获取且合法的开奖期都必须进入唯一结算任务账本并到达明确终态；不得静默丢期。
- 每个合法赛前冻结预测都必须用 exact draw 结算；不存在预测的开奖任务必须明确记录排除原因。
- 核心结算提交不依赖 Teacher、Research、UI 或延后证据侧路；任何侧路失败不得回滚核心结算。
- 后台退出、息屏、任务移除、进程恢复的静态契约必须通过；物理设备结果必须如实标记
  `RETEST_REQUIRED`，不得用主机测试冒充。
- 主链延迟预算优先于研究，但 Research 必须拥有有上限的公平切片，不能无限饥饿。

## 4. 唯一真值与界面硬门

- 主界面四张运行卡、深度学习/算法创造页和“一键复制完整检测报告”必须读取同一份数据库快照。
- 禁止同时出现 `SHADOW_ONLY=true` 与 `SHADOW_ONLY=false`、旧 R900/R904 标题与新 R919 状态混写。
- 创造能力卡必须直接显示：Legacy 完整性、原子/导航家族、新原子提案、创生资产总数、
  赛前冻结数、已结算数、证书数、淘汰数、最佳中文机制名、Future OOS、Wilson/FDR、
  主链贡献以及本轮未运行的精确原因。
- 所有 DB 读取异常显示 `READ_ERROR:<类型>`；缺样本显示 `NO_SAMPLE:<原因>`，不得伪装为零或 PASS。
- 为什么中/不中/不出手必须同时显示赛前预测证据和开奖后归因；Teacher/矩阵无记录时必须给出
  缺失表、缺失期或缺失字段的具体原因，禁止只显示一个 `N/A`。

## 5. 深度学习、动态迭代与创造硬门

- 公式、策略与算法家族分层：没有独立 State、Score Program、Settlement Update Program 的候选
  不得称为算法家族。
- 每个新资产/算法必须有由真实机制生成的中文名、结构哈希、行为哈希、血统、适用域、失效条件、
  赛前冻结记录和开奖后 exactly-once 状态更新。
- 创造流程必须是失败向量驱动的结构创造，而不是只改窗口、阈值或权重。
- 未来 OOS、Wilson、覆盖、Brier、ECE、分块/Regime、最大连挂、FDR、主链配对和资源成本共同决定
  保留、变异、淘汰、制证；开发回放和小样本不得冒充高胜率证明。
- 没有有效证书时研究贡献严格为零并回退原 Production；有证书时按既定限幅进入评分，仍无 REAL 权限。

## 6. 交付硬门

- Java 17 全源码编译、算法/资产 VM 合同、逐期结算 SQLite 闭环、迁移、故障注入、唯一 Owner、
  Research 无 REAL 权限、报告一致性、主界面 R919 文案和 APK DEX 类存在性全部必须通过。
- APK 必须通过 zipalign、ZIP 完整性、包名/版本、v1/v2/v3 签名校验及上一版证书连续性检查。
- 总包必须同时包含：完整 Git 源码快照、签名覆盖安装 APK、校验和、自检证据、逐文件变更台账、
  架构/主链说明、物理设备复测说明和构建脚本。
- 编译成功不等于实机成功；报告未证明的项目必须明确保留为 `RETEST_REQUIRED` 或 `NOT_PROVEN`。
