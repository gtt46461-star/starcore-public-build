# V51 APEX 哈希可用性、走势窗口与不可造假补充合同（51072404）

## 1. 结论先行

号码来自目标区块哈希，不代表历史区块哈希能够预测未来区块哈希。

目标期区块哈希只有在目标区块产生后才存在，因此它属于开奖后字段。任何训练、回放、状态、专家、Ranker、SelectedHitP、Predictability 或 Policy 在预测目标期时读取目标期 `hash`，都构成未来泄漏。

历史哈希有正式价值，但当前只允许承担以下职责：

1. 验证平台公布的“区块 → 排列”映射是否一致；
2. 检测错块、重复块、跳块、期号与区块号错位；
3. 检测开奖算法、取块规则或数据供应商发生变化；
4. 建立不可篡改的数据链和训练数据身份；
5. 作为异常、漂移、Falsifier 和数据质量证据；
6. 审计是否有人把目标哈希、目标开奖或开奖后字段混入预测。

在没有严格时序OOS证据前，历史哈希不得作为号码分数、Top3、Rank1、SelectedHitP 或真实BET的正向专家。

## 2. 本次10,000期实证审计

审计文件：`reports/V51_HASH_SIGNAL_AUDIT.json`。

- 10,000期全部是01—10完整排列；
- 16进制哈希字符总体均匀性检验 p=0.8045；
- 十位置号码均匀性经BH多重校正后无显著发现；
- 检验“前1—4期历史哈希64个字符位置 × 下一期10个位置号码”共2,560项关系；
- BH-FDR q≤0.05 的发现数为0；
- 最小校正后q约0.3834；
- 四个严格时间折中，加入历史哈希后没有一个折达到整体Top3增益门；
- Rank1四折全部下降，约下降1.35—2.85个百分点。

正式结论：

`HISTORICAL_HASH_USE_FOR_AUDIT_ONLY_NUMBER_WEIGHT_ZERO`

这不是说历史哈希永远不可能有用，而是说当前数据没有证明它能预测下一期号码。V51必须将它的号码预测权重固定为0，直到新未见数据同时通过FDR与多折增益门。

## 3. 哈希信号晋级硬门

历史哈希要进入号码模型，必须同时满足：

- 全部特征只来自目标期开奖前已确认区块；
- 以targetIssue为分组单位，十位置不得拆散；
- 相关搜索通过分组置换与BH-FDR q≤0.05；
- 组合模型相对无哈希模型，整体Top3提升>0.5个百分点；
- Rank1提升>1个百分点；
- 至少3/4独立时间折同方向；
- 新冻结段仍保持增益；
- Java Production Replay与Python逐字段一致；
- 下游Ranker、校准、Predictability和Policy全部重训。

任何一项失败：号码权重=0，只保留审计和反证用途。

## 4. “走势、形态、趋势窗口”继续研究的正确方向

历史走势仍然可以研究，但不能把自然随机波动叫作因果规律。V51接下来只接受以下可前推改进：

### 4.1 直接动作学习

把一个targetIssue的十个位置作为同一组，直接学习“哪个位置的Top3在这一期更可靠”，而不是先让十个位置各自夸大概率，再从中挑最大值。

训练目标同时包括：十位置Listwise排序、Pairwise动作间隔、Top1 Regret、第三号替换鲁棒性，以及去专家、缩窗口、轻扰动后的Rank1保持率。

### 4.2 可预测性采用交叉拟合残差

Predictability不能由人工Sigmoid公式生成。它必须学习号码模型与Ranker交叉拟合残差、专家消融方差、状态原型距离、变化点概率、Motif后继分布可信下界、关系边FDR、第三/第四边界稳定性。

### 4.3 Conformal选择性风险控制

在开发段使用按时间滚动的conformal risk control，估计在给定覆盖率下的错误上界。Policy不得通过“欠单补频”凑15%，而要在风险上界合格的机会中自然形成覆盖。

### 4.4 Null与Planted-Signal双压力测试

- 对完全随机排列数据，系统必须回到约30%且策略面为空；
- 对人工植入可前推状态的数据，系统必须识别状态并在新时段恢复增益；
- 若随机Null也能找到40%/15%，说明False Discovery Guard失效，CI必须失败。

### 4.5 专家逐个真实消融

九专家只有在“完整模型减去该专家”的严格OOS结果下降时才能拥有正式权重。只增加类名、固定公式或解释字符串，不算专家实现。

## 5. 关于“量子预测”

没有目标区块产生前的量子测量数据、可信物理随机源侧信道或可验证提前信息，就不存在能提前得到目标哈希的“量子预测”。把普通优化算法改名为量子算法不会创造信息。

V51可以使用量子启发式方法做组合搜索，例如策略面优化、特征子集选择或排列求解挑战器，但它只能提高搜索效率，不能突破目标哈希的不可得性，也不得绕过OOS门。

- `training/audit_v51_hash_signal.py`：历史哈希严格时序审计；

## 7. 发布状态

本补充合同不会降低40%命中、15%覆盖、Rank1稳定领先、ECE≤4%等发布门槛。当前哈希审计结果不会使V51晋级，真实BET继续禁用。

只有纯开奖前信息在严格时序OOS中真正达到全部硬门，才允许生成 `V51_FULLY_PROVEN_RELEASE`。
