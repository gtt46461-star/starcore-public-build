# R920 实体 Android 覆盖安装与连续运行验收

## A. 覆盖安装与冷启动

1. 保留旧应用和数据库，直接安装 R920 APK；禁止先卸载。
2. 系统应接受升级，应用信息应显示 `V57.20.6-R5.3.6-920`。
3. 连续冷启动 10 次；每次首页可见 R920 标识，不应点击即退。
4. 若主 UI 仍发生未知异常，应出现“R920 启动保护模式”并给出阶段和错误，而不是静默退出；复制
   全文连同 `CrashRecorder` 内容回传。

## B. 首页与创造能力界面

1. 展开四张唯一真值卡，确认没有旧 R900/R919 与 R920 混写。
2. “为什么中/为什么不中/为什么不出手”应同时包含赛前证据与开奖后 Teacher/正推/反推/因果/
   反哺归因；无记录时必须写明缺失原因。
3. 16 状态框应包含原始 K3 概率、Rank、第三边界、动作稳定性、号码风险、形态状态、窗口共识、
   跨位支持、校准、深度学习、算法发明迭代和 DecisionGate。
4. 创造卡应显示 240 原子/12 组/72 家族、资产/算法冻结与结算、中文机制名、淘汰、Future OOS、
   证书和主链贡献。无证书时贡献必须为 0。

## C. 逐期结算

以连续 200 个自然未来期为验收窗口：

- 合法已抓取期进入任务账本覆盖率 100%；
- 有赛前冻结预测且已开奖的结算覆盖率至少 98%；
- duplicate settlement/update 为 0；
- 无赛前预测的期开奖进入明确终态并显示排除原因，不与预测命中分母混写；
- Teacher、资产、算法 sidecar 对同一冻结记录最多更新一次；
- 最新开奖、预测、结算、严格 OOS 游标不应长期停滞。

## D. 后台运行

分别执行：亮屏前台 30 分钟、返回桌面 30 分钟、息屏 60 分钟、划走任务 60 分钟、系统回收进程后
重新打开。记录每段的起止业务游标、开放任务、结算滞后、P95、队列、checkpoint/resume、OOM 和
系统电池限制。若 ROM 禁止自启动/后台活动，按界面入口授予权限后重测；程序不得把权限缺失显示成
“后台正常”。

## E. 真实出手与胜率

- `MODEL_PROVEN=false`、`REALTIME_PROVEN=false`、无有效证书或唯一 DecisionGate 拒绝时，HOLD 是
  正确结果，不得通过降低门槛制造“有出手”。
- 研究候选必须从冻结后的下一自然期开始计算 Future OOS；训练/回测不计入。
- 至少记录 N、命中、Wilson、FDR、ECE、Brier、Coverage、BlockMin、RegimeMin、MaxMiss 和 paired
  mainline；不能只看命中率。
- 若未达到证书标准，界面应显示 `MODEL_NOT_PROVEN` 和具体失败项；不得宣称 70%–80%。
