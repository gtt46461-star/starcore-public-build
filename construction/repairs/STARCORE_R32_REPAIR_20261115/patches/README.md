# 可应用的生产源码改动

在施工分支独立工作树从032对应的源文件开始。按批执行，例如 `git apply --check construction/repairs/STARCORE_R32_REPAIR_20261115/patches/P1.patch` 再用 `git apply` 应用。已经合入的变更用 `git apply --reverse --check` 对照，不重复应用。当前源文件若有别的修复，检查具体hunk并合并，不能用整份旧文件覆盖新版本。

|补丁|覆盖|施工者仍需完成且在本批验证|
|---|---|---|
|P1.patch|旧库索引前三列、合法最小预冻结历史尾段、小范围写优先级、控制者排空故障队列、迁移者尽早初始化假设配额|主进程逾期、快速回补合并和无最新返回、长持锁底因、受保护缺件恢复、背景与实时端到端及旧库升级。|
|P2.patch|恢复回放pin时先准备缓存，失败不发布半成品；供体跨冻结输入轮转、同输入重放可复现|真实恢复遇到的准入/END错误、十位置训练与权重发布；根据业务数据补全独立出生、矩阵、消费、同机会评估及清退。|
|P3.patch|正式旧门处理非法计数和越界概率；保持有效输入原阈值|从正常策略入口证明合格策略被消费到唯一真实结算，过期、撤销和双写反例。|

14个目标路径分属五批。每一份diff含目标路径、上下文和基线blob。P5在实际源码版本、签名环境和设备上执行，构建/发布版本号在交付时取值。整套方案有18张本轮联合卡；5份补丁只覆盖已能按源码定位的部分，应用补丁后须照各卡完成余项。
