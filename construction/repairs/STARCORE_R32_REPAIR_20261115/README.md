## 施工顺序与签收

|批|本批集中修改|本批当场签收的业务行为|
|---|---|---|
|P1|旧库、写者排空、后台、实时尾段、赛前冻结、开奖结算与存储恢复|给032形状的旧库喂连续数据，迁移越过两个故障单元；在正常服务入口按时冻结并唯一结算；失败时能追踪实际事务。|
|P2|回放、十位置训练、策略工厂、家族、原子、20类矩阵、淘汰与代际|喂按时间揭晓的固定序列，跨重启出现新的可执行子代、训练步、一次真实的算法消费以及下一轮提出或淘汰原因。|
|P3|资格、证书、真实主链冻结/结算及撤销|合格测试策略在正常选择入口出手一次，失格、过期、重复、跨期及竞态均有拒绝证据。自然出手另记。|
|P4|同源报告、研究表、图表、导出和恢复|从正式导出入口解压读回；逐项说明能力、输入、产物、消费和效果；两种报告格式能定位相同问题。|
|P5|构建、升级、联合故障、签名及APK压缩包|同签名覆盖032、正常冷启、真实运行、APK与ZIP的哈希相符；发布状态和未取得的真机/自然证据按原规则标明。|

每批的故障、改法、事务所有者和负例见 [五批逐项施工](guide/五批逐项施工.md)。同一文件只有一个计划写入批次；后批通过已存在且已验证的接口消费。旧卡若横跨多个主题，其整卡联测归到所需代码齐备的批次。前批有独立的生产入口用例，不留“等后批才能签”的签字栏。设备和自然质量分别记实况；原发布门仍生效。需要修正上游缺陷时，将关联文件和回归用例一起作为原责任批的修复提交，再继续下游；一次缺陷只记一次。
