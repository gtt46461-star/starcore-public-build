# P4 检测报告真实页内审计及逐对象证据合同

本贡献属于 P4，与原 P4.patch 连续施工。P4.patch 先提供 ReportExportServiceCP4 → ReportR29 → RepairDiagnosisR32 的同快照接线；本增量在同一批增加真实诊断计算，不要求任何后续批次代码。

## 真实缺口与替换

原 P4 主要按六层状态和静态处方出报告。T06/T10 能辨识阻断帧，但 T01–T16 其余问题仍需人工猜读，原对象证据hash、页分母、原因不确定性和缺数值效果的明确状态未逐对象齐备。缺失对象只有 coverageGaps 文本，没有该对象独立诊断行。

- `files/app/src/main/java/com/ethk3/novaonepro/strategyv2/RepairDiagnosisR32.java` 是完整后态；`build` 接 `ResearchTableAuditR32.audit`，每个登记对象输出原对象 hash、同快照引用、未观测字段、效果证据缺口、原件缺失专行；`attach` 将同一个对象输出到 Markdown 和 JSON。
- `files/app/src/main/java/com/ethk3/novaonepro/strategyv2/ResearchTableAuditR32.java` 是新增完整实现。直接解析当前报告已采集的16张逻辑研究表原页，逐行给页分母、原行hash、问题计数、首个直接观察、具体修法；上限200行、16个细节，不复制原载荷，不访问第二个数据库快照。
- `files` 中另两份 ReportExportServiceCP4/ReportR29 是原 P4 的完整接线后态，仅供总包组装。若父包已包含 P4 后态，使用本增量patch即可；不得再次用旧完整导出文件覆盖其他返修。

## 施工与验收

在已应用 P1–P5 的候选树运行 `git apply --check P4-diagnostics-completion.patch`，再应用。逐文件父态与目标 SHA-256 见 MANIFEST.json；目标相同则按已应用核验，不重复覆盖。

新增370条宿主断言已通过，使用真实 JsonR27、StatsR27、P4后态生产诊断类和已编译生产注册表。覆盖迟冻结、目标泄漏、无结算、融合阻断、坏JSON、错区间、无配对支持、自身删除、孤立消费、不可读页，以及165个对象和16表实际接线。删除整组logicalTables的反例也仍产生165个诊断行，16个明确 SOURCE_OBJECT_MISSING。

新增探针为 `verify/ResearchTableAuditProbe.java`；运行结果在 `verify/RESULT.log`。父工程全量编译应将新增类与修改类纳入，原P4 probe也应复跑。Android APK构建、手机导出及长期运行本贡献未执行，保留 NOT_RUN。

## 边界与仍未证明事项

页审计分母只等于本报告读到的页，不能表示全表命中率或总体故障率。直接观察不是确定根因；置信字段明确根因仍待原事务复演。对象索引没有附同目标配对效果原件时，before/after/estimate/interval 均保持 null，并输出 `PAIRED_ORIGINAL_NOT_ATTACHED_TO_OBJECT`。这些字段明确报告缺项，不能以生成报告本身冒充“算法已经提升”。真正训练、生成、融合及晋升由 P2/P3 的对应代码和验收承担，本贡献仅检验它们已留下的证据。
