## 怎样查看每个问题、文件和代码

1. 打开`START_HERE.html`，进入P1.01至P5.01对应的问题页面。每页有现场证据、修改方法、事务边界、正常/故障验收，以及每个涉及文件的完整后态代码。
2. `issues/Px.xx/*.md`逐文件记录旧要求、问题、方法锚点、修改合同、前后SHA-256及代码链接。`code/Px/files`是本批唯一后态源码；同一文件只归一个批次写入。同批多个问题涉及它时共同使用这一份文件。
3. `patches/P1.patch`至`P5.patch`给出本轮真实差分。`PRESERVE_REFERENCE`交付原有完整实现，不将无差分文件计作本轮新增功能。
4. `SOURCE_BASELINE.zip`是锁定基线的完整项目源码、资源与工程输入；`SOURCE_CANDIDATE.zip`是应用本包全部代码后的完整项目。两者均不含签名私钥。新方案不会用旧源码覆盖远端后来已修复的文件。
5. `verification`保留实际命令、日志和主机回执；`VERIFICATION.json`只汇总本轮实际运行的检查。旧回执保留原范围，不能当作本轮真机或自然效果证明。

## 检测报告必须回答的内容

`reference/R32.1/guide/检测报告字段合同.md`和P4后态生产代码共同定义：逐对象显示输入/产物/真实消费者/数值效果、当前分子分母、冻结与可见时间、版本和证据引用、第一处失败、原因可信度、修改文件与方法、具体处方、验证动作和下一次采集触发。82项能力、20类矩阵、18张研究图、29张旧图和16张逻辑研究表按各自分母核对；矩阵别名不重复算成功。

创造策略的方法、公式、家族、矩阵和深度模型必须有可执行原件、独立训练与消费证据。历史筛选、未来资格、影子和真实结算分开记录。提高命中率的方向由失败分层、冻结实验、父子配对和消融验证决定；代码存在或历史冠军不能证明自然未来优势。一代子代有独立证据并胜过同机会父代才记改进，不强行把每一代都记成更强。

## 完整性的含义

本包交付每个声明文件的完整代码和真实差分，但“源码已给出”“某项缺陷已有补丁”“业务联测通过”“真机长期稳定”“自然未来命中达标”是五个不同结论。逐项状态见`IMPLEMENTATION_STATUS.json`，未覆盖项见`OPEN_ITEMS.md`。保留这些明确状态，是为了让下一次施工从真实断点继续，避免用虚假全通过记录再次卡住。
