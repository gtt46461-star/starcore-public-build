## 1. 为什么R31.1一直兜圈子

以下均为对施工分支`construction/r31-final-20261104`（HEAD `2c5eca70`）的实际核查，不是推测。

| 编号 | 根因 | 证据 | 后果 |

## 2. R31.2的五条硬规则

1. **批次序号=施工顺序**。S00→S21共22批，严格依次；上一批`RECEIPT.json`提交后才能开下一批，同时只开一批。56张原卡按原P00–P08依赖顺序串行展开，不打乱任何原依赖（`check-plan`自动校验）。
2. **关门只看LOCAL项**。每项原验收被固定分为四层：LOCAL（JVM单元/HOST/静态/编译/lint，198项）、EMU（Android仪器测试，8项，只在S20集中跑）、DEVICE（真机/时长，24项，DEFERRED）、NATURAL（自然质量，1项，永不作施工门）。混合项拆成“本地可验部分a + 设备部分b”，原文字节不变并记录哈希。延后项只能写NOT_RUN/NOT_PROVEN，任何批次都不能写PASS。
3. **S01先把全量测试修绿，此后永远保持绿**。S01专门修复已合入在制品造成的全量失败（Certificate指纹、内存准入相容、其余单元/HOST失败）。从S01起，每批关门都要求全量单元失败=0、HOST全过、lint与androidTest编译通过、测试数不减、跳过数不增。后续卡已在树内的代码保留，不得破坏绿色基线，并在它自己的批次里验收。
4. **唯一关门命令**：`tools/r312_gate.py`。每个LOCAL项必须在`BINDINGS.json`绑定至少一个实际通过的测试（JUnit`类#方法`或`HOST:条目`）；超范围主源码改动必须逐条写原因；证据≤20MiB/批，禁止复制源码快照。
5. **发布身份只冻结一次**。各批只跑开发构建（`compileDebug`、`compileDebugAndroidTest`、`testDebugUnitTest`、`lintDebug`）；`verifyFinalR31BuildIdentity`、`lintRelease`、r982调用清单、签名、APK/ZIP只在S21执行。

## 4. 每批固定流程

```bash
G="python3 construction/STARCORE_R31_FINAL_20261104/tools/r312_gate.py"
$G status                 # 当前批、卡、未绑定的LOCAL项
# 写/定位测试 → 填 construction/r31/r312/Sxx/BINDINGS.json → 改源码 → git commit
$G build --batch Sxx      # 本地：gradle四个开发任务 + HOST_SUITE，写BUILD_SUMMARY.json
#   本地无Android SDK：push后由r312-gate.yml跑同一命令，下载工件后
#   $G build --batch Sxx --import BUILD_SUMMARY.json
$G close --batch Sxx      # 全部条件满足才写RECEIPT.json；否则逐条列出问题
git add construction/r31/r312/Sxx verification/r31/r312/Sxx && git commit && git push
```

`BINDINGS.json`格式：

```json
{"items": {"R31-B02-C03#A3": ["com.ethk3.novaonepro.strategyv2.CommitKeyR31Test#payloadConflictRaisesIntegrityConflict"],
           "R31-B02-C02#A1": ["HOST:run_runtime_ddl_host"]},
 "scope_extensions": [{"path": "app/src/main/java/...", "reason": "调用方签名随本批接口变更"}]}
```

`close`的完整检查：上一批已关；工作区干净；BUILD_SUMMARY对应当前源码（之后只允许证据文件变化）；gradle实际执行且单元任务非UP-TO-DATE；（S01起）全量失败/错误=0、HOST全过、测试数不减、跳过不增；每个LOCAL项绑定的测试全部实际通过；不得给非LOCAL项绑定PASS；超范围主源码有原因；证据≤20MiB且不含源码快照。S00是唯一允许全量失败存在的批次，失败逐条写入RECEIPT，作为S01的输入。

## 5. 失败时怎么处理（不再兜圈子）

- 本批测试失败：只在本批修，重复“改→build→close”，不重写方案、不重审全包、不回头动已关批次的RECEIPT。
- 失败根因在已关批次的文件：在本批修，按`scope_extensions`写原因；已关批次不重开。
- 失败需要真机/模拟器才能判断：不是本批LOCAL项就不阻塞；是LOCAL项则先写HOST/JVM最小复现，复现不了就说明它不是LOCAL层，需修订方案（只能由方案修订改层级，施工中不得自行降级）。
- 同一源码、同一失败：不重复跑CI，不重复生成证据。
- 每批只交一份RECEIPT、一份BUILD_SUMMARY和失败原始日志；汇报只写：本批改了哪些文件、测试结果、下一批。
