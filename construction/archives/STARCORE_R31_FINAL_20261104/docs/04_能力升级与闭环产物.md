# 能力升级与可验收产物

这份方案同时处理故障恢复和能力提升。恢复领取任务只能说明系统重新工作；只有生成了有效策略、完成真实学习、产生可追溯研究结论并被实际预测使用，才完成相应能力验收。所有新增能力必须接入既有 owner、写事务、输入角色和资源预算，不另起一条无法追踪的后台链。

## 2. 研究产物必须被使用，不能停在图里

统一闭环：`source_run → numerical_measure → recommendation → consumer_apply → candidate_artifact → independent_comparison → adopt/reject`。

recommendation至少包含：输入数据集/修订、统计角色、支持数量、单位/轴、建议类型、适用家族/位置/窗口、有效期、可信程度、失败条件和预算。consumer_apply必须记录实际读取者版本、读取时间、修改前后配置hash及产生的候选。一个建议被多个子代使用不增加独立样本量。

四种状态必须分开：

- PRODUCED：已生成有效数值产物，尚不能证明有用。
- CONSUMED：实际改变了允许修改的开发参数或预算，并产生子代。
- CONSUMED_UNPROVEN：已经使用，但独立比较未支持增益或样本不足。
- VERIFIED_EFFECT：预先规定的独立比较支持所声称的效果，且适用范围仍有效。

对于研究图，只显示前两种状态不等于“达成高品质策略”。对于普通展示图，如存储普查、状态、资金曲线，不应人为接入算法使其“全部影响预测”；它们分别服务容量治理、故障诊断或风险评估。47图逐项规定具体消费者，避免为了满足图表数量制造无意义反馈。

## 3. 三条不同的反馈支路

**业务反馈**：已公开规范开奖结算不可变预测，写settlement与outbox；重复事件只作用一次。遗漏赛前冻结仍可把新标签送往合法训练，但不能创造过去的出手机会。

**开发反馈**：TRAIN/SELECT损失、行为重复、无效AST、算子成本、短结构失效等反馈给创造器，用于分配下一个研究轮次。保留有界失败摘要和可重放抽样，不能永久复制每个失败候选的全部中间状态。

**确认反馈**：独立确认/FUTURE决定资格、晋升、撤销与对用户的效果说明。它不能反过来让同一候选针对同一确认段反复调参再宣称独立。新研究可以使用已明确降级为开发数据的旧段，但其后必须另取未曝光段确认，曝光账本不能清零。

## 4. 同时优化质量、稳定、频率和成本

“高品质”采用版本化多目标合同，而不是单个历史命中率。至少包含：独立未来命中及基线差、恰当的统计不确定度、校准、最坏时间块、风险度量、ACT/日历机会、漏冻结和迟到率、模型CPU/内存/磁盘成本。指标的目标值和主次关系先注册，再查看验证结果。

频率不足时先诊断：无资格策略、规则本来稀疏、冻结链漏期、源延迟、模型发布未完成、阈值漂移或错误的统计分母。分别修工程或改研究，不能统一降低质量门或随机补出手。15%是本次保留的优化起点，须与自然质量合同联合检验，不是已测达成率。

最终冠军可以长期不变；这不妨碍探索持续进行。只有已确认更好的子代才替换冠军，因此“正式冠军不被未经证实的退化替换”是可施工的工程约束，“所有探索子代天然更强”不是可保证的结果。

## 5. 报告如何说明缺少什么能力和怎么修

每项能力报告应包含八个字段组：

1. **实现**：源码提交、类/方法、语义版本、运行owner。
2. **输入**：数据是否到位、角色、时点、样本、依赖与pin。
3. **执行**：任务状态、最后一次实际提交、游标单位、耗时及失败链。
4. **产物**：策略/参数/矩阵/研究建议/检查点hash，不能只有累计次数。
5. **消费**：谁使用、改了什么、实际生成哪个下游对象。
6. **效果**：采用何种独立验证、比较对象、样本与不确定度；未证明须明确。
7. **缺口**：故障、缺数据、缺教师、未实现、无支持、无改善、平台限制等精确原因。
8. **处方**：对应施工卡、文件/方法、修改动作、前置阶段、验证输入与预期结果。

如果当前报告无法提供其中某组，它应输出缺失组及补采方法，不能用一句“系统运行正常”覆盖。B11将这些字段与本包的40项合并需求、44指标、96检查、47图、60任务交叉映射。1832条历史要求原文与原状态保留；文件路径匹配只是导航线索，不宣称完成了1832条语义验收。

## 6. 施工与验收顺序不能互相循环

最终实施依赖只采用`ledgers/execution_phases.json`和每张卡的`execution_phase`。P00至P08有向无环；同阶段共用接口或同一文件的卡由一个文件owner串行整合，并在该集成组联合测试后关闭。B01/B02按同一租约/写事务合同同版交付；B07/B08按同一研究产物合同联合整合。

B05拆成两段：P02先做普查、准入、报告生命周期和堆内存治理；P06才启用需要完成权威迁移的破坏性回收。B06依赖的是P02已交付的有界基础设施，不依赖尚未启用的全部GC。B10在P05完成主链权威迁移，随后P06的图表与缓存GC才能关闭。B12是最终发布验收门，不是前序代码的开工前置。

专题原始依赖保留在`evidence/audit_manifests/original_dependencies_NOT_EXECUTION.json`用于追溯，不得展开为可执行DAG。机器自检会检查阶段覆盖、每卡归属、前置严格早于当前阶段和所有卡仅出现一次，避免施工执行器互相等待。
