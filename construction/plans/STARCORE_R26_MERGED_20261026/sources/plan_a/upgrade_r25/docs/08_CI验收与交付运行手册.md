# CI验收与交付运行手册

## 基线锁定

使用公开仓库construction/su1-20261022核实最新HEAD；本包审阅基线为cd7f058a8345de7c9c89c308c7c91416a1596760。施工前重新比较，如不同则生成文件差异审计。不要执行旧build_strategy_su1.sh自动改SU1身份并推送的流程；当前R13身份由release manifest与签名约束共同决定。

先自动发现Gradle wrapper、app模块、SDK位置、Java17、NDK及CMake。没有签名私钥时仍完成可执行的代码检查、单测与lint；打包要求真实既有签名，不能创建新签名冒充覆盖安装。既有API认证不输出到日志，真实API响应未运行就标NOT_RUN。

## 流水线阶段

1. 锁定输入commit与source tree；记录工作区有无修改和生成器版本。
2. 核对历史要求保全、两个R24补丁与R25窄补丁适用hash，按统一80卡施工。
3. 运行新增HOST合同及原仓库现有单测、lint、语义identity和catalog核验。新增任何消费者都进入语义manifest。
4. 调用实际Gradle任务 testDebugUnitTest 与 lintRelease；构建任务不自动改写源码分支。不能把这两个任务通过当成APK构建通过。
5. 通过现有受控R13签名流程构建待测APK，并记录apksigner结果、aapt包身份、SHA256。debug或release性质如实标记。
6. Android集成安装同一hash APK；覆盖旧数据、冷启动、迁移中断恢复、3期以上端到端冻结结算反馈。稳定性SLO需要更长观测，不以3期替代1000机会基准。
7. 真机矩阵读取设备和系统版本，执行锁屏、非充电、网络切换、报告取消、低存储、进程终止与恢复；未测项目不写PASS。
8. 发布包加入机器结果、diff、数据schema、模型manifest、报告、签名指纹与回退说明；最终APK须与被安装测试APK完全一致。

## 机器回执格式

```json
{
  "sourceCommit": "actual checkout SHA",
  "apkSha256": "actual tested APK hash",
  "applicationId": "actual aapt identity",
  "versionCode": 0,
  "signatureStatus": "NOT_RUN",
  "unitTests": {"status": "NOT_RUN", "tests": 0, "failures": 0, "skipped": 0},
  "apiRuntime": {"status": "NOT_RUN", "evidenceFile": null},
  "deviceRuntime": {"status": "NOT_RUN", "deviceIdHash": null},
  "quality": {"status": "NOT_PROVEN", "certificate": null}
}
```

这是字段示例，不是真实构建结果，versionCode 0只是示例占位；实际回执必须从真实工具输出生成。CI不得通过拼接字符串把测试次数固定为21，也不得从apiKey存在推导实际请求成功。

## 依赖与权限

默认contents read。构建与测试不需要写施工分支；发布工件与仓库合并分开，用户要求实际交付APK时按既有授权执行必要流程。第三方Actions版本用已核实的完整commit SHA，严禁编造pin。签名文件和密码不放缓存或公开artifact；敏感API返回做必要脱敏，同时保留错误类型和验证结果。

所有新计划脚本只作HOST规范。生产CI尚未迁入本包，因此本包没有一份声称已经可直接替代当前所有流水线的虚构YAML；按以上阶段改现有R13流程，实测结果加入机器回执后才关闭R25 028。
