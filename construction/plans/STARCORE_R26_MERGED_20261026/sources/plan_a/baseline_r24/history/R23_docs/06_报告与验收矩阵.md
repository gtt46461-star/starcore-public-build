# 检测报告、能力证明和发布验收

## 1. 四级完成度与零资产诊断

每项能力输出SPECIFIED / HOST_IMPLEMENTED / ANDROID_WIRED / DEVICE_VERIFIED，质量单独QUALIFIED / NOT_QUALIFIED / INSUFFICIENT。只要存在required缺项，完整版本发布状态不得为PASS。注册表存在只能算SPECIFIED。

最小诊断独立于研究表是否创建：报告buildSHA、APKhash、schema单位水位、最后attempt/progress、等待原因、SQL错误码、历史数量、连续有效历史、请求数量、冻结数量、已结算数量、训练outbox待处理、artifact数量。读取某表失败记录该表失败而不是整个报告只返回error=true。

能力凭据的11个位置：implementation、inputContract、trainReceipt、weightsChanged、checkpointRestore、predrawReceipt、settlementReceipt、feedbackReceipt、deviceParity、deviceLongrun、qualityProtocol。质量结果单列。主机CapabilityEvidence是字段契约检查，不是密码学证书验证器；生产必须把引用解析到实际hash和区间收据，不能仅填字符串骗过门。

## 2. 全功能矩阵

|类别|必须看到的真实产物|失败时具体输出|
|---|---|---|
|抓取|源响应hash、提交receipt、水位与下一期请求|HTTP成功但未提交、重复/乱序/冲突、重试游标|
|数据|合法排列、连续区间、有效长度、5000滚动|缺口位置、重复期、source mismatch；不可凭无SQLite断定损坏|
|迁移|DDL单位hash、已提交/总数、nextUnit|阻断SQL及等待资源、未就绪能力|
|创造|TypedHypothesis→编译计算图→不同机制/行为|空壳、重复、类型错误、只有改参数|
|训练|梯度/状态增量、损失、权重前后hash、耗时|没有update、无标签、预算不足、NaN、更新覆盖|
|恢复|重启前后预测/优化器继续一致|状态版本、缺口、损坏、origin误判|
|专家|失败簇→提案→最小反例→实验结果|只生成解释文字、无代码变更、无可证伪指标|
|进化|父子hash、映射、行为改变、配对证据|只涨教师分、误继承命中、NO_OP计代|
|门控|选择后校准、质量覆盖前沿、固定区间指标|分位门凑频率、置信过高、样本不足|
|主链|证书→提名→intent→唯一授权→结算|拒绝站与原因；REAL推荐没有外部执行回执|
|报告|完整分母、缺项、下一施工卡|报告导出成功不等于业务通过|
|设备|冷启/覆盖安装/关屏/恢复/持久运行测量|崩溃、OOM、ANR风险、超时、后台限制|

主机测试通过不能自动填ANDROID或QUALITY。给每个测试保存命令、环境、实际输出、代码hash、证据hash和失败案例，不能只填写true。

## 4. 失败驱动升级报告

每个失败簇记录causeKey/stateKey/position/numberGroup/entryOffset/sample/hit0/delayHit/LCB/decayRisk。hit0是目标期命中；delayHit只能用于研究下一步条件，不能补成原期命中，不得因此追期。

输出建议不是“增加深度学习”而是可执行experiment：例如calibration_overconfidence中固定四个模型，只比较旧分位门与已冻结的选择后校准门；差异仍不显著则拒绝该解释。空间剪枝问题必须说明真实号在哪一阶段被删、候选概率质量如何变化，但最终仍K3。
