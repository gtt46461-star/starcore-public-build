# Android生产改造接口、事务和运行包络

## 1. 禁止新增重复owner

下列SU3/R23类名是拟新增适配/状态类，不是已经存在的文件；既有主要入口位于app/src/main/java/com/ethk3/novaonepro/及strategyv2/。数据库迁移走既有ResearchSchemaCoordinatorR926/StrategySchemaSU1/SU2；授权仍DecisionGateEngine；结算仍SettlementEngine；CPU任务不持有DatabaseCoordinator写锁。

```java
// 拟增接口，Android不支持record时用final不可变类。
interface TrainableFamilyR23 {
  String mechanismId();
  FrozenMarginals predict(PastOnlyInput input, ImmutableArtifact artifact);
  TrainingDelta trainStep(TrainingBatch batch, ImmutableArtifact parent,
                          OptimizerState optimizer, ComputeBudget budget);
  ArtifactBytes encode(TrainingDelta state);
  RestoredState restore(ArtifactBytes bytes, CompatibilityContract contract);
  MutationPlan propose(TypedHypothesis hypothesis, ParentSchema schema);
}
// predict不得改变训练状态；标签只能通过结算后的batch进入。
```

既有OnlineModelsSU2.Model的stateWidth/predict/update/write/read接口可以保留为兼容外壳。新增FamilyRuntimeAdapterR23将单个不可变模型快照提供给predict，update在锁外私有副本上调用；不能把新的可变模型直接放回旧settleWithin事务。

## 2. 必需记录与字段

|记录|必须字段|不可省略约束|
|---|---|---|
|artifact|artifactHash,parentHashes,mechanismHash,featureHash,learningRuleHash,trainedThrough,optimizerHash,rngHash,serializationVersion|内容寻址、写完整再发布|
|hypothesis|failureCohortHash,causeKey,stateKey,graph,operator,budget,falsifier,proposalBirth|不可使用出生后验证结果修改本次假设|
|prediction|issue,policyVersion,artifactHash,inputThrough,createdAt,deadlineAt,position,numbers,rawMarginals,calibratedQuality,mode|inputThrough严格早于目标；deadline前；同一政策同一期不可变|
|settlement|predictionKey,labelHash,settledAt,hit,settlementOwner,revision|唯一结算；不同labelHash冲突隔离|
|training_outbox|modelVersion,labelSequence,ruleHash,parentHash,status,attempt,lastError|唯一键防重复；无REAL也可登记|
|publication|modelVersion,expectedThrough,newThrough,artifactHash,commitReceipt|CAS防止旧训练覆盖新快照|
|generation|parentPolicy,childPolicy,behaviorDiff,evidenceRange,pairedProtocol,qualityGate,verifiedStatus|名字/代数不得代替证据|
|mainline_handoff|certificateId,nominationAt,intentId,rejectionStation,rejectionReason,executionReceipt|每站可追踪，REAL冻结不等于外部执行|

在历史≤5000限制下，原始开奖表按滚动策略清理；学习状态与统计摘要保留hash和水位，不能把原始开奖复制到另一大表绕过限制。需要长期逐条审计的证据包应明确导出/留存策略，不偷偷无限膨胀手机数据库。

## 3. 原子闭环伪代码

```text
onValidatedDraw(draw):
  dbOwner.atomic:
    verify source hash / handle duplicate or revision conflict
    commit canonical draw
    settlementOwner.settle_existing_frozen_predictions(draw)
    insert training_outbox for registered eligible learners
    persist next target + analysis request
  dispatch fast analysis from latest committed model snapshot

onTrainingSlice(job):
  immutableParent = artifactStore.read(job.expectedParent)
  batch = read_only_history(job.cursor, label_cutoff)
  child = train_private_copy(immutableParent, batch, bounded_steps)
  artifactHash = write_immutable_blob_and_verify(child)
  dbOwner.atomic:
    CAS expected cursor; record artifact; mark consumed labels
  publish RAM reference only after durable commit
```

主机参考durable_learning_r23.py使用独立临时SQLite验证契约，不是让生产另开数据库；端内必须移植到原owner。其测试用连续整数序列，生产使用已校验sequenceId，禁止直接对日期期号做加减。

## 4. 资源规划与服务等级

实时：优先保障开奖验证/落库、当前结算、下一期分析冻结。轻量：初始化进度、种子、每期反馈、证书维护、诊断。重研究：大搜索、训练重放、多家族消融。三类都要记录attempt/progress，不能将“线程启动”计为进度。

候选游标为campaign/family/candidate/fold/minibatch/step。预算中止必须可恢复；一次压缩或模型构造超过切片时，把它移出写锁并分块，而不是仅在外层if超时。实时过期后不得补作赛前预测；用明确NO_PREDRAW原因保留覆盖损失。

拟定设备验收场景：低电量、充电、未充电、屏幕关闭、网络断开/恢复、源重复/乱序、数据库写拒绝、进程被杀、设备重启、5000期滚动、报告并发导出、模型artifact损坏、学习任务重投递。主链时延≤5000ms是既有目标而非本轮已测结果；每种设备须报告P50/P95/P99、最大值、失败率、RSS和功耗。

Android服务运行受OS规则约束。验收先锁定targetSdk、serviceType、权限及后台策略，使用合法的通知/用户启用方式；不得依靠持续重启服务、伪造服务类型等绕过限制。若当前部署方式不支持全天连续服务，必须显示可用时段/降级原因，不可承诺“永久后台”。

## 5. 无资产/无证书时也能工作

空数据库→最小schema→已知历史校验→创建研究种子→历史训练→恢复测试→LIVE_SHADOW冻结→每期结算学习→新期资格。种子不合格仍可训练，不能获得REAL。无预测历史只提供训练标签，不能补造成前瞻。

所谓“满血”最终验收为每项必需能力都有可测进度与产物，不是把所有能力的开关强置true，也不是把所有模型并发开到OOM。
