## 3. 根因树与优先级

### 3.1 已由报告和源码共同支持的断点

```text
RESEARCH schema尚未完成
  ├─ 常规研究回调先受实时压力阻断，再受schema gate阻断
  ├─ SU1迁移每次只推进一条；缺总量/下一SQL/持久进度的清晰报告
  └─ SU2建表只在充电+idle周期Job的入口可见
       ↓
没有可运行SU2资产 / 训练与诊断入口缺表
       ↓
历史快速训练不能作为普通运行的可靠启动路径
       ↓
冻结预测、结算反馈、校准、证书与主链资格都无法自然积累
```

此图表示可证实的依赖阻断，不把所有停滞归因于唯一一个未知异常。历史补采与实时写任务共享写入压力、主线程心跳同步IO、模型全量恢复等是并存问题，需要分别验证。

### 3.2 代码级确定问题与待复现风险

**确定存在的设计冲突：** 15%短窗样本门槛；Job充电/idle限制；SU2全表建造集中在Job；诊断catch仅保留error=true；结算事务内模型训练/压缩；`genesisSeq < retainedFirst`导致滚动窗口后拒绝旧检查点的条件。

**需要故障注入/真机证明的影响：** 97条迁移是否长时间不前进；哪条具体SQL或哪类持锁造成WRITE_REJECTED；模型RAM先更新、事务后回滚是否发生过；手机到5,000期滚动后是否每期全量重放；部署缺失是否来自未接线、被门槛淘汰或构建选错版本。诊断应明确`OBSERVED / SOURCE_CONFIRMED / REPRODUCED_HOST / DEVICE_UNPROVEN`，不能一律写“已彻底修复”。

### 3.3 还必须修复的现场覆盖与后台问题

最近30个开奖只有4条冻结预测，缺席26条，其中24条NO_ANALYSIS_REQUEST、2条过期/替代。主循环当前能做出少量预测，不是整个APP完全没有运行；但逐期覆盖显然未达要求。P73/P74同时修开奖提交→目标期→分析请求的耐久衔接。报告还记录后台能力查询READ_ERROR、电池无限制=NO、精确闹钟=NO，P100必须验证权限读取和设备真实行为，不能把这些都归咎于算法。旧汇总settled=0与canonical详情4条的口径差异纳入P96/P98核对。

## 4. 主链约束与成功定义

固定单位置K3，每期最多一条REAL。保留唯一`DecisionGateEngine`授权和唯一`SettlementEngine`结算。所有新增专家、家族、编译器和训练任务只能提交候选或不可变intent，不能自行授权、下注或另开结算链。没有执行回执时，只能称“REAL推荐/冻结”，不能冒称外部真实成交或实际投注。

**15%定义：** 主链在预注册的应服务有效期集合上的质量覆盖目标。推荐以4,000期证据窗评估，600动作对应15%；短窗1,500期用于及时风险观察，不再要求其也有250动作。15%不是限制上限，也不是每期随机抽15%。在质量合格、运行健康、用户启用时可以更高覆盖。若优质机会不足，报告`QUALITY_COVERAGE_SHORTFALL`并进入定向研究，不能强凑动作。

个体专家可以更稀有；组合策略必须对**去重后的单一动作流**重新验证。三个5%专家不自动等于15%合格组合，重叠、选择器误差与相关性都会改变实际结果。能独立达到约15%的合格资产不得因为隐藏250/1500条件被排除。

产品目标继续保留：主检验命中率≥35%，37%为更强目标，40%为优先目标；固定块稳定性、校准、有效样本与下界同时验收。观察最长连挂≤6作为原质量目标保留，出现第7次连续失利进入风险处置。暂停、跳过或切换策略不能清零已有真实动作连挂。该规则不是对未来最长连挂的保证。

四层通过必须分别显示：`ENGINEERING_VERIFIED`、`HISTORICAL_RECIPE_QUALITY_MET`、`FRESH_POLICY_QUALIFIED`、`DEVICE_REAL_CHAIN_VERIFIED`。CI成功不能跨层；高训练胜率不能跨层；候选数量变多也不能跨层。

## 5. 数据库、迁移与调度的具体改造

### 5.1 迁移不再等重训练Job，也不允许假READY

在既有数据库owner下维护最小能力依赖：`INGEST_READY / LABEL_READY / DIAGNOSTICS_MIN_READY / TRAIN_STORE_READY / FAMILY_RUNTIME_READY / CERT_READY`。这些是能力状态，不是新数据库或新owner。`ResearchSchemaCoordinatorR926`返回结构化`MigrationStepResult`：

```java
record MigrationStepResult(
    String module, int expectedUnits, int committedUnits, String nextUnit,
    String lastCommittedUnitHash, long lastProgressAt, long lastAttemptAt,
    String waitReason, String sqlErrorCode, String causeChain, boolean ready) {}
```

实际Android Java版本不支持record时用不可变final类实现。DDL与该单位收据同一事务；步骤hash不匹配必须诊断`MIGRATION_DRIFT`，不能跳过。SU2现有一次执行所有DDL的`ensure()`拆成小单位；涉及复制旧大表的迁移采用有界copy cursor＋最后原子切换，不能假设“一条SQL就一定短”。报告必须看到“已97/总N、下一单位是什么”，本轮没有凭空编造N。

`lastAttemptAt`只代表尝试；只有DDL提交或业务水位前进才能更新`lastProgressAt`。进度老化进入有界保留槽，不允许所有空闲时间都被同一高优先级后台任务占掉；实时硬截止临近时仍需让行，若连续无法给槽要记录资源不可行，而非无限显示初始化。

### 5.2 三类通道仍共用一个写入owner

实时通道负责开奖入库、当前结算、冻结与唯一授权；轻量研究通道负责启动迁移、种子、每期增量任务、证书/诊断；充电加速通道处理大规模搜索、重训和大消融。Job仍可用于加速，但不是算法存在、SU2建表或有效证书更新的唯一触发器。

所有CPU训练、完整历史回放、候选评分、gzip、报告构建都在写锁外。写锁内只执行小量条件更新和短收据。WAL不意味着可并发多个写者，因此不能靠再加写线程治本。[M1]

优先级不是固定“实时永远吃完”：实时任务受截止保护；轻量任务有最大等待观察和老化；历史补采下调优先级并限页。边界是**不能为了迁移抢占正在进行的原子实时结算**，也不能在实时任务结束后永远不给迁移机会。

### 5.3 心跳修复不是机械commit改apply

主线程从内存快照读取UI字段。频繁心跳合并到单独持久化owner；租约接管和用户启停必须保留耐久回执/代次隔离。`apply()`也有生命周期阻塞与无错误回执问题，不能简单全部替换后宣称安全。[M2]

## 6. 抓取几期、历史积压、训练没有数据的统一解释与修复

界面必须分别显示：库内总历史、连续可训练历史、最近成功HTTP、最近成功提交、当前待结算、已冻结预测、已有真实动作、历史训练样本、前瞻证据样本。把“已冻结5条”叫作“只有5期历史”会误导排障。

本次4,743历史中2,589条PENDING不能只通过SQL批量标成成功。恢复器分三种：存在当时的不可变赛前冻结则按唯一owner结算；确实没有冻结则标`EXCLUDED_NO_PREDRAW`终态且不计预测命中；证据未齐则继续具名等待。历史数据仍可用于`HISTORY_REPLAY`训练，**训练不以过去曾真实出手为前提**。

抓取写失败时，保留有限量payload/hash和待落库任务；重复返回同一期只承认相同hash，冲突单独隔离；提交后才推进watermark。不可只在UI说“抓取成功”而数据库拒绝。

每个已确认开奖产生两种独立消费结果：预测结算消费、学习事件消费。没有算法时仍能创建seed/proposal；没有REAL时仍可训练研究资产；没有ACT时可更新已注册在线策略；但缺赛前预测绝不能通过学习重放补造成真实预测。

## 7. 快速历史训练与在线学习：从“入口存在”变成实际闭环

`ModelFoundryJobSU2`现有门槛是至少3,400期，8代、24候选、1200期VAL。当前历史数4,743已超过这个数值门槛，因此不能以“历史就几期”解释这里的零产出；真正前置还包括schema和调度。方案不简单删掉样本门槛，而是按家族提供`minimumTrainRows`，不足时产明确`WAIT_HISTORY`和可运行的小样本研究骨架，不授予REAL。

把整代执行拆为`campaign → family → candidate → fold → minibatch → optimizerStep`游标。所有状态包括权重、优化器、随机数、训练截止、特征hash、编译器版本、学习规则版本、父代谱系持久化。共享历史编码与各家族重复特征缓存；候选独立保存轻量差异；资源预算耗尽时保留确切可续游标。

现有HallOfFame保存表达式里的`evo.dev()/evo.val()`移到写事务之前。不得只修改注释“每片≤2秒”而仍一次跑完一代。预算是协作检查与实测最大值，单个不可中断操作超时必须拆分。

在线事件顺序：

```text
冻结prediction(t, artifact(t-1), inputThrough=t-1)
→ 开奖校验/唯一结算提交label(t)
→ 同事务写training_outbox(t, ruleHash, revision)
→ 锁外读取不可变父检查点，训练私有副本
→ 写入artifact并校验完整hash
→ 短事务CAS推进trainedThrough与publicationReceipt
→ 提交成功后原子发布，下一期读取新快照
```

失败前后不能让RAM比DB先走一拍。当前`ModelLiveLoopSU2.settleWithin()`在事务里训练静态RT并压缩，需彻底拆开而不是仅外包一层线程。

### 7.1 5000期滚动不能使学习每天从零

`originSequence`表示模型起源，不等于恢复需要的最早原始数据。已有检查点在5000期，原始窗口从1滚到2，只需第5001期增量，不应因为`genesisSeq=1 < first=2`拒绝恢复并重放5000期。恢复条件改为：模型/特征/学习规则兼容，检查点through≥可用数据first−1，补齐区间连续，检查点没有越过目标。只有确实缺不可重建状态才触发明确再训练任务，并保留当前已验证模型。

## 8. 创造能力重建：16种研究专家＋24种结构家族＋6类尺度

家族与专家清单在两个JSON注册表中，每项规定输入、结构、损失、变异、真实产物和验收。它们是**待实现目标注册表**，不是声称本轮已经训练出24个优秀家族。现有`ModelGenomeSU2`主要基类为MSDIR、BOCPD、HMM、LOGLIN、KALMAN、RELBAYES，另有SU1PROG、ATOMNET、REGMEM、RELMEM、CONTMAT适配；保留这些作为对照和可复用能力。

新增研究系统不再只有“换窗口/换随机种子/加投票权”。专家根据失败证据提出可执行结构改造：例如选错位置交给位置关系专家；真号在7→5被删交给集合解码专家；高分窗口实际低命中交给校准专家；相同失败跨家族同步出现交给相关性与状态专家。每个提案必须说明**为什么预计解决此类失败、具体修改哪个算子、需要哪份数据、如何证伪、最多消耗多少预算**。

24种机制包括跨位置时滞图、排列因子图、超图、因果TCN、双轴注意力、状态空间、图递归、隐状态专家、半马尔可夫、变点局部模型、度量检索、结构自动机、有类型公式、程序宏、完整K3集合评分、软多层解码、联合排列能量、自回归排列、低秩关系张量、状态片段记忆、层级条件贝叶斯、失败残差、旧策略蒸馏、互补专家联合预测。每个机制至少提交独立计算图、可训练参数、状态格式和正反fixture；只有参数或显示名称不同不得增家族数。

### 8.1 六尺度不是六倍重复统计

默认尺度8、32、128、512、2048与最多5000可用期。各尺度共享底层嵌入，输出有效样本mask、缺口标记和状态置信。旧数据不足某尺度时，不造出等长重复数据。所有位置、号码、集合、家族对同一期的观测相关，统计单位仍是一期，不把1200动作×24家族×6尺度算成几十万独立样本。

### 8.2 深度模型容量与手机运行

先实现小型可验证的因果编码器、图编码器、集合读出和程序解释器四个计算骨架；随后完成家族适配、状态继承与互补组合。不预先给每家族超大网络。初始参数预算、训练步、活跃模型数全部配置化，真机以deadline/RSS/功耗实测收缩。容量增加必须在固定数据与预算的消融中带来独立改善，不能用“更深/更多”当作胜率证明。

## 9. 公式创造的可执行协议

一个候选不是一句“多位置交叉”。其结构必须包含：

```text
Hypothesis {
  causeKey, stateKey, applicableWindow, supportRows,
  featureGraph, predictorGraph, setDecoderGraph, selectionPolicy,
  familyId, parentArtifactHashes[], structuralOperator,
  trainingRuleHash, exposureBudgetId, computeBudget,
  expectedFailureReduction, falsificationTest
}
```

Typed-DAG类型至少包括`PastPermutationTensor / LaggedRelationGraph / StatePosterior / NumberMarginal / K3ActionScores / CalibratedActionProbability / FrozenIntent`。编译器拒绝当前未知开奖、未来标签、动态K、追期和强制凑频率等节点。结构ID、参数ID、行为指纹、学习规则ID分开；只有真正新结构/新行为才记新策略。研究性随机探索可保留少量明确预算，但不能把它包装成“已深度学习创造”。

程序宏来自DEV中多次有效的子图，必须有引用版本和消融；学习型提案器用历史研究的成败来调整下一次搜索方向。这类“学习搜索与可复用程序库”的设计可参考程序合成研究，但其在本数据的优势必须独立验证。[M4]

## 10. 多位置、多号码到唯一K3：不能硬剪死正确支路

本次对照发现，在325次研究动作中，7码集合命中236，5码集合命中158，最终3码命中103：7→5丢失78个已包含的真实号；5→3再丢55个。它说明应检查缩减阶段，而不只是追加号码冷热特征。不能据此直接声称“只要不缩减就可保持72.6%胜率”：最终任务仍必须固定K3，扩大集合不是合格改进。

R22最终动作空间为10×C(10,3)=1200。粗层结构为候选提供约束和特征，但允许多个软分支；最终使用集合评分＋全动作比较，保留被早期错误剪枝的纠错机会。每期真实开奖可以给所有候选动作打标签，用于训练；然而一个期号仍只有一个统计簇。最终选择器也必须走步验证，不能在事后1200动作里选中奖者。

拟采用的损失组合：逐位置/联合排列NLL，集合包含标签的成组排序或BCE损失，边际与集合一致性约束，校准损失与复杂度惩罚。损失权重只在DEV/TUNE定；固定旧策略、纯独立边际、硬集合格、无状态等作消融对照。深度网络输出不是天然校准概率，不把最大softmax当可信胜率。

## 11. 动态进化、变异、融合与“一代更强”的正确实现

每次变异先分类：参数变化、结构变化、适用状态变化、学习规则变化、融合/蒸馏变化。不同类别决定兼容性与证据起点。同构复制权重/优化器；异构进行可追溯映射或蒸馏；父代只读，子代出生后重新累计自己的证据，不能继承父代70/152命中。

保留四个计数：搜索尝试、有效新结构、合格资产出生、前瞻验证改善。NO_OP、改名、反复调同组参数不算已变强一代。既定在线学习规则每天更新权重可继续同一政策序列，不必每期清零；换结构、训练规则或选择政策则注册新版本和新比较。

进步判据不是某次训练分更高，而是父子同区间、同成本、同有效机会的质量目标和配对证据通过。旧强资产保留在不可变档案和在任保护中，挑战失败不覆盖它。未来性能可能漂移，系统以监测、暂停和有证据回滚应对，不能把“永远不下降”写成已成立性质。

## 12. 15%质量覆盖前沿与主链接入

### 12.1 不能把Top15%当作高胜率

本轮固定对照采用既有R21配方，仅把过去500个score的门槛从70分位改为85分位。实际覆盖14.49%，不同固定块覆盖约8.39%、13.73%、31.73%、4.10%。其中高频块命中27.53%，低频末块只有23次动作，命中47.83%。后者不能挑出来当“系统已达47.83%”；它提示score分布漂移和选择后校准需要检查，不构成确定的收益因果结论。

新门控依据选择后校准的动作质量和状态可信度，而非机械只取15%。定义政策集合的前沿：在预注册数据和成本下，达到覆盖≥15%的政策中寻找更高的下界、更稳的分块表现和更少动作连挂。没有同时可行的点，就报告缺口与下一步结构研究，不用放宽质量去掩盖。

### 12.2 必须修复但不能削弱资格

把资格样本窗与风险观察窗分开：挑战者可用长窗≥250动作进入比较；正式证书保留足够新期动作（现实现600，约15%需要约4000期）和完整分母；短窗1500的225次不因少于250直接降级。近期样本不足是`INFORMATION_LOW`，缺冻结是`OBSERVATION_GAP`，统计上确认退化才是`DEGRADED`。这些状态的动作不同，不能合并为一个bool。

保留现有`AlphaLedgerSU1`的生命周期预算；对主链切换所用的重复查看补齐可审计预算。固定样本置信区间不能反复每天挑最好的看而不校正；时间一致区间或预先安排的检验要陈述其条件。[M3] 同期候选相关性与时间依赖需要配对/成组处理。仅换成“高级统计名词”不算实现，必须有已知真值和反例测试。

### 12.3 真的合格后不能停留展示层

路径为：`trained artifact → live shadow frozen policy → settled evidence → valid certificate → promotion queue → chosen immutable intent → DecisionGateEngine → canonical REAL record → execution receipt（若有）→ SettlementEngine → stats/feedback`。

证书维护不再只依赖充电Job；候选有明确提名队列。相同策略在同条件获得有效资格时，工程层不能无理由无限停在SHADOW。但用户关闭、来源断链、证书失效、风险暂停或未出现该策略适用窗口时仍不可强制REAL。报告必须显示具体拒绝站和原因，不用一个“SHADOW_ONLY”盖住所有情况。

## 13. 检测报告重写：无需等2000期才能发现启动故障

报告输出固定四层：**代码存在、接线存在、实际调用、产物/效果**。例如“F04注册=1、训练步=0、checkpoint=0、freeze=0”应显示已注册未运行，而不是“深度家族已启动”。每项都记录lastAttempt与lastProgress、输入数、输出数、未消费数、首次阻断、责任文件/方法、预算和下一步验收。

启动期/无表时也必须生成完整故障诊断，不执行一个不存在的`su2_diag_snapshot`查询就结束。建议契约：

```json
{
  "schema":"R22_DIAGNOSTIC_V1",
  "status":"BLOCKED_SCHEMA",
  "firstBlockedStage":"SU1_MIGRATION",
  "committedUnits":97,
  "expectedUnits":null,
  "missingTables":["su2_model_genome","su2_diag_snapshot"],
  "rootEvidence":["schema_not_ready","mandatory_path_depends_on_charging_job"],
  "qualityMetrics":null,
  "fixCards":["P70","P71","P97"],
  "evidenceLimits":["single_snapshot","raw_sqlite_not_exported"]
}
```

这里expectedUnits为null，是本次报告没有足够字段；生产新版本应填真实数组长度。无胜率样本必须null，不是0。每条诊断须有“看到什么→源代码条件→最小复现→修改→验收→复验结果”。程序无法自动确证的深层统计原因显示假设和反例设计，不自称能仅凭一份报告完美推导所有升级答案。

报告必须包含：100位置—号码面、1200动作覆盖、每家族训练与淘汰漏斗、出生后父子对照、适用状态、7/5/3丢失树、选择后校准、固定块稳定、连挂序列、主链缺席、唯一owner冲突、CPU/持锁/RSS、后台重启恢复、存储淘汰、所有功能四层状态。大证据按固定页数/字节分卷并SHA校验；达到预算时明确未导出内容，不能仍声称完整原始证据。导出可取消，旧大报告可安全清理但不能删除未结算业务证据。

## 14. 完整历史、旧优势与新数据的证据等级

本轮4,743开奖与上轮重合2,115且无号码冲突。这证明报告之间一致，不证明外部开奖源绝对真实性；如需来源认证须另核验采集时间、原payload和源接口证据。旧125策略档案和原高分记录继续保留；这些记录既不能被新模型均值抹掉，也不能在缺原执行器冻结链时直接给新代码背书。

新研究同时建立三条线：原执行器精确复现、兼容迁移对照、真正新期前瞻。固定历史可反复用于研究，但每次接触都记暴露账。开发者看过的“测试集”再调方法，不能继续说严格未见。历史高分、历史走步、冻结前瞻、真实执行四类成绩分别展示。

## 16. 施工顺序与交付标准

16批详见`03_批次顺序.csv`。B01—B05优先恢复版本、迁移、普通运行研究、写入/心跳、积压、增量学习与无表诊断；B06—B10实现R21能力对齐、专家/家族、结构程序创造、状态/集合解码、谱系；B11—B13完善独立证据、15%质量门控、资格主链；B14—B16完成全功能诊断、容量与设备验收。

## 17. 不允许的捷径
