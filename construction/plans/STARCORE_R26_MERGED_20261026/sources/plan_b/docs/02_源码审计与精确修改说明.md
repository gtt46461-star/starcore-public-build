# R25 源码审计与修改说明

## 阅读范围与证据

全部路径前缀为 `app/src/main/java/com/ethk3/novaonepro/strategyv2/`，除非另行注明。行号针对附件中SHA匹配正文，仅是定位锚点；实际施工必须按hash和方法确认，不能把行号强套新提交。40份正文SHA核对通过；32份纯Java正文一起编译通过；排除ProgramModelSU2是其依赖的5份SU1正文不在当前完整正文集合，不以stub伪造完整构建。Android依赖类未做安卓构建。

`evidence/source_coverage_994.json`列出994条源文件、正文可得性、哈希结果；不能把缺失954份正文的静态调用索引当成已阅读源代码。当前仓库连接可读取特定文件，但容器无法通过DNS拉取整库；本轮没有取得全仓checkout。

## A01｜ModelGenomeSU2身份与不可变性

证据：27—40行公开TreeMap；65—73行text/key；92—117行parse；132—137行4位有效数字fmt。本轮原Java反例见 `legacy_defects_reproduced.json`。

禁止只把 `%.4g` 改成 `%.17g` 就直接覆盖全部旧资产。还要解决类型、字符串分隔符、跨语言语义、parse/serialize、所有缓存key和证书绑定。

实施：新增 `PolicyIdentityR25.java` 与 `GenomeCodecR25.java`，协议域分别`STARCORE_POLICY_R25_V1`与`GENOME_R25_V1`；参数改成不可变结构，构造时深拷贝；持久化中浮点固定8字节大端，所有字符串UTF-8长度前缀；集合明确顺序/无序语义；空值、整数、浮点、字符串分类型。展示的公式保留最多数位不影响identity。旧ModelGenomeSU2只用于旧格式载入；新增格式不复用旧SU2魔数。

调用点：ModelEvolutionSU2候选键/缓存；ModelReplaySU2.Library缓存键；ModelLiveSU2.Hub模型键；ModelStateCodecSU2编码；ModelStoreSU2资产查找；委员会/教师/证书/报告键均使用统一映射。研究资产升级和正式证据迁移分开。若旧输入文本已截断，不凭空恢复原权重，重新导入后新policy出生。

验收：相近浮点不碰撞；类型不同不碰撞；JSON字段顺序不影响语义；外部map修改不影响策略；保存恢复后的预测一致；旧文本仍能读；旧证书不会自动附给新ID；跨Java/Python黄金字节逐字一致。

## A02｜SelectiveEvidenceSU2配对证据

证据：36—65行evaluate；57行上界；65行仅paired<0拒绝。原例1000期、40%对45%仍PASS，是反例而非实盘结果。

修改：新增 `PairedQualificationR25.evaluate(TrialCalendar, Protocol, AlphaReservation)` 返回 `INSUFFICIENT/NONINFERIOR/IMPROVED/INFERIOR/INVALID`及lower/upper，不返回含混布尔；以`lower >= -margin`判非劣，`lower>0`判改善。margin来自冻结Protocol，不允许调用者看结果后传较大δ。样本不足不能归DEGRADED。

删除生产授权调用路径上对 `SelectiveEvidenceSU2.pass` 的直接信赖；旧函数可保留为LEGACY_REPLAY_ONLY以重现历史。调用图中所有消费者必须逐个替换并导出静态检查，没有取得全文的消费者列BLOCKED_SOURCE_MISSING，不擅自伪称全部替换。

缺失修复：用枚举的TrialRow替换可矛盾的act/hit/missing布尔组合。MISSING不能同时有settledHit=true；ABSTAIN不记命中/失误；迟到预测不得进入前瞻证据；数据无效、网络缺失、模型拒绝分别统计。运行完整性先于统计判定。示例下界实现见reference_r25.py，生产需绑定预算账本和前瞻可见性，而不是只复制一个sqrt。

## A03｜ModelEvolutionSU2裁判与代数

证据：91行val实际用DEV+VAL；139行judgeEb；641行committeeJudge改善即增加effectiveGenerations。已有多种真实建模结构，不应整体删除。

改名：`val`→`researchSelectionScore`，`valFit`→`researchFitCache`；修改日志/报告字段同批进行，兼容旧键只读。保留教师排序，但不得作为资格下界。增设独立QualificationEvaluatorR25，读取冻结TrialCalendar，不接受任意历史概率表。

旧effectiveGenerations迁移到legacyResearchGenerations；新增七类计数，并让verifiedImprovements只由不可变资格事件写入。结构相同只调参数不增加structuralCandidates；结构新但行为退化为原模型只记attempt。创建日志必须保留失败者。

缓存key还须加入policyHash、datasetManifestHash、splitHash、teacherSnapshotHash、scorerVersion；不能同策略在不同输入快照沿用旧分数。每个任务开始冻结这些字段，新增开奖不改变进行中的campaign输入。

## A04｜ModelReplaySU2概率、门控与缓存

定位Library 26—55行、构建器build、pooledTable、evaluate/门控分段。真实模型构建必须保留；旧ADAPTERS注册需核对真实接线。

概率输出接口分开 `RawLogits/Marginals/ActionProbability/UtilityScore`；无条件把score叫phat禁止。多位置K3统一从合法边际求和；risk加成不写入概率列。quantile历史阈值只能标targetCoverage，不标qualityPass。

新增SharedFeatureFrameR25与GlobalResearchBudgetR25。Library、Evolution的tables/results/cumLL、ModelLive的Hub和校准环共享预算；禁止多份同历史T×10×10复制。超过bytecap时单个模型过大必须返回RESOURCE_BLOCKED，不能因为“cache只剩1个”继续突破预算。

验收：不同数据hash不能命中同结果缓存；缓存清空不改变预测；float/对象/native内存分别测；全1200动作和最优Top3一致；zero-act报告coverageFailed而不是qualityPassed。

## A05｜ModelLiveSU2 / ModelStateCodecSU2 / ModelStoreSU2

定位ModelLive.Hub.adopt/adoptCalibrated、predict/update、readModelsInto/readInto；ModelStateCodec.writeRanked/readRanked 71—74行；ModelStore.settle及状态落库。

新增PolicyManifest、CheckpointManifest、PublishIntent与CommittedSnapshot。生命周期是冻结规则、更新状态、提交状态、再激活。Checkpoint必须覆盖教师状态、校准环、meta gate状态、归一化器、RNG、递归状态和游标；单独保存权重不足。

Codec新版本含policyHash和状态schema。若压缩长度/展开长度/矩阵形状/CRC/hash不匹配，拒绝并回落到上一个已提交合法checkpoint，不重置出生日期、不把已结算标签再消费。共享Hub恢复必须保证所有成员与calibrator游标一致，不能仅检查models.size。

接口：`PreparedCheckpoint prepare(ReadSnapshot, FeedbackBatch, SliceBudget)`在写事务外运行；`commit(expectedCheckpoint, prepared, consumedEventIds)`由原DB写Owner在短事务中完成；`publish(committedId)`只读已提交记录。取消的prepared只可进入GC，不发布。

## A06｜MainlinePolicySU2 / MainlineAdapterSU2 / RealAuthoritySU2

已有R24补丁保留，但不能把它当完整R25。MainlinePolicy 30行250/1500、91—98行demotable，需状态化而不是一个boolean。计划修复应把旧比较方法替换为同日历下界与永久预算。

MainlineAdapter只向DecisionGateEngine交PreparedDecision及冻结证据引用，不自行产生第二条REAL。RealAuthority验证policy证书允许的checkpoint演化规则；旧策略fallback也要验证当前资格。所有hardcoded全局false/SHADOW_ONLY的解除须经过双向授权测试与独立配置审查，不能为了让应用次数>0直接硬编码true。

## A07｜OnlineModelsSU2 / AtomStreamSU2 / AtomNetSU2

OnlineModels具有真实预测/更新实现，run先predict后update；保留这个顺序并增加prefix-test。AtomStream现有RING=1600，不应声称已经覆盖5000尺度；扩展为共享history view和独立状态缓冲，不能每个原子分配5000×100数组。

AtomNet的predict/update须绑定相同featureFrameId；防止反馈时用已更新的当前状态重新算上一期特征。梯度、状态量、训练样本和权重差分别导出。将原子线性/交互/非线性贡献做受控消融；credit高并非因果证明，credit只用于提出下一次实验。

## A08｜未取得正文的正式主链文件

DecisionGateEngine、SettlementEngine、DbStore、策略迁移/调度/报告Owner等部分正文不在40份匹配集合内，当前索引可定位但不能提供未经验证的“替换第几字符”。施工者应在B00从实际checkout补足，再执行以下前置断言：只有一个正式REAL写入口；只有一个正式结算入口；canonical冻结在截止前；数据库迁移继续原游标；报告为只读。

R25卡中对这些文件的修改以语义锚点、前置断言、输出契约和测试指定，标SOURCE_BODY_REQUIRED；拿到全文后生成受hash保护的patch。拒绝为了看似精确而编造不存在的行号。
