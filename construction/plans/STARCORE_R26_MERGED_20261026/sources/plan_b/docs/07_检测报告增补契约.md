# 28章检测报告R25增补契约

不另建一份只覆盖新功能的小报告。以原28章为完整骨架，继续保留96检查、1832要求、299卡、P001—P124、48张R24卡，再加入32张R25卡。各旧状态原样保留，不能因有映射而自动完成。

## 统一Envelope

```json
{
  "sectionId": "TRAINING",
  "status": "PASS|FAIL|INSUFFICIENT|NOT_RUN|UNKNOWN|INCOMPLETE",
  "repoCommit": "实际提交",
  "apkHash": "实际APK或null",
  "snapshotHash": "只读数据快照",
  "scope": "HOST|ANDROID|DEVICE|PROSPECTIVE",
  "ordinalFrom": 0,
  "ordinalThrough": 0,
  "expectedRows": 0,
  "exportedRows": 0,
  "omittedRows": 0,
  "evidenceRefs": [],
  "errors": [],
  "repairCards": [],
  "nextTrigger": "具体所需事件或证据"
}
```

示例中的0为格式占位，不代表当前实际为0；实际未知字段用null/UNKNOWN并说明。status字段实际必须是单个枚举值，不能把上方竖线字符串原样写入报告。

## 机器可判定的红线

有MISSING却全完整通过；仅历史数据却PROSPECTIVE_PASS；未测设备却DEVICE_PASS；空家族返回公共模型却FULL；补写赛后结果标赛前；alpha预算超支仍授证；同一期多REAL；新policy继承旧命中；全局连挂被版本切换清零；报告截断不标数量；0动作仍称达到频率；缺正文称全仓审计。这些都应使最终结论FAIL，而不是警告后继续发布。
