# 研究来源和适用边界

访问核对日期2026-10-26。技术依据只采用官方平台文档；A/B既有算法原始论文链接仍保留在各自sources研究附录，不把旧论文成绩写成本项目结果。

- S1 Android前台服务时限：https://developer.android.com/develop/background-work/services/fgs/timeout 。适用target、系统版本和服务类型需一起核对；不能把其他target限制当当前设备已发生故障。
- S2 Android长时WorkManager：https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running 。Android16下长时worker可能耗尽Job配额，因此本方案不把周期/长时Job当逐分钟持续引擎的自动保证。
- S3 Android Thermal API：https://developer.android.com/games/optimize/adpf/thermal 。温控遥测用于降低并发、分块和恢复管理；不支持忽略系统热限制的“无限满载”承诺。无API设备记录UNKNOWN，不把不插电映射为热故障。
- S4 SQLite WAL：https://www.sqlite.org/wal.html 。读写并发不等于多个同时写者；短事务、checkpoint和长读监控分别设计。
- S5 Android Doze：https://developer.android.com/training/monitoring-device-state/doze-standby 。删除软件的充电/闲时条件不会自动撤销系统调度与网络限制。

本方案的公平服务份额、60秒服务窗口、并发1、200ms量子与20ms检查目标是工程设计起点，不是上述官方文档给出的通用性能保证。全部需要真实设备测量。引用平台边界用于实现可靠持续运行，不作为保留旧“仅充电训练”模式的理由。
