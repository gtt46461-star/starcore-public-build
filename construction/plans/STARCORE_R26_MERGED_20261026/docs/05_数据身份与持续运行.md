# 数据、身份、事务与持续运行合同

## 1. 数据表与约束

参考DDL在`schema/r26_runtime.sql`。这些是研究元数据表，不取代正式开奖、决策或结算表。正式结算Owner在原事务内写feedback_outbox；host参考用单独SQLite只验证协议，Android必须使用原协调器。

| 表 | 主键/唯一约束 | 关键字段 | 不变量 |
|---|---|---|---|
| r26_session | session_id | user_enabled、boot_id、state、heartbeat、实际进度 | 心跳与进度分开；强停不自动冒充RUNNING |
| r26_feedback | event_id，issue_ordinal唯一 | source_hash、payload、ready_at | 同ID内容冲突拒绝；原事件幂等 |
| r26_policy | policy_hash | canonical_spec、birth_ordinal、mode | 不可变；旧证书不自动跟随 |
| r26_checkpoint | checkpoint_hash | policy、parent、trained_through、完整state_json | 全部状态自洽；训练截止不逆行 |
| r26_active | policy_hash | checkpoint_hash、version | CAS更新；一个已提交活动快照 |
| r26_consumption | event_id+policy_hash | checkpoint_hash | 重试不重复有效消费 |
| r26_task | task_id | lane、mechanism、snapshot_hash、cursor、fence、lease、owner | 快照固定，过期fence不得提交 |
| r26_progress | receipt_id | task、fence、cursor前后、cpu、blocked_reason | 只有提交过的实际进度才能算活性 |

生产还须并入原反馈来源键、schema版本、错误链、artifact manifest和期号→ordinal映射。DDL迁移在工作线程分块，旧DB不能要求清数据才能启动。`INTEGER issue_ordinal`是经TargetIssueResolver映射的序号，不对YYYYMMDDxxxx直接+1。

## 2. 事件与发布顺序

1. 开奖结果通过原合法性/冲突验证，SettlementEngine只结算已有赛前冻结。
2. 同一事务插入唯一feedback事件；提交后wake。入队通知可重复或丢失，持久扫描补齐。
3. 先完成下一目标的截止前冻结；训练读取已提交模型私有副本，训练样本只能是已揭晓数据。
4. 计算新状态；权重、optimizer、RNG、normalizer、calibrator、teacher、recurrent、feature字典和游标全部属于同一checkpoint。
5. 生产文件先写内容寻址临时工件、校验、fsync并原子完成；数据库短事务验证expectedParent/fence/事件来源，再提交checkpoint、消费表与active CAS。
6. 数据库提交后才发布内存指针。重启以提交表恢复，不用临时文件时间猜活动模型。

host示例将完整state JSON直接存SQLite以测试原子性，不模拟已完成Android文件持久化；文件/SQLite双资源崩溃注入仍是Android验收项。取消未提交步骤可重算，重复计算不增加完成样本或进化代数。

## 3. 统一身份协议

PolicySpec必填：graph、features、updater、update_schedule、initial_state、rng、gate、router、calibration、missing_policy、resource_schedule、evidence_protocol、runtime_abi。resource_schedule也冻结，避免根据未来结果任意改变更新轨迹却沿用证据。

编码使用有类型JSON树作为协议传输：null/bool/int/f64/str/seq/map显式标签；整数十进制字符串，f64为IEEE754大端8字节十六进制；map键按UTF-8字节序排列；拒绝孤立代理、NaN和Inf；区分整数1/浮点1.0/布尔true，区分正负零。列表有序；无序集合先按该集合明确规范排序，不擅自交换模型成员语义。Policy对象只保存canonical不可变字节和hash，不保留用户可修改map引用。

域名分别`STARCORE_POLICY_R26_V1`与`STARCORE_CHECKPOINT_R26_V1`。A与B的R25域不混用，旧checkpoint或证书只读展示。迁移输出legacyId/newPolicyId/precisionRecoverable/evidenceScope；丢失精度必须标不可恢复，不能创造原参数。`evidence/identity_golden_vectors.json`供Java/Python逐字比对；本轮Python可验证，Java生产编码器接线必须另测，不能凭向量存在就称跨语言通过。

## 4. 持续调度与容量

runtime_policy.json是唯一配置默认值：requires_charging=false、requires_device_idle=false、requires_screen_off=false、localTrainingUnmetered=false。注册表中全部24家族、16专家启用；没有“完整功能仅充电开启”的另一套配置。启动后有就绪任务即持续推进；长期无任务必须说明输入尚缺/所有任务已完成，不用循环空跑伪造计算量。

参考调度核使用P0绝对截止优先，P1/P2/P3按固定服务槽轮转，P2内所有机制任务公平轮转；没有充电与idle输入。实际Android需要持久队列、条件唤醒、内层20ms取消检查和租约。公平指可运行且系统给予资源时的服务公平；P0持续过载会触发研究饥饿/容量失败，不能宣称无条件时限保证。每个让出有原因、开始/结束、游标和下一触发。

默认200ms工作量子是起点而非允许不可中断200ms的借口。按20ms目标分块，关键区到来能尽快让出。严重热态或内存分配失败保存状态并自动恢复；电量数值、充电状态、用户操作界面不直接禁用能力。每个任务的stateBytes、临时峰值、CPU时间、队列延迟和恢复误差都进报告。

## 5. 重要失败路径

重复event同hash返回已有结果；同ID不同hash拒绝。旧parent CAS拒绝；旧fence即使工作者复活也拒绝；lease已过期拒绝。新campaign不能复用旧snapshot分数。输入未来标签拒绝，迟到冻结不算自然前瞻。缺历史不伪造padding为真实数据。原始5000上限不靠任务快照偷偷突破；任务依赖将淘汰时按TTL完成或明确过期取消，不能不断pin住全部历史。

人工停止、系统限制与温控恢复都需要新运行收据；不追补过期REAL。资格失效回退只能用当前仍合格的已提交旧冠军。历史回放成功不修改自然赛前记录。
