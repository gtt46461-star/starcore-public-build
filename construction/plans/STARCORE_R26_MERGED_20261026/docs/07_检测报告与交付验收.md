# 40章完整报告、UI、CI与设备验收

章节机器合同以`registries/report_contract_40.json`为准，原36章逐项保留，新4章加入双方案覆盖、持续运行、防饥饿、无损身份。B的可行性、谱系、非劣方向与历史缺陷字段融入相关章，不能只在附录写“已合并”。每章必须存在，状态可为PASS/FAIL/PARTIAL/NOT_RUN/INSUFFICIENT/NOT_APPLICABLE/ERROR；ERROR带完整原因链，NOT_APPLICABLE必须给业务理由。

## 运行面板必须真实

显示所有功能启用、每家族最后训练事件与耗时、每专家最后结构提案、队列最老任务、关键区抢占、恢复时延、待消费标签、checkpoint/父checkpoint、进化七计数。充电/idle作为设备遥测列，不能作为功能开启列。仅更新心跳、空循环或重复保存同状态不增加有效训练数。真实排行榜与研究影子榜分开，显示窗口、分母、区间、状态及是否自然前瞻。

100面/1200动作/Rank1—3/七层漏斗来自本期冻结payload；晚生成的可视化标延后解码，不能晚推理后填成赛前。倒计时按目标截止和时钟误差展示，截止后进入等待/抓取状态，不一直卡0；50—55秒抓取仍要基于真实发布规律，不能承诺抓到未发布结果。

## 必测矩阵

| 用例 | 核心断言 | 最低证据 |

| P0连续压力 | P0先执行，关键区结束P2恢复；持续过载不能PASS | 抢占/恢复P95、饥饿告警、缺口分母 |
| 24家族+16专家+导出 | 每机制有真实服务；内存不越界；导出不锁死结算 | PSS/heap/native/队列延迟/全部机制收据 |

| 断网/重复开奖/迟到/时间回拨 | 无重复REAL/结算，无法冻结如实缺期 | 唯一键、单调时钟、输入可见性与完整日历 |

| 模糊/对抗/负控 | 错shape/NaN/Inf/未来标签/任意代码拒绝 | 种子、输入hash、最小反例与错误码 |

保留T29—T34设备格，扩API35/36及用户机型；真机、模拟器、HOST分别标级别。强制停止后不能宣称后台仍运行，恢复后不回填旧期REAL。测试SLO按设备版本分组，至少1000次工程机会后评估稳定尾部；60分钟场景是功能压力验收起点，不能据此保证长期SLA。

## CI顺序

固定源码与依赖→manifest/权限审查→有意义的单元/合同/反例→SQLite/文件恢复集成→Android构建→升级安装和启动→设备连续矩阵→工件校验→受控交付。新增方案HOST检查命令是`python3 code/run_checks.py`，只输出实际执行状态。Android工作流要从JUnit、instrumentation和设备日志生成回执，不从静态文字拼PASS。

交付包至少含源码commit/tree、diff及before/after hash、依赖锁/SBOM、APK hash、签名指纹、包名/versionCode、迁移日志、测试命令和原日志、40章报告、未完成项和已验回滚路径。公开库无API key/签名私钥；构建环境变量存在不等于实际API连通测试已通过。

工程、24家族/16专家能力、35/37/40质量、用户设备交付分开签署。仅写方案、创建目录、编译HOST或跑合成用例，不能把生产状态改为已完成。
