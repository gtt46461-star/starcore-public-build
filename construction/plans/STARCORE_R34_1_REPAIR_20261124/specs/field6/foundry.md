# 从原子、矩阵和思路族生成持续可执行的策略

## 生产入口与分类

B06 沿现有服务调度进入 R26 的 FoundryCampaignR26 和 R27 的 RuntimeR27.EvolutionTask → EvolutionLoopR27.stepBirth → stepGate。IdeaFamilyR27.propose、专家、已验证的遗留父本及结构提案均沿已有出生所有者提交。B07 接训练、冻结和结算，B08 接研究消费及下一代。共用 typed action 与原有写者。B06 的隔离用例当批即可用合法输入验收，后批在同一接口增加各自原件。保留既有 policyHash、证书和谱系键，另外存带版本的结构描述与分类。旧记录缺少可重放的基因组或行为原件就标为历史未知，重新取得新证据时再评。

| 分类 | 计算依据 | 记账方法 |
|---|---|---|
| 数值训练、参数迭代 | 同一可执行机理的权重、学习率、衰减、窗口数值、阈值、温度、随机种子或目标位置取值改变。新数据也可能引起完全不同的 K3。 | 可保留为性能更好的版本。增加训练或迭代数，继承同一机制根。 |
| 从零创造 | 正常生成器从已登记的原语、组合规则及已验证的组件产生可执行公式。没有策略父本。导入已知种子、恢复旧公式分别标来源。 | 在同输入、同位置角色、同规则审计范围内对照全档案，排除等价或近重复，首次回放或训练落库后记新根。 |
| 结构变异 | 从已存在父策略中增加、删减、替换、改接真正执行的节点、来源关系、状态更新或决策路由。 | 保存父和子原字节、节点路径与前后边、触发的研究原件。固定其余参数，撤销该编辑后，至少有预注册探针的成对输出差异。 |
| 交叉和融合 | 交叉记录替换的片段和供体。融合记录多个不同来源的实际有效父组件、路由和读出。只改变同一组合的权重沿原组合迭代。 | 在共同目标上查两亲、联合、逐亲消融、最强单亲及固定等权。零权重、不可达分支、同一机制克隆不能补足有效父代数。 |
| 进化和质量 | 一个完整代次要能追出提出、训练/回放、同预算比较、留存或淘汰、下一轮真实调度。子代的结构或行为新颖只表示候选进入研究。 | 分列已运行代、开发中有改善的代、独立未来证实改善的代。全负的一代也可完成选择并继续探索，不能为其登记性能提升。 |

结构身份从实际解码后的 PolicySpecR27.executable、ModelGenomeSU2 成员的执行图、已发布派生原子/分子展开得到。数字若实际选择不同程序实现（例如 family 叶调度），沿注册表读出选中实现和真实连边。仅有不同数字不足以认定。对图节点按输入角色、可见时间、是否有状态、数据类型、更新规则、输出口及有向依赖标识。区分“同一槽换位置”与“加入另一来源并形成新跨位边”。编号、日志、常数、隐层权重、窗口、随机种子从结构比较键剔除，完整数值仍保存在可重放身份。安全消去等价包装时核查原生产执行器的缺失值、浮点和状态顺序。已知别名（例如 repeat 与本位的一阶 cross）的行为需在同域复核。冻结 TRAIN 探针上并列比较完整概率、固定读出的 K3、真实选择器的 ACT/HOLD、有效输入掩码。空掩码或全无共同支持留待补证。真实运行的 BirthGateR27 还执行当时的 maxDepth（上限 6）、40 节点、12 常数、耗时、状态大小及输出限制。PolicyContractR30 先执行的 64/8 属于前置合同。

## 七条可立即实施的路线

下表是开放组合语法的起点。输入按期 t 的可见水位冻结，所有总结选码的输出仍为一个位置 K=3。既有 24 个模型族、21 个思路族、16 个专家及 20 个矩阵的对象责任继续以[逐对象合同](../RESEARCH_OBJECT_CONTRACTS.json)为准。审核专家、只读图表和随机负对照各保留原职责。

| 路线 | 从哪里生成可执行公式 | 如何反证贡献 |
|---|---|---|
| 跨位置滞后 | 用 CROSS_POSITION_FLOW 的有支持源位→目标位滞后边，交给 I04。一个可执行起点为 `(zscore (cross 2 1))`，再让 I09 加入第二种有证据的输入。 | 在相同期历去掉跨位边、只用本位、交换对照源。列出逐号码和覆盖差。 |
| 多位置证据交集 | I14 由本位短窗的三号码与两邻位长窗的三号码求交集。例为 `(set_intersection 8 32)`。I20 再让事前重复状态决定是否启用。 | 分别跑 A、B、交集、条件交集。交集不足三个则弃权，断档另记。保留所有机会作分母。 |
| 状态转移及条件路由 | I03 的条件转移输出与 I06 的历史状态门结合，分别学习状态内分布。对照候选 `(if (regime 32) (c 0.1) (trans1) (crosscond 2))`。 | 固定一支、去掉门、打乱开发状态对应关系并保留时间顺序，各自回放。改变门值只记参数迭代。改变可达分支和状态连接另行取证。 |
| 历史片段检索 | I07 以过去已知片段检索后继分布。例如 `(zscore (knn 3 10))`。F20 的检索机制留在原工厂。可以从检索和单步转移的误差差异产生新组合。 | 原始匹配对照无检索、同预算置换匹配、单步转移。断期不跨段，近邻后继须在预测前已知。 |
| 原子、分子与符号公式 | AtomWorldR27 和 DerivedAtomR27 从不同谱系取有支持的子树，测移除贡献。把有增量的子树配成带类型的分子。I09 可将其用于新上下文。 | 展开分子回算其 AST。移除一个原子、只用任一原子、同预算无引导搜索。缓存里的分子只有在真实出生公式消费后才有创造贡献。 |
| 学习表征及残差修正 | F03–F07 通过 StructuralProposalR26.neuralChildren 改变实际超边、膨胀连接、注意力掩码或状态连接。I08 只读已发布、同 ABI 的概率面。STUDENT_ERROR / RESIDUAL_MECHANISM 有足量同目标残差后，I10 可提出替换失败组件的公式。 | 比较同初始化、同数据、同预算的原图、重连图、去残差和无教师模型。记录梯度、完整检查点及后续赛前消费。只更新同一网权重是训练。 |
| 互补专家和融合 | 以 ALGORITHM_COMPLEMENTARITY、两亲同机会误差和反事实矩阵提名候选，按 FusionOpsR27 与 FusionStudyR30R1 实际执行加权、条件路由或秩投票。 | 固定父本与训练域，重放父一、父二、组合、等权和逐亲摘除，区分双亲可执行、有效、开发净增益、独立增益。两父同错时可落负结果。 |

## 持续创造新公式与新生成规则

1. 每次有合法的新输入或结算反馈，按真实预算在现有工厂分配三个来源的工作，分别是没有策略父本的新根搜索、失败驱动的父本编辑、互补机制组合。以就绪最久的未覆盖机制获得的实际切片核对公平性。选中的热门家族不能吃光可用的全部探索机会。队列项记录来源、未试组合、输入 pin、优先级原因、成本与可恢复游标。没有输入或被实时截止抢占时记阻塞及唤醒条件。
2. 生成器在有类型和因果约束的槽位中组合“输入来源/原子或分子、数值或状态算子、信息连边、门控或读出、可学习部分”。从未试的组合及有效失败假设中提案。每次生产只保留有界的活跃前沿、签名索引、研究片和活跃权重，归档淘汰轨迹。长期累计编号可继续增长。数据修订、重启和多工人竞争用已有事务、输入身份、owner/fence 与唯一出生键收敛。保护活证书、训练、未决确认和谱系引用。赛前线程读取上次可用发布，离线研究在分片内让行。
3. 对**新思路族**另给证据。发现多个已实训策略中反复有贡献的组合后，对照两棵以上的实际执行树，保留相同的有类型骨架，把不同且有干预证据的位置抽成类型槽。将这条可执行生成规则、来源子树、适用/反证条件、版本和提议时的模板目录快照存入已登记的研究产物。在原 IdeaFamilyR27 / ResearchContext 的提案消费者解码，沿既有工厂执行。若当前 ABI 不能解释某个新原语，保存可复现的待实现提案，由注册的新编译器版本处理。
4. 从发现时未用的开发段/独立种子分支验证规则。冻结原模板、研究输入和计算预算，用新规则在不同上下文生成至少两棵去参数后仍不同的树。两条必须实际出生并训练/重放，证明结构差及未与既有模板/谱系重复。同预算关掉该规则看实际提案、接纳和输出如何改变。对验收输入只固定刺激与算子预算，测试程序不得预填子代源码/期号→答案。重启后从同一规则版本继续一次，记录首个实际消费者。两份权重、一个模板换窗口、只换族名均只记相应较低层级。自然独立有效性仍逐资产评。
在 B08 的 MutationOpsR27.mutate / DirectedResearchPolicyR30R1.materialize 接入一种可定向复演的结构编辑。从已定位的失败组件、可用原子及配对开发贡献提取 P 和 D，保留 P 的实际节点，按类型加入 D 的秩支路，返回正常提案并经过原出生门。D、目标位置、输入 pin 和父本由生产记录提供。B12 用该真实算子获取一个可复算证例，工程输入分别提供 TRAIN 探针与有已知互补状态的 SELECT 片段，让 FusionStudyR30R1.pair 和 comparison 走原门。

5. 对**失败结果**继续调度。来源缺失只挂起受影响对象，补齐后重开。充分比较后冗余或负贡献的策略释放活跃名额，冻结淘汰原因及引用。相同输入、相同干预不重复计费。下一轮用失败指向的节点引入另一类原子、路由或父本，并用等预算随机结构搜索作对照。记录每个机制的实际派发/完成数、配对改善及成本。同一代或同一期可以为零。重启不得重新获得多重试验额度。

R27 的 family 叶现有白名单为 8、11、12、20、21。其他 F 家族走自己的生产实现或原模型发布桥。set_intersection 使用专属根读出，不能任意嵌入通用打分树。固定规则如严格交集以支持重建、回放和冻结消费验收。只有可学习组件要求参数/优化器更新。新增诊断字段跟随既有 schema 所有者作兼容迁移，关键写入和旧证书身份保持可追溯。

## B08 新思路规则的可执行验收格式

R341-B08-04-A01 先按旧合同核验 Android 用例、沙箱和真实对象消费。另在本批已提交的运行器源文件中放一行 `// STARCORE_RULE_PROBE R341-B08-04-A01 {JSON}`。JSON 固定 discovery_pin、transfer_pin、discovery_through、transfer_through、target_position、seed、budget_units 和 preexisting_rule_shapes。两个 pin 指向事前冻结、时间不重叠的开发数据片。输入包、日历和两段实际可见边界随原回执核查。本批可关闭并重建研究 owner 以验收规则恢复，跨进程的后台服务在 B12 重验。

运行原件的 rule6_index_artifact 指向索引。索引与事件共同带 scope=ENGINEERING_ONLY、case_id、source_commit、r30Sandbox 和 database_instance。索引包含 catalog_before、两条 discovery、publication、至少两条 transfer、restore 和 disabled_control。引用一律为相对索引的 path、sha256，并在批次回执中登记原文件。每个事件有 kind、pin、role=DEVELOPMENT、source_table、durable_key、committed_at，保留可从隔离数据库读回的业务记录。

- RULE_REGISTRY 给出当时已登记和归档规则的机制摘要、实际查询。EVALUATED_FORMULA 引用生产 canonical 字节、policy_hash、出生时间、观察期范围与 REPLAY_OR_TRAIN 评价原件。评价带身份、支持数、输出引用。
- PUBLISH_RULE 给出两条发现资产的身份、归纳的 pattern、rule_id 和去数字的 structure_hash。宿主从两条执行 AST 推导其相同结构和类型槽，保留真实共同运算节点。通配整棵树无效。同结构窗口变化不能造出槽，已有模板只换数值不能再次计新族。
- transfer 的程序携带 rule_id、publication_sha256、投入预算、种子、执行 owner。在未参加发现的开发段取两个结构相异的实际产物，与发现样例逐一去重。从同一规则生成并各自首评。RESTORE_RULE 绑定同一发布原件及开闭前后的不同 owner。RULE_DISABLED_DISPATCH 使用同一预算、种子、完整迁移段和已提供的调度机会，列实际投递的规则。
- 控制实验采用受支持的符号节点，完整索引、字段和正反样例见 [规则复算](../../tools/rule_induction6.py) 和 [可运行示例](../../tools/test_rule_induction6.py)。设备仍须从生产原子/分子和矩阵读取有支持的输入，核对原始数值及已执行的消融。离线样例验证验收器，不产生生产族、证书或真实交易。
