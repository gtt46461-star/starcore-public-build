# 构建、迁移与批次接续

## 构建身份和手机安装

122 底座的 `tools/r33/run_release_build.py` 在 Gradle 启动前后调用 `binding.identity`，并在回执 `planManifestSha256` 记录旧方案身份。它实际调用 `:app:assembleRelease`、`:app:assembleDebug`、`:app:assembleDebugAndroidTest`。B01 保留上述语义，另记录 R34.1 新封印、提交、批次和 APK 内嵌身份。构建签名验证使用已有公开指纹。Android 测试结果须有实际运行日志和逐项断言，本次 Gradle 任务列表只提供编译依据。

构建前从指定方案提交导入四条资料路径。旧的 `prepare_worktree.py` 使用按行拆解的 Git 路径，Git 默认设置可以把中文入口按转义形式输出，导致已暂存的合法导入被误判。再次运行又只检查应用祖先，可能沿用旧方案。当前工具用零字节分隔路径，并在已有工作树校对仓库、分支及目标资料树。出现 `PLAN_IMPORT_REQUIRED` 时先保留本地修改，在清洁施工分支运行 `--create` 只暂存资料；`PLAN_ALREADY_STAGED_VERIFY_AND_COMMIT` 表示可核对并提交上次的导入。保留先前应用提交。旧封印回执归档，按本次增量逐项重验。

## B02、B03 的当批签收

B02 对实时请求从入队到提交确认使用同一截止；注入锁前阻塞、SQL 已提交而通知延迟、容量暂不可用，核对每个请求的业务结果。B02 可以用受控容量输入独立运行这组测试，B10 接入真实目录/租约后重跑同一组断言。

B03 用已提交的迁移单元、只读连接和当前 session 的注册/claim 收据签收结构与任务接通。对 B06/B07 才生成的数据，B03 注入最小合法输入或证明可恢复的缺项，保留错误与样本角色。后批需要追加的结构由该批在同一迁移 owner 追加版本，不回写已签收的旧 schema hash。每批在前一批基础上独立编译、可重启，可用旧数据覆盖升级。

## B12 发布回读

对实际下载地址的空目录回读记录请求时间、HTTP 结果、长度和摘要。签名、包名、版本、内嵌提交和方案封印五项一致后记录对应层的交付结果。源码 bundle 在空 Git 库中验证应用祖先与构建提交可达。一个地址临时失败可单独重传并重验该对象；保留前次失败和其他已核验产物。工程阶段用可控发布端制造截短、错误内容、旧产物等反例，真机覆盖安装继续由 B12 的 DEVICE 回执签收。
