# 07 检测报告：必须回答三个问题

用户要求检测报告必须说清楚：**①软件为什么胜率低；②各项功能为什么不够强大；③到底怎么升级修改优化。** 10.29 报告有 44 章、96 项检查，但 39 章是 PARTIAL（"导出了原始记录，效果需另行验证"），没有一章按功能给出"效果 + 原因 + 下一步"。R28 新增三章并修两处空章。所有结论由数据自动选择模板，**不允许手写结论，空数据只显示 INSUFFICIENT**。

## 7.1 新章 R28-01「胜率为什么低」（R28-050）

固定结构，每一项都给出数值与来源表：

| 小节 | 内容 | 数据源 |
|---|---|---|
| A 基准 | 随机基线 30%、保本线 30.3%、30% 时每注期望 −1% | 常量 + `AppConfig` 赔率 |
| B 实盘 | 主链严格样本外、观察池、对照池：期数、命中、Wilson 区间、相对保本线的差 | RSEC-034、`r27_live_frozen` |
| C 运气上限 | 当前观察池规模 k、平均期数 N 下的 E_max(k,N)；榜首与之对比 | 模拟表（启动时用固定种子计算并缓存） |
| D 进化真实性 | 七计数、已验证提升、冠军/I00/打乱对照三线、"冠军不换"的原因 | `r27_generation` |
| E 还需要多少期 | 按当前效应估计，单个策略与观察池整体需要的 FUTURE 期数（docs/01 1.5 公式） | e 过程 `expectedRemaining` |
| F 数据检验 | 各位置均匀性、上期→本期依赖置换检验、可复制性（与 `tools/r28_independence_audit.py` 同算法，每 1000 期重算） | 回放数据集 |
| G 结论（三选一） | ①"已发现：策略 X 在 FUTURE 上通过 e 过程，HR=…，下界=…>30.3%"；②"未发现：N 期、k 个策略，无一显著高于保本线；最可能原因：数据无可利用规律（证据 B/D/F）"；③"样本不足：还需约 M 期" | 由 B/D/E 自动选择 |

## 7.3 新章 R28-03「施工与验收核对」（R28-052）

- 读取 `assets/r28/r28_acceptance_metrics.json`（构建时打包，与 `registries/` 同内容），对 43 项指标逐项给出：目标、当前值、PASS / FAIL / INSUFFICIENT、数据来源；
- 读取 `assets/r28/r28_cards.json`，每张卡显示：代码是否已合入（构建身份）、绑定指标是否 PASS；
