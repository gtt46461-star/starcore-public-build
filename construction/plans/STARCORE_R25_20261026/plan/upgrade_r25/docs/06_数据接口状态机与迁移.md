# 数据接口 状态机与迁移

这些接口是Android接入合同。schema/r25_reference.sql是可执行的HOST模型，不能直接替代现有Schema生成器或DatabaseCoordinator。正式开奖、REAL和结算使用旧表；r25表仅保存新元数据。

## 事务边界

结算事务只进行原有结果确认、唯一结算和引用Outbox写入；重复事件依据正式事件身份幂等。数据库中持久化同一eventId与policyHash唯一消费记录，模型处理器在内存私有副本中计算，事务时比较活跃checkpoint版本。CAS失败丢弃本次候选，重新读最新状态；不得再次使用旧梯度写新状态。

断点包括phase、candidateIndex、sampleIndex、optimizerStep、RNGstate、snapshotHash、ruleHash和数据消费截止。每次让出必须保存全部数值状态，而不只是代数。断点只有完整commit后才推进可见游标；进程丢失时从上一个commit重算未提交片段，统计不得把重算计为重复训练完成。

任务租约的owner与fence必须同时比较。claim递增fence；续期只允许当前owner、fence且尚未过期。过期旧线程复活不能续写、不能发布模型、不能释放新持有者租约。基于单调时钟的运行租约不能跨重启直接复用；重启进入新bootId并重新领取。参考SQL用可控整数模拟时钟，生产实现需要bootId列。

## 11张参考表

| 表 | 主键与用途 | 迁移及验收 |
|---|---|---|
| r25_policy | policy_hash；规则及出生 | immutable触发器；重复hash不同出生拒绝 |
| r25_checkpoint | checkpoint_hash；父链与状态序号 | policy及sequence唯一；artifact optimizer RNG分别有hash |
| r25_active | 每policy一行当前指针 | expectedVersion CAS；读者只读完整状态 |
| r25_consumption | event_id加policy_hash | 重放一次生效；同事件不同sourceHash报冲突 |
| r25_task | task_id | snapshot不可悄悄换；fence递增；cursor只前进 |
| r25_cohort | cohort_id | 出生后起点；固定终点或序贯模式先登记 |
| r25_look | cohort加digest | 固定终点一次开封；序贯分配可求和但不代表已实现检验 |
| r25_experiment | experiment_id | seed失败成本完整记录；不得只保留冠军 |
| r25_publication | manifest_hash | 文件落盘后PREPARED再COMMITTED；恢复检查引用 |
| r25_capability_receipt | 能力层级加artifact | 没有证据不能向下一层晋级 |
| r25_report_section | report加section | expected等于exported加omitted；ERROR给错误码 |

各生产表额外加入schemaVersion、createdAt、updatedAt及必要索引，但不得手工改DB userVersion常量掩盖迁移。通过当前ResearchSchemaCoordinator注册单语句迁移和回执；ready必须比较所需表、列、索引、触发器和SQL身份。测试从10月25日旧schema快照开始，模拟每个DDL后中断、恢复、重复执行、空间不足与Owner竞争。不执行DROP重建，不把清数据作为验收。

## 政策身份编码

参考Python采用有序JSON，Java采用带长度前缀UTF8，两者明确具有不同encodingId，不可跨语言直接比较hash。生产只能选择一种规范编码并新增跨语言golden fixtures；涉及迁移时显式登记旧新identity映射，映射不继承新的质量证据。这样避免字符串拼接歧义、字典顺序、Unicode或浮点格式悄悄改身份。

PolicySpec中的initial_state要有初始化checkpoint清单，checkpoint不是只有权重，也包括优化器累积量、归一化、状态缓存、特征字典、路由、校准器和RNG。资源导致的跳步与批次时间也纳入固定更新日程；如果让出顺序会改变浮点结果，规定容差、次序和平台标识，而不是声称所有设备bit一致。

## 模型发布伪代码

```text
训练线程取不可变父checkpoint及policy
在budget内计算私有候选 并记录消费事件
保存候选文件 计算hash fsync 校验解码
写PREPARED manifest
现有Owner事务内:
  检查parent policy expectedVersion knownThrough及取消标识
  写新checkpoint consumption及COMMITTED发布意图
事务提交后:
  原子切换内存快照
  将发布标为ACTIVE 并保留可回退父快照
启动恢复:
  PREPARED没有commit时保持旧快照
  COMMITTED时验证文件及hash后恢复内存
  文件坏则阻断该策略并记录恢复错误 不伪造新文件
```

原子指针不能替代跨文件与数据库的恢复协议。参考Python只验证数据库一侧的事务和CAS，不声称已验证fsync或Android文件系统故障。

## 施工时源码定位

32卡JSON的resolved_targets给出实际索引路径；标INDEX_PATH_NOT_FULL_BODY_REVIEW只表示路径有证据，不表示正文已审。LOGICAL_TARGET_TO_LOCATE必须在B01定位并写入账本。精确行号来自source_anchors_r25.json并附SHA；源码hash不匹配时按方法语义重审，不自动套用旧行号。
