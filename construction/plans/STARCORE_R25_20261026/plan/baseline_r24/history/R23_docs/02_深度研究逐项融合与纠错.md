# 深度研究的用处、已落实部分与必须纠正的内容

## 结论

用户贴出的研究有用的部分是：时序表征、位置关系建模、结构搜索、参数/状态继承、自监督、闭环反馈与独立验证。它不能原样成为STARCORE施工规格：证券交易数据、GDP、成交量、夏普和仓位优化不是本项目给定任务；60%—70%也不是已有证据。只引用这些技术名词，不能宣称“完美融合实现”。

## 文献不能被误读为本项目的成功证据

TCN论文比较的是其选定序列任务，不证明TCN在所有数据上优于LSTM，也不证明一定预测出本任务下一期优势。[M1] 图注意力已有公开研究，“GNN暂无公开论文”不是正确的通用说法。[M2]

注意力是否能作为解释有明确争论。R23不把一张attention热图当成原因证据；要求输入遮挡、结构干预、梯度/置换等对照，并报告对预测和质量的影响。[M3a,M3b]

PPO属于on-policy方法。把历史数据包在一个仿真环境里，不自动消除离线数据偏差；也不应把普通监督预测包装成RL。真正离线RL需要处理训练分布外动作等问题，CQL是相关研究例子，而非本项目必选模块。[M4a,M4b]

程序宏学习可参考DreamCoder：学习可复用结构和搜索提案，而不只是随机生成公式。[M5] 选择性预测可参考risk-coverage方法，但覆盖与正确率仍由实际任务数据决定，不能宣称加一个15%门就会自动高命中。[M6]

## 融合验收不是文档勾选

对每项深度研究能力要求：数学定义→实际源码→调用入口→权重变化→断点恢复→冻结输出→结算反馈→消融收益→真机资源→新期质量。失败或缺项必须保留状态；“设计已融合”“主机代码已实现”“Android已接线”“真机有效”“质量通过”五个标签不能混用。
