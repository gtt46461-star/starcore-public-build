## 对照173源码的原因

DatabaseCoordinator.dedicatedDdlTaskR31Q 在主连接创建 r31q_ddl_cache_flush(x INTEGER)；StartupCheckpointIdentityR31.identity 只允许3张r335临时表，故同一应用自己的第四张表触发 R31_STARTUP_CHECKPOINT_TEMP_SCHEMA。WAL连接池中准备读连接与提交写连接可有不同TEMP目录，因此既有prepare直接失败，也有prepare VERIFIED后requireWithin失败。该链已用实际SQLite目录+原谓词复现；未声称已在用户真机运行修复。

- [app/src/main/java/com/ethk3/novaonepro/DatabaseCoordinator.java](https://github.com/gtt46461-star/starcore-public-build/blob/4d1de9d83692635b5c5ce39144fece1c8a31c8ac/app/src/main/java/com/ethk3/novaonepro/DatabaseCoordinator.java)；锚点 `CREATE TEMP TABLE IF NOT EXISTS r31q_ddl_cache_flush`；SHA256 `7e9c41a4b14c972e7b0af257fe960829942e2e958475311e71e6d81ed9d5f05a`。
- [app/src/main/java/com/ethk3/novaonepro/strategyv2/StartupCheckpointIdentityR31.java](https://github.com/gtt46461-star/starcore-public-build/blob/4d1de9d83692635b5c5ce39144fece1c8a31c8ac/app/src/main/java/com/ethk3/novaonepro/strategyv2/StartupCheckpointIdentityR31.java)；锚点 `sqlite_temp_master`；SHA256 `3d8331e9053bc4c622bd8613a84b6bc4d4044178b30e79cb15b9a8d5a2cf6d68`。
- [app/src/main/java/com/ethk3/novaonepro/SchemaDomainCoordinatorR926.java](https://github.com/gtt46461-star/starcore-public-build/blob/4d1de9d83692635b5c5ce39144fece1c8a31c8ac/app/src/main/java/com/ethk3/novaonepro/SchemaDomainCoordinatorR926.java)；锚点 `CREATE TEMP TABLE IF NOT EXISTS r335_extension_catalog`；SHA256 `5243a33ec11803fef6168bf584c067cd38c2143be0e6da4cbc6b8de8a8b0fc3d`。

## 处理步骤与修改边界

- 应用runtime.patch：新增StartupTempSchemaR343精确允许4张自有表的type/name/tbl_name/sql契约；只允许本源码实际产生的定义，禁止任意TEMP白名单通配。
- StartupCheckpointIdentityR31中的主数据表、sqlite_master、schema_version、table_info均显式main限定，避免临时同名遮蔽；保留原CAS逐字节等价、source generation/schema/column guard、事务receipt、热原件保留语义。DDL触发器体内不添加SQLite禁止的qualified DML。
- 源码变更重新构建后overlay原数据升级，重跑checkpoint→retention→session register→OWNER_READY；不能只清空journal或将BUG改READY。

具体代码以本批 `PATCHSET.json` 所列补丁和 `patches/<组>/after/` 完整文件为准。适用前态按SHA核对；已有正确生产实现按本卡调用链恢复并取证，不为增加修改量而重写。无精确补丁对应的观察不足项，按本批操作合同补取原件；不能捏造一个未经证实的根因。

## 验收断言

- 宿主SQLite重现原谓词失败；新helper接受实际4张自有表且拒绝x TEXT/影子checkpoint/trigger。
- Android真实WAL连接池：准备读和提交写均可完成；非空CAS、热原件缺冷源、source generation变化、未知TEMP shadow反例均保持原拒绝/等待语义。
- 当前新source journal产生OWNER_READY及后续真实task numeric receipt，连续两次进程重启不再出现本TEMP错误。

## 不得破坏

- 不要删除所有TEMP保护。
- 不要忽略异常或把CAS比较改为state_hash比较。
- 不能把服务BUSINESS_READY当研究OWNER_READY。
