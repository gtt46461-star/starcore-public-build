## 取件并展开可施工版本

在本仓库当前修订上执行，使用 Python 3.11 或更高版本。下面示例在临时工作目录接收大文件，最终方案写入该工作目录下的 prepared 子目录。如已有下载好的 33.5.zip，可直接将它的路径交给最后一条命令。

```bash
REVIEW="$(git rev-parse --show-toplevel)/construction/plans/STARCORE_R33_5_REVIEW_20261119"
WORK="$(mktemp -d)"
curl --fail --location --retry 3 -o "$WORK/33.5.zip" \
  https://github.com/gtt46461-star/starcore-public-build/releases/download/r33.5-plan/33.5.zip
python3 -B "$REVIEW/prepare.py" "$WORK/33.5.zip" "$WORK/prepared"
```

完成后打开 `$WORK/prepared/START_HERE.md`。基础方案在 `STARCORE_R33_5_20261118/`，本次修订在并列的 `current-review/`。施工机使用这两目录，原卷内标为 PART2_PENDING 的记录属于第一卷当时的审查。运行工具时将 PLAN 指向基础方案，具体命令中 REVIEW 的目录层级按各页说明取值。

手机 ZIP 里是两个展开的文件夹。实测 6214 个文件，第二卷原件正确。相对认证分卷，第一卷缺 62 个文件且有 17 个旧版。prepare.py 校验外包 SHA、每个旧件/新件和两棵完整目录树，补齐到 6276 件，再装入这次重跑的 53 套宿主收据。先前 7/75 的分片记录只记录另一条历史上传路线。[逐件差量](packaging/release-comparison.json)
