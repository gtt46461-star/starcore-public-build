# 02 施工规则：顺序、文件所有权、门禁、状态

## 1. 顺序

- 批次严格按 B00 → B01 → … → B10 施工；B11 只在 B11-01 判定 REQUIRED 时施工。
- 批次内卡片严格按编号顺序：前一卡提交且本卡门禁通过，才开下一卡。**不并行施工任何两张卡。**
- 跨文件、跨线程的并发问题全部集中在 B01（规则见 docs/B01 第2节 L1–L7）；之后批次发现新并发问题，回到 B01 规则新开 B01-xx 子卡，不在别的卡里顺手改。

## 2. 文件所有权（机器检查）

- 每张卡的“独占文件”见 `registries/cards.json` 与各批次文档；`registries/file_ownership.json` 是 `ownership_check.py` 的输入。
- 同一批次一个文件只属于一张卡。唯一例外记在 `file_ownership.json.batch_shared_sequential`（当前只有 B03 的 ReplayEvaluatorR27：B03-01 改回放样本生成，B03-06 改评价入口，按序施工、方法不重叠）。
- 对所有卡开放的路径：`construction/r30/`、`evidence/r30/`、`construction/plans/STARCORE_R30_FINAL_20261031/`（方案只读副本）、`release/release_manifest.json`、`release/release_identity.properties`、生成身份文件（rebind_identity.py 产物）。
- 需要改未登记文件：停止，先在 STATUS.md 记录原因，新开子卡（编号 Bxx-yy-z）登记文件后再改。

## 3. 每卡固定流程

```
1  git switch construction/r30-20261031 && git pull --ff-only
2  按卡“施工步骤”逐条做；代码从本包 code/ 原样复制（ADD），或按补丁/替换代码修改（MODIFY）
3  ./gradlew --no-daemon :app:compileDebugJavaWithJavac
4  ./gradlew --no-daemon :app:testDebugUnitTest            # 含本包 code/test 下 R30 测试
5  git commit -m "<卡号> <一句话>"
6  python3 tools/r30/ownership_check.py --card <卡号> --base <上一卡提交>
7  推送 → r30.yml 自动跑 tools/r30/ci_build.sh（R29 原有全部检查 + R30 追加门禁）
8  STATUS.md 把本卡改为 DONE（附提交、CI 链接）或 BLOCKED（附原因）
```

## 4. 批次门禁

| 层 | 内容 | 何时 |
|---|---|---|
| G1 编译与单测 | compileDebugJavaWithJavac、testDebugUnitTest、lint（新增问题=0） | 每卡 |
| G2 R29 原有检查 | tools/r29/ci_build.sh 中全部（身份、DDL、SU1/R26/plan1025、qual_host、host_checks） | 每卡（CI） |
| G3 R30 追加 | SQL 合同 T01–T06、所有权检查、写点扫描 | 每卡（CI） |
| G4 模拟器冒烟 | 安装、冷启动、服务 60 秒心跳、无崩溃；批次相关 androidTest | 每批最后一卡 |
| G5 覆盖安装 | 在 CP06 数据与 CP16 数据上各做一次覆盖安装（两证书各自对应） | 每批出包 |
| G6 真机 | 批次出口里写明“真机”的指标 | B01（24h）、B02（24h）、B10（全部） |

**时间门槛只在对应环境判定**：例如“首次服务 ≤60s”“schema 安装 ≤180s”是 CP06 已有的模拟器门槛，继续沿用；但 M03/M04/M05/M07 等时延指标**只以真机 r30_issue_timeline / r30_writer_hold 为准**，CI 模拟器的时延只记录不判定（registries/metrics_r30.json 的 environment 列）。这是 R29 B01 在 CI 模拟器时延上反复失败的教训。

## 5. 状态字

| 状态 | 含义 |
|---|---|
| TODO | 未开始 |
| DOING | 施工中（同时只能有一张卡） |
| DONE | 本卡全部验收项满足，有提交与 CI 链接 |
| NOT_RUN | 需要的设备/环境测试未执行（不得写 PASS） |
| BLOCKED | 无法继续，写明原因与需要的决定 |
| QUALITY_NOT_MET | 自然质量指标已测但未达目标（不改口径） |
| NOT_REQUIRED | 仅 B11：开工条件不满足 |

## 6. 回滚

- 代码：每批出包前打标签 `r30-bXX-<versionCode>`；回滚=安装上一标签同证书 APK（versionCode 更低需先卸载——**会丢数据，禁止**；因此回滚一律通过“新 versionCode + 旧代码”重新出包）。
- 数据：R30 全部新增表均为加法（CREATE TABLE IF NOT EXISTS），不 DROP、不改旧列；B00-03 回收 R29 时 RP 文件改名保留，不删除。
