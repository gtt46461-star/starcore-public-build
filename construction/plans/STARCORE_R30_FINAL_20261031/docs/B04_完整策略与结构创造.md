# B04 完整策略与结构创造

## 1. 定义

“完整策略”= 现有 `PolicySpecR27` 的全部五段（输入/模型/读出/选择器/更新器）+ 来源 Meta，且通过 `PolicyContractR30.violations()` 为空。R30 不另立第二种策略格式；R29 方案中的 PolicyContractR29 由 PolicyContractR30 取代（直接复用真实 PolicyAstR27 的类型检查与范围/因果检查，本包测试已证明它会拒绝 `add(PROB, RISK)` 这样的类型混合）。

## 2. 去重

语法不同、行为相同 = 同一策略。行为指纹 `BehaviorSignatureR30` 取 256 个 H_TRAIN 探针期上的（是否出手、位置、K3 集合），不出手的期不看位置与号码。

## 3. 新增类（已写好，直接复制）

- `code/main/.../StructureWindowR30.java`：窗口计数与 top3，纯函数，只读 [target-w, target)。
- `code/main/.../SetIntersectionPolicyR30.java`：思路族 I14，实现 bb607cf 真实接口 `IdeaFamilyR27`（id/nameZh/coreIdea/generate/mutate），程序为 `mix(α, freq(p,w1), freqnb(p,w2))`。
- `code/test/.../R30B04StructureTest.java`：500 次出生与 200 次变异全部通过 `PolicyContractR30`；修改目标期本身不影响窗口计数（PIT）。本包已在 bb607cf 源码上实测 4/4 通过。

族注册：bb607cf 的族列表在 `EvolutionLoopR27.java` 第 46–49 行（`new IdeaI01…` 到 `new IdeaI13SelectorOnlyR27()`）。为避免两张卡改同一处，I14–I20 七个新族统一由 **B04-06** 一次追加到该列表之后，B04-04 只交付类与测试。

## 4. 资格不豁免

任何族（包括 I14 现行交叉方法）产生的策略都走同一条：出生合同 → 观察 → 序贯资格（全局 α 预算，`SequentialQualificationR27`）→ 证书门（34%/250/ECE0.04/26%/连败6 不变）→ 主链。R30 不为任何族开绿灯。
