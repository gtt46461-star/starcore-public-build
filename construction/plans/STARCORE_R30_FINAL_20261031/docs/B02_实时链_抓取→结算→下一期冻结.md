# B02 实时链：抓取→结算→下一期冻结

## 1. 测量先行

R29 报告里“请求到提交 P95=46.5s”只有一个总数，无法知道时间花在哪一段。B02-01 先把每期 8 个时间点落进 `r30_issue_timeline`（与业务写同一事务、先写者赢、单调钟+开机标识），之后 B02-02…05 每一项改动都必须用该表证明“哪一段变快了”。

## 2. 时间线配对 SQL（ReportR29 第3章使用）

开奖期 i 的结算 → 目标期 i+1 的冻结。目标期号由 `TargetIssueResolver` 给出，这里用 r36 已有的请求表把两者连起来：

```sql
-- 最近1440期：开奖期的观测/结算点 + 下一目标期的请求/准备/冻结/截止
SELECT d.issue AS draw_issue, t.issue AS target_issue,
       d.boot_first_observed, d.mono_first_observed, d.mono_settled, d.boot_settled,
       t.boot_next_requested, t.mono_next_requested, t.mono_next_prepared, t.mono_next_frozen, t.boot_next_frozen,
       t.wall_next_frozen, t.wall_next_deadline
FROM r30_issue_timeline d
JOIN r30_issue_timeline t ON t.issue = (SELECT min(issue) FROM r30_issue_timeline x WHERE x.issue > d.issue AND x.wall_next_requested IS NOT NULL)
WHERE d.wall_first_observed IS NOT NULL
ORDER BY d.issue DESC LIMIT 1440;
```
期号是同长度数字字符串（例如 202610310593），字符串比较即时间顺序；跨日期号同样满足。组装 `IssueTimelineR30.Row` 时，SETTLED 用 d 行、NEXT_* 用 t 行，然后 `summarize`。
