## 2. 校准不能靠“填满概率箱”验收

原R29提案写“10个等宽概率箱至少5箱各20个样本”，这给预测值的跨度加了不必要限制。例如200条预测均为0.34、实际68次命中，样本ECE为0，但只有一个非空箱，原条件一定拒绝。它是计量反例，不是软件真实胜率，也不是未来高质量证明。

ECE按全部样本加权：`sum_b (n_b/N) × abs(mean_probability_b − observed_rate_b)`。空箱权重为0；不要为了填箱人为把0.34改成0.8。项目现有 `StatsR27.ece` 已使用这一加权方式，需修正的是方案的支持门及新增报告字段。[Guo等原始论文](https://proceedings.mlr.press/v70/guo17a/guo17a.pdf)给出该定义；下面的支持规则是本项目的工程提案，不是论文证明的通用阈值。

R29_GATE_V2首版合同：

- 固定10等宽箱、边界在验证前冻结；验证ACT≥200，空数据为INSUFFICIENT。
- 每箱≥20条视为“有基本样本支持”；这些箱覆盖的验证样本比例须≥90%。少样本箱仍参与ECE，不能删掉高误差尾部。
- 样本ECE≤0.04；并列箱计数、平均预测、实际频率、区间、时间块敏感性、支持区间与unsupportedMass。仅在验证支持范围内使用校准结论。
- 不要求概率值横跨5个箱。新预测落到未验证区域应标OUT_OF_SUPPORT，不外推成“已经可靠”。
- 拟合只用TRAIN/SELECT中的时序预测；校准器冻结后注册未来确认，确认数据不得反用于当版校准拟合。改变校准器须新策略版本或事前固定且已验证的更新规则。

样本ECE达标只是完整质量门的一部分，仍需真实优势、命中、稳定性、PIT、覆盖、资源与主链验证。样本有限时区间可能很宽；本修订不把“低样本ECE”升级为未来误差保证。修改落点：R29-034、036、039，默认值与Q05同步。

## 3. 缺期开奖与乱序到达：修复两个具体漏洞条件

`LiveShadowsR27.settle` 的查询只选 `hit=-1`。某期结果未到且落后超过2期时，代码将其改成 `hit=-2`；在此方法里该行以后不再进入补结算查询。另一个条件是缺失早期结果时继续处理后期结果；`SequentialQualificationR27.State.observe` 以 `ordinal<=lastOrdinal` 直接忽略，从而后补早期结果可能被结算表记账，却未计入资格状态。当前方法虽然有ORDER BY，但不能保证前面缺失的开奖结果在下一批补回时仍保持整体顺序。

这两个条件由当前源代码和对应SQL/控制流反例支持；不据此声称用户手机已实际发生了指定次数。`tools/verify_revision.py`复现的是SQL筛选与控制流，未运行Android或Java应用。源码定位：

|现有位置|问题条件|施工动作|
|---|---|---|
|LiveShadowsR27.settle|缺失draw超过两期写hit=-2|改为PENDING_DRAW+retryAt；补抓成功后仍可结算原合法冻结|
|同方法循环|前一期缺结果，后一期先更新e状态|结果可以分别入账；资格提交通过独立连续消费器，不能越过未解决的早期ACT|
|SequentialQualificationR27.State.observe|以最大ordinal代替去重与完整性|receipt唯一键去重；lastContiguousOrdinal表示连续已处理期，而非最大已见期|
|StoreR27.writeEprocess/ResearchWriteQueueR27|状态和回执跨批次可见性|receipt、e状态、游标同一事务提交；明细分块须有complete manifest|

新增 `QualificationInboxR29`，以 `(experiment_id,target_ordinal)` 为幂等键。结果摘要相同的重复事件无操作；摘要冲突先隔离，不能INSERT OR REPLACE覆盖事实。无合法冻结为工程缺口，不补造预测；已有合法冻结、只是开奖晚到则正常补结算。

处理顺序：

```text
resultArrived(experiment, issue, draw):
  verify original predraw freeze and result identity
  persist unique result receipt or conflict marker
  enqueue qualification pending row

consumeContiguous(experiment):
  while next registered opportunity is resolvable:
    transaction:
      verify next issue and matching frozen identity
      if an ACT result is still missing: stop, keep pending
      apply the pre-registered scoring rule exactly once
      persist consumption receipt + e-process state + next cursor
```

无ACT机会可按事前规则以零增量推进，但不得把“ACT但缺开奖结果”临时改成无ACT。长期无法恢复的ACT缺失：保持缺口并停止授证，或执行实验登记时就确定的保守计分/证据段关闭规则；不可根据输赢决定删期。为了公平调度，待补抓与可结算队列分开分页，不让最早缺失行长期占满LIMIT。旧库已hit=-2的记录通过原freeze+draw哈希恢复，旧证书受影响时先撤销并重建，不悄悄修改历史胜率。

测试：1、3先到，2后到，应与1、2、3顺序消费得到同样状态；每步杀进程、重复重投、摘要冲突均不得漏计或双计。补回结果可修复统计，但绝不能提高原来的赛前冻结覆盖率。落点R29-010、035、036、039。

## 4. 初次准入不以已经REAL为前提

|阶段|频率分子|分母|状态用途|
|---|---|---|---|
|未来确认|合法赛前ACT决策期数|注册后的全部应有期|FUTURE_ACT_RATE；研究目标≥15%，质量支持时更高|
|主链部署后|正式REAL决策期数|部署起点后的全部应有期|Q02真实频率；漏期和系统故障仍在分母|
|尚未部署|无REAL观测范围|不存在部署窗口|Q02=NOT_DEPLOYED，不能当首张证书的前置门|

同时分列ACT决策数、已结算ACT、待结算ACT；HR只能用已结算ACT作分母。不得用未来确认ACT冒充REAL，也不能给新候选设置“先有15% REAL才能授证”的闭环死锁。单个符合质量条件的策略允许先应用；若部署后频率不足，产品频率目标仍标未达，继续寻找互补窗口，禁止凑配额。

## 5. 继续施工的顺序和交付边界

先B00锁定身份与指标，再B01—B02把分库、调度、抓取、冻结、结算恢复做实；B03—B06保留并升级历史训练、完整策略、神经接线与校准；B07贯通确认→证书→唯一主链；B08—B10完成可诊断报告、设备稳定性和自然质量验证。各批依赖不变，允许相邻批一起施工，但每次交付须有对应源码和可安装公有版APK。

本次运行的检查是方案引用/哈希/SQL、报告复算及明确标注的构造反例；它们不等于手机性能验收或已找到高胜率策略。无需等待未来2000期才能出工程诊断：已有历史和每个任务的输入/输出/错误立即可报告；未来质量不足按条件列出缺口，不能留一张空白诊断书。
