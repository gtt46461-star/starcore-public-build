# 检测报告必须自动指出问题、证据与具体修复


## 1. 报告与计算共享同一个指标实现

新增ReportR29、MetricEvaluatorR29、DiagnosisRulesR29；保留R26/R27原始章节作兼容源，界面与HTML/JSON都读统一结果，不能三个出口各算一套。导出snapshot必须绑定source/APK/schema/featureABI、两个库的eventWatermark、时区、设备会话、采样时段、所有指标定义版本。跨库watermark不一致应标CONSISTENCY_PENDING，不能拼成同一瞬间快照。

每个MetricResult包含：metricId、definition、unit、population、numerator、denominator、value、timeRange、sampleCount、sourceSnapshot、evidenceRefs、uncertainty、status、missingReason、nextTrigger、repairCardIds。空数据=null/INSUFFICIENT；从未运行=NEVER_RUN；运行失败=ERROR；本项不适用=N/A且给理由。不得以0填缺失，或用相邻链的表填当前链。

## 2. 固定12章

|章|必须回答|具体证据|
|---|---|---|
|01身份/施工|安装的到底是哪份代码；哪些卡已验证|source、APK、签名指纹、卡→测试→运行报告|
|02时钟/抓取|开奖何时可见、何时抓到、哪期缺失|scheduledIssue、firstSeen、source hash、网络错误|
|03冻结/结算|影子每期是否齐；是否重复或补造|完整机会表左连接冻结结算，缺期列表|
|04主链与胜率|REAL、SHADOW、OBSERVE、REPLAY各自表现|各自分母、ACT率、HR、区间、对照、费用|
|05任务与资源|谁没运行、谁阻塞、为何变慢|ready与progress差异、依赖图、P50/95/99、CPU、heap|
|06策略生成|究竟生成了什么、是不是结构创新|AST/模型合同、语义与行为去重、拒绝原因|
|07训练与深度学习|每期是否训练、新网络有没有供消费者使用|事件游标、uniqueIssues、optimizer状态、模型消费回执|
|08进化/变异/融合|父子到底改变哪里，独立结果是否更好|diff、配对delta、置信范围、族覆盖、七计数|

|10诊断与升级建议|为什么差、还有哪些解释、下一步怎么改|结构化Finding、证据强度、反证、施工卡、预期可测变化|
|11长期稳定与存储|后台、重启、热控、5000热数据和总空间|设备场景、积压、回收账、失败恢复|
|12验收差距|工程/设备/质量各缺什么|逐项PASS/FAIL/INSUFFICIENT/NOT_RUN，不能总括为通过|

## 3. 诊断规则必须具体且可证伪

|触发证据|可输出结论|对应改动/验证|
|---|---|---|
|r27_calibration=0且只有OBSERVE|校准输入对象缺失/状态筛选导致无任务产出|LiveShadows.calibrate扩确认对象；R29-034；构造合法冻结后模型应产生|
|I08只有family leaf且无AtomNet模型消费收据|新网络未直接参与该族决策|FeatureCache model_surface；R29-029；消费hash一致+消融|
|draws>2000但诊断章空|诊断入口口径或任务依赖不匹配|UpgradeDiagnosis输入适配；R29-041；先生成历史研究部分，未来不足单列|
|ACT HR低于全期HR，支持不足|当前选时可能无效，尚不能定因果|I13选择器配对消融；R29-022/037|
|shadow=0但观察有数据|确认入口/留出条件/队列需诊断，不能仅“继续等”|列每个资格条件和最近失败事件；R29-035|
|跨族行为高度相似|名称多但有效多样性不足|行为聚类与结构替换；R29-025|
|父子差置信范围跨0|尚未证实改善|保留冠军、继续新样本；不得强行代代换冠军|
|ready积压且无进度+长锁等|工程饥饿，预测质量暂不可判定|独立writer与事务审计；R29-005/006|
|控制组排名很高|搜索选择偏差风险|等预算空信号对照与新确认；不能结论“数据永无规律”|

每条结论标OBSERVED（直接实测）、SUPPORTED_CAUSE（故障注入/消融支持）、HYPOTHESIS（待验证推断）、UNKNOWN。自动诊断可以提出可检验修改，不可能自动保证找到真正根因或必然提高胜率；没有证据时输出缺什么数据、去哪里补。

## 4. 完整但不膨胀

导出job状态QUEUED/RUNNING/CANCELLING/CANCELLED/COMPLETE/FAILED；每个分页/压缩块检查取消；取消延迟目标≤2秒。默认摘要+全部能力/指标清单+必要证据索引，不复制多个巨型数据库快照。每个大表记录expected/exported/omitted；分页覆盖需可重建。完整证据按需导出，保留manifest/CRC/SHA与不可变定位。Zip写临时路径，完成验证后rename发布；取消和失败清理本job临时文件，不能删别的成功报告。

默认压缩报告目标≤20MiB；若完整证据超过上限则输出有分卷manifest的独立完整附件，不截断JSON、不裁掉失败行。只保留最近2个默认导出与用户pin文件，磁盘统计包含数据库/WAL/artifact/report/tmp，5000期不等于总磁盘有界。报告中保留1832要求的状态汇总和可定位索引，不每次复制所有历史正文。

## 5. R29.1新增诊断字段

每个确认实验必须导出pendingDrawIssues、pendingQualificationIssues、lastContiguousOrdinal、lateResultsRecovered、duplicateReceipts、conflictingDrawHashes。报告中区分结果迟到但预测合法与预测本身迟到。添加校准分箱支持和unsupportedMass；禁止因只有1—4个非空概率箱就断言失准。Q02主链部署前显示NOT_DEPLOYED，并展示FUTURE_ACT_RATE作为研究频率；两个分母和时间起点分别落库。对应卡R29-010/034/035/036/037/039。
