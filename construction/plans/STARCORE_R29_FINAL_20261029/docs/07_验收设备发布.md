# 设备验收、测试设计与每批交付


## 1. 基本规则

不采用先写“完成”再补证据。每张卡状态为PLANNED→IMPLEMENTED→HOST_VERIFIED→DEVICE_VERIFIED；涉及自然质量另有FUTURE_QUALIFIED。报告导出、代码合入、编译成功均不能推导DEVICE_VERIFIED。没有手机测量就在账本写NOT_RUN。

每批提交准确改动文件、before/after hash、变更理由、测试命令和原始日志；生成可安装APK并提升versionCode，保持公有版包名 `com.starcore.research.r13` 和既有公有版签名指纹，允许覆盖公有版；不覆盖私有版 `com.ethk3.novaonepro`。签名密钥不进入公有仓库。安装失败、签名不一致或开机崩溃时，本批不能签收。

## 2. 测试套件

|测试|输入/故障|必须观察到|
|---|---|---|
|PIT反证|替换当前/未来开奖标签及firstSeen，保留过去|既有事前特征/ACT/K3/hash不变；变化必须报泄漏|
|零信号全管线|独立均匀排列、相同搜索预算/选择/停止策略|错误准入率的二项区间，不能只做1次“没过线”就宣称安全|
|正对照检出|预登记弱信号和结构切换，K3优势34/37/40%，15/30/100%频率|检出概率与所需自然期数曲线，不把合成结果说成真实胜率|
|父子修复|同一期父/子/参数微调/随机同预算|结构变更、配对delta、区间可重算|
|复现|相同dataset/seed/artifact，重启于任一切片|预测、优化器、随机游标和一次性消费一致|
|分库迁移|复制一半/切换前后杀进程；ack丢失|无丢事件、无重复正式结算/资格累加，旧库可回退|
|冻结竞态|迟到准备、时钟跳动、结果先到、重复提交|迟到拒绝；绝不能以开奖后当前时钟回写predraw|
|报告|全空/部分表/64行以上/大报告/取消/重建|状态准确、分页完整、取消≤2秒、校验可重现|
|门槛可行性|既有连挂门与R29提议门均跑同分布|列功效/误放风险，参数变更有独立版本和变更记录|
|性能|候选/模型/观察同时满载、导出同时运行|端到端P95、写锁等待和积压均满足目标，无OOM|

真实数据回放用于比较与筛选；已反复研究过的4824期及仓库1万期不可再叫全新最终测试集。最终质量仍依赖注册后的未来数据。

## 3. 目标机矩阵

先在用户报告所示Android 14 / V2353A测前台与息屏；再覆盖项目实际minSdk和一个当前target附近版本。目标场景：干净安装、保留数据库覆盖升级、正常前台60分钟、息屏后台≥6小时、连续运行≥72小时、断网20分钟恢复、跨日/时区变更、进程被回收恢复、低存储、热压力、报告导出并发。强制停止期间不宣称服务可以继续；恢复时显示覆盖缺口并补结算。

72小时是工程稳定性窗口，不代表足够统计样本。每期抓取、冻结、结算、训练游标、后台heartbeat全部留证；平均耗时不足以替代P95/P99。测试在受支持网络/设备条件下记录，源未发布与本机故障分别统计。发现P0错误立即阻止当批发布。

## 4. 发布与回滚

发布包由APK、来源提交、source tree hash、依赖/构建identity、签名证书指纹、plan hash、测试清单、真实设备报告、数据库迁移版本组成。模型通过完整写入+校验+原子指针切换，撤销证书和切回稳定artifact的目标≤5秒；整APK/数据库回滚不能承诺5秒。迁移允许版本检查和可恢复路径，不能要求用户清数据解决启动失败。

仓库已有 `.github/workflows/r13.yml` 与 `tools/r27/run_host_tests.sh`；施工应在实际源分支检查脚本参数后复用，新增R29验证并接入既有流水线，不能另建与Android工程无关的Python model.py项目。根README指向当前方案与真实施工分支，避免用户从旧main构建。
