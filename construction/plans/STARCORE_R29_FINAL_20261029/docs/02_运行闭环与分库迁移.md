# 实时链、研究链与可恢复分库


## 1. 每期责任与时序

`source available → first observed → validated draw → draw committed → settlement committed → training event → candidate prepared → predraw frozen → next result`。
每个节点记录issue、eventId、来源哈希、wall time、monotonic elapsed、session、成功/错误码。开奖首次可见时间未知时标UNKNOWN，不能把首次收到当源端发布时间。用户要求“倒计时50秒时拿到开奖”分解为源延迟和本机延迟；源端尚未发布时不伪造开奖。

健康网络期抓取目标1秒一次，单flight、请求超时与抖动退避；不得多个Service各自轮询。校验期号/十数排列/来源一致，冲突隔离。目标机首次有效收到到draw+正式结算P95≤1000ms；分析请求到结果持久化P95≤5000ms，同时有效赛前结果必须在下一截止前≥5秒提交。超时为MISSING/LATE，不能补成当期FUTURE。允许SKIP真实出手，但必须有当期SHADOW或明确阻断记录。

## 2. 三个域，两套写者

|域|存放|责任|
|---|---|---|
|realtime|draw、opportunity、正式freeze/decision、settlement、outbox、cert projection|单写者短事务；禁止训练、长查询、导出压缩进入事务|
|research|R27研究表、模型元数据、实验/训练/观察/资格账|独立SQLite文件、独立单写者；读快照，批量提交|
|artifact|不可变模型/checkpoint/压缩历史回放块|先写临时文件、校验、原子发布后提交引用；有pin与回收账|

仅拆SQLite而继续共享DatabaseCoordinator串行队列不会消除阻塞。修改 `ResearchWriteQueueR27`、`ResearchPoolR27.Worker`、`StoreR27` 与所有跨库读消费者；生成表所有权注册表，禁止研究写入实时连接。WAL仍只有一个写者，跨ATTACH库不是一笔原子事务。默认实时权威记录采用满足持久要求的同步设置；研究可重算缓存与不可丢检验预算/冻结证据分级，不能把整个研究库都视为可丢缓存。

## 3. Outbox/inbox协议（新增ResearchEventBridgeR29）

1. 实时事务写draw、幂等结算及outbox(event_id,issue,kind,payload_hash)，成功后返回UI；唯一键防重复。
2. 研究读取已提交outbox，研究事务 `INSERT OR IGNORE inbox(event_id)`；仅首次消费执行状态增量、训练任务和cursor更新。
3. 研究提交成功才回传ack。ack丢失重投也不会重复训练/计分。原子变更包括模型引用、学习游标、已消费事件；大量评分明细可分块，但只有complete manifest可见。
4. 证书在研究库完成不可变审计，发布cert projection到实时库；DecisionGate只读projection并核验版本、hash、有效期、撤销epoch与当期冻结。
5. 不允许持有realtime写锁等待research写锁。故障注入覆盖两库每次commit前后、ack丢失、重复事件与磁盘满。

## 4. 迁移状态机

`PREPARED → COPYING → VERIFIED → CATCHING_UP → CUTOVER → OBSERVING → ARCHIVED`。原库备份和迁移manifest先落盘；复制期间旧Owner仍唯一写入且记录增量watermark；分块复制按主键校验行数及规范化行哈希；追平后短暂停旧研究写者，记录watermark、切换路由，开启新写者。至少一次冷启动/杀进程/升级恢复及完整回归后才封存旧表。旧表清理必须由引用计数、回滚窗口和空间预算共同决定，不在首次启动执行DROP/VACUUM。

R28“复制完直接DROP”的方案由此取代。保全的旧策略/模型若无法恢复，记录具体缺失算子、参数、数据范围、消费者；禁止把全部旧资产都转成几个数值参数或只读文案。

## 5. 调度与内存

Realtime协调器负责fetch/settle/freeze；ResearchPool唯一安排各家族、专家、AtomNet、回放、校准和诊断。旧任务经adapter注册，可重复调度入口停止，但算法类保留。截止优先队列给freeze/settle高优先级；训练切片目标10—50ms且可中断，禁止单个预训练调用占用数秒后才检查取消。线程数先设2个计算worker并由真机基准调整至1—4，不能用核数强制满载。

每任务有ready条件、last_started/last_committed、work_cursor、pending_count、oldest_pending_issue、blocking_dependency、retry_at。区分“执行但无有效样本”“等新开奖”“有样本未调度”；有积压时连续5期无提交即诊断告警。积压不能通过清队列处理。共享增量特征缓存按(dataset hash, trainedThrough, feature ABI, position)索引，模型切换只读不可变版本。图表读分页物化视图，主线程不拼长文、不全表扫描。
