# 03 统一单系统：删繁就简

## 3.1 为什么必须删

报告事实（docs/00 0.4）：同一进程里 R908、R9xx/CP12/R932、R26、R27 四代研究代码同时调度，79 个线程，603 张表写在同一个数据库文件里。R908/R9xx/R26 在报告里**没有任何一个已验证产出**，但：

- 占写锁：实时链 `F01_WRITE_FAILED`、抓取 `BUSY_DEADLINE`、写等待>200ms 每小时 14,932 次；
- 占 CPU：16 个 R26 线程与出号线程同优先级（R27.4 才把续算降级，专家/铸造线程仍在）；
- 占存储：主库 1.72GB、旧备份 742MB；
- 占维护：每一版施工都要给旧链"补接线"，所以 1832 条需求永远闭不了环。

前几版方案的做法是"新系统并行观察一段时间再退役"，结果是旧系统一直没退役。R28 改为：**先导出种子和档案，再立即停用调度；旧表只读保留到归档完成。**

## 3.2 R28 目标结构（只有四块）

```
┌──────────────────────── 实时链（realtime.db = 现主库瘦身后）────────────────────────┐
│ AutoFetchService → TargetIssueResolver → AnalysisSingleFlightR36 → V51RuntimeOrchestrator │
│ → DecisionGateEngine（唯一 REAL 入口，规则不变） → SettlementEngine（唯一结算入口）        │
│ 线程：fetch / analysis / settlement / ui-read，前台优先级；只有它们写 realtime.db         │
└───────────────┬───────────────────────────────────────────────▲────────────────────┘
                │ 开奖行、结算行（只读复制到 research.db）          │ 冻结的 K3 意图（仅 ACTIVE 证书）
┌───────────────▼──────────────── 研究引擎（research.db，新文件）──┴────────────────────┐
│ RuntimeR27：回放数据集、特征缓存、14 思路族、进化、负对照、观察池、影子池、           │
│ AtomNet、原子/分子/矩阵、校准、消融、e 过程、证书门                                   │
│ 线程：ResearchPoolR27（cores−2 个，后台优先级）+ 1 个研究写线程                        │
└───────────────┬─────────────────────────────────────────────────────────────────────┘
                │ 只读
┌───────────────▼───────────────┐   ┌──────────────────────────────┐
│ 报告与图表（ReportR27/ChartCacheR27，读两个库）│   │ 健康监控（HealthMonitorR28，1 个线程）│
```

主链衔接只有一个点：`MainlineBridgeSU2.chooseIfDue` 读研究库里的 ACTIVE 证书，生成"意图"交给 `DecisionGateEngine`。**DecisionGateEngine、SettlementEngine、V51DecisionGateCore、CertificateBundleServiceR929、AppConfig、DbStore 的门控逻辑不改**（R27 已用 H15 测试核对 SHA256，R28 沿用）。

## 3.5 表与存储瘦身（R28-026）

1. **分库**：R27 的 `r27_*` 表迁到 `starcore_research_r28.db`（docs/04）。
2. **归档库**：退役系统的表（R908、R912 lane、R932、R967、R26 研究、CP12 学习器）在完成种子导出后，用 `VACUUM INTO` 写到 `starcore_archive_r28.db`（只读），主库删除这些表。归档库可在设置页导出、可删除。
3. **旧备份**：`binance_k3_nova_one_pro_v57.db.r926.577271030.bak`（742MB）在新备份通过 `PRAGMA integrity_check` 后删除。
4. **报告目录**：`files/r981_reports/jobs/*/snapshot.db`（每份 1.69GB）导出完成并交付后删除快照，只保留 ZIP；报告目录上限 300MB，超出删最旧。
5. **在线开奖**：保留 ≥5000 期在线（用户要求），研究库保留全部开奖的紧凑矩阵（每期 10 字节，1 万期仅 100KB）。

目标：实时库 ≤1.0GB（M15）、应用总存储 ≤2.0GB（M16）、实时库表数 ≤80（M17）。
