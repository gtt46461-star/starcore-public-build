# 08 升级不清零：数值ABI与证据连续性（R27-B02）

## 8.1 问题

`ResearchSemanticsGeneratedR967.TRAINING_RULE_SHA256`（`TrainingCodeIdentityR964.SHA256` 引用它）随源码变化。只要装新APK：

- `LegacyReplayR26.java:40/99` → `BLOCKED_NUMERICAL_ABI_PRESERVED`，旧学习核永久停止；
- R26 策略 `runtimeStatus=BLOCKED_NUMERICAL_ABI_PRESERVED`；
- `ResearchPruningR965` 合约键含源码树哈希，样本计数从0开始；
- `r967_numeric_training_run` 新运行身份需要"新增120次更新"才可冻结。

本项目改版非常频繁（一天多个版本），所以样本永远攒不起来。

## 8.2 原则

**证据属于"计算结果"，不属于"源码哈希"。** 只要一个策略在同样输入上算出逐位相同的输出（预测与在线更新后的状态），它就是同一个策略，证据继续累计。只有计算真的变了，才算新策略。

## 8.3 语义等价验证（Golden Replay）

新增 `strategyv2/SemanticAbiR27.java`：

1. 固定黄金输入集 `GOLDEN_SET`：从库内抽取的 512 期连续开奖（含至少2个缺口），随 APK 打包为资源 `assets/r27/golden_512.bin`，其哈希写入代码常量；不随版本变化（除非显式升级黄金集，见8.5）。
2. 每个策略（policyHash）都有一个 **语义指纹** `semanticFingerprint = SHA256( 对 GOLDEN_SET 逐期前推的 [100面概率(按IEEE754 bit) ‖ 选择器输出 ‖ 每64期一次的状态哈希] )`。
3. 升级后启动时，对所有"实时影子池 + 有资格记录 + 有证书"的策略，用新代码重算语义指纹（ResearchPool 后台，影子池32个×512期，秒级）：
   - 指纹一致 → `ABI_CONTINUITY=EQUIVALENT`，所有 FUTURE 样本、序贯检验状态、校准模型、证书继续有效；
   - 指纹不一致 → `ABI_CONTINUITY=CHANGED`，旧证据冻结保存（不删除），策略以 `parent=<旧policyHash>, operator='ABI_REBIRTH'` 重新出生：权重继承、回放成绩立刻重算、FUTURE 从0开始。报告列出"因升级导致计算变化的策略清单及差异位置（第一处不一致的期号与字段）"。
4. 数值ABI字段 `numerical_abi` 改为"语义ABI"＝策略所用全部运算符实现的指纹集合（每个运算符/家族有自己的小黄金测试，`OperatorGoldenR27`），而不是整个源码哈希。改动报告导出、界面、调度代码不会再触发任何策略重生。

## 8.5 黄金集本身需要更换时

只在"运算符语义被有意修改"（例如修复一个确实错误的公式）时更换：新黄金集与旧黄金集并存一个版本；受影响运算符列表写入发布说明；受影响策略全部 ABI_REBIRTH，并在报告"版本影响"表中列出。不受影响的策略继续。

## 8.6 验收

| 测试 | 目标 |
|---|---|
| 只改界面文字后重新构建安装 | 影子池全部 `EQUIVALENT`，FUTURE 样本数不减少，序贯检验状态不变 |
| 故意修改一个运算符（如 `freqDecay` 半衰期公式） | 只有使用该运算符的策略 `CHANGED`，报告列出第一处差异期号；其余不变 |
| 升级安装后 10 分钟 | 全部等价检查完成，`BLOCKED_NUMERICAL_ABI_PRESERVED` 计数 = 0 |
| 覆盖安装 + 杀进程 | 等价检查可断点续做，不重复登记重生 |
