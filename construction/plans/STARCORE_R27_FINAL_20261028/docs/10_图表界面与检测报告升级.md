## 10.2 首页/研究页文字

- 顶部常驻一行："当前合格策略：N个；最接近合格：<策略名>，差：<哪一项>"。
- 任何显示命中率的位置都同时显示：样本量、成绩类型（REPLAY/HOLDOUT/FUTURE）、Wilson 区间。样本 < 120 时数字灰显并标"样本不足"。
- 实时研究池排行（现"0/32"）按 FUTURE 的 e 值排序，而不是按命中率排序（少样本命中率排序必然把运气最好的排第一）。

## 10.3 检测报告：新增与补全

报告必须由程序 **自动生成** 以下章节，每章给出状态、分母、来源、证据级；空数据显示 `INSUFFICIENT` 并写缺什么，**不得为 PASS**。

### 新增章 R27-01：胜率真相与差距（报告第一章之后立即出现）

自动填写：
1. 本期全部影子策略的 FUTURE 命中率、样本、Wilson 区间、e 值；按 e 值排序。
2. 同期 I00 随机基线族与打乱标签冠军的 FUTURE 命中率。
3. "运气上限"：按当前活跃策略数 k 与平均样本 N 计算 E_max(N,k)，与排行榜第一名对比。
4. 回放：全部存活策略 H_SELECT 成绩分布（直方图分位数）、H_HOLDOUT 冠军成绩。
5. 结论模板（程序按数据选择其一，不允许手写）：
   - "存在 FUTURE 序贯检验通过的策略：…"；
   - "未发现在 FUTURE 上显著优于随机的策略；排行榜最高者 x% 低于/接近运气上限 y%"；
   - "样本不足：FUTURE 已结算 n 期，需约 m 期才能判断（按当前效应估计）"。
6. 与上一份报告比较：哪些指标变好/变差、变化是否超出噪声。

### 新增章 R27-02：进化真实性

七计数、每代冠军三条线（主/负对照/随机）、停滞诊断（第05章5.8）、思路族存活、出生拒绝原因分布、NO_OP 比例。

### 新增章 R27-03：持续运行与饥饿

研究CPU占比、每任务 wait_kind 分布、卡住与从未运行任务清单、写队列等待、冻结准时率、DEADLINE_MISSED 计数、回放吞吐。

### 新增章 R27-04：升级连续性

本次升级的 EQUIVALENT/CHANGED 清单、首处差异、重生策略数、未完成等价检查数。

### 补全 R26 的19个 NOT_RUN 章

| 章 | R27 采集来源 |
|---|---|
| IDENTITY、BUILD_IDENTITY、SUPPLY_CHAIN | 构建时生成的 `build-identity.json`（commit、tree、APK哈希、依赖清单）打包进 assets，报告读取并与运行时比对 |
| REQUIREMENTS | 读本方案 `registries/r27_cards.json` 与 R26 128卡映射，报告每卡状态（只有设备证据才可"已验证"） |
| DATA、AVAILABILITY | `draws` 行数、排列合法性、重复、缺口（期号连续性）、脏数据、firstSeen 分布 |
| OPPORTUNITY | N_sched、N_frozen、N_act、N_settled、DEADLINE_MISSED |
| FETCH | 抓取延迟 P50/P95/P99、主备切换、`WRITE_REJECTED` 原因分布 |
| ATOMS | 第07章原子回放评分 |
| FAILURES、ABLATION | 冠军失败簇、消融结果（第05章） |
| RANKING、ACTION_SURFACE | Rank1/2/3 命中率（FUTURE）、100面/1200动作一致性检查结果 |
| OWNER | 主链红线测试结果（每期 REAL ≤ 1、无证书不出手） |
| UI | 帧统计、图表加载耗时、取消响应 |

| MERGE | R26→R27 冲突裁决表（本方案 README 第4节）逐条状态 |
