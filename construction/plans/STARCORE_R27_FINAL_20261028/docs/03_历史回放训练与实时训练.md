# 03 历史回放训练与实时训练（R27-B03）

用户要求："必须实时跑数据，同时应该用历史数据直接训练。" 这完全正确，也是 R27 最核心的改动：**新算法出生后几秒内就在几千期历史上完成逐期训练和评估，而不是等实时开奖一期一期攒。**

## 3.1 数据与时间段

库内原始开奖滚动保留 ≤ 5000 期（`historyRetentionLimit=5000`），另有仓库 `research_data/*.csv` 1万期可作为离线导入源（需与库内同期数据逐期比对哈希，一致才导入；不一致的期标 `CONFLICT` 不用）。

把可用历史按时间切成四段（以最新已结算期为 T）：

```
旧 ──────────────────────────────────────────────────────→ 新
| H_TRAIN（最老 ≈60%） | H_SELECT（≈25%） | H_HOLDOUT（最近 ≈15%，≥ 720期） | LIVE（T 之后的实时未来） |
```

| 段 | 用途 | 谁能看 | 什么时候滚动 |
|---|---|---|---|
| H_TRAIN | 参数训练（梯度、计数、拟合） | 所有候选 | 每天收盘（daily-close）整体后移 |
| H_SELECT | 淘汰、排序、选父代、融合权重 | 所有候选；看多少次都可以 | 同上 |
| H_HOLDOUT | 代际比较、晋升到实时影子的唯一门 | **只有每代冠军及其挑战者**，每次查看记账（exposure ledger） | 每 720 期一个新的"封存块"，老块并入 H_SELECT |
| LIVE | 实时影子冻结→结算，资格/证书/REAL 唯一依据 | 冻结后才可见结果 | 实时 |

为什么要分段：第01章 B/C 实测——同一段数据又训练又挑选，训练集上会"一代比一代强"，未来却回到30%。H_HOLDOUT 让系统自己能发现"这一代其实没变强"；LIVE 再兜底。

缺期处理：112个缺口不伪造连续。历史切成若干"连续片段"（segment），跨片段的滞后特征按家族 `missingPolicy` 处理（默认：滞后窗口跨缺口时该期特征标缺失、该期不参与训练，但计入分母为 `SKIPPED_GAP`）。这同时修复 `foundry-su1` 的 `SU1_HISTORY_NOT_CAUSAL_CONSECUTIVE` 异常（00章0.4）。

## 3.2 回放数据集：一次构建，所有候选共用

新增 `strategyv2/ReplayDatasetR27.java`：

- 构建：从 `draws`（dirty=0）读取，按期号排序，生成 `int[T][10]` 排列矩阵＋期号序号＋片段编号＋firstSeen；计算数据集哈希 `datasetHash = SHA256(期号‖排列‖片段)`。
- 存放：内存（5000×10 字节级，≈50KB）＋磁盘缓存 `files/r27/replay/<datasetHash>.bin`。
- 共享特征缓存 `FeatureCacheR27`：240个原子（`GenesisSchemaRegistryR915.atoms()`）中所有 `PREDRAW_HISTORY` 原子按"期×号码×位置"预计算一次，量化为 `float16`；5000期×10位×10号×240原子 ≈ 24M 值，按需只算候选用到的原子组（典型 < 30 个）。
- 增量：每来一期新开奖，只追加一行、更新滚动窗口统计，不重算全部。
- PIT 规则：第 t 期特征只用 ≤ t−1 的开奖；单元测试对每个原子做"把第 t 期改成随机值，t 期特征不变"的泄漏检查（`ReplayLeakageTestR27`）。

## 3.3 回放评估器：逐期前推（prequential / walk-forward）

新增 `strategyv2/ReplayEvaluatorR27.java`：

```
for t in segment.start+lookback .. segment.end:
    x_t   = features(≤ t-1)
    out_t = policy.predict(x_t)          # 10×10 概率面 + 选择器 → 是否出手、位置、K3
    record(out_t, draw_t)                # 命中、Brier、对数损失、出手与否
    policy.update(x_t, draw_t)           # 仅在 H_TRAIN 中更新；H_SELECT/H_HOLDOUT 中按"已登记的在线规则"更新
```

- 在 H_SELECT/H_HOLDOUT 上运行时，策略只能按 **出生时已固定的在线更新规则** 继续学习（和实时完全一样），不能用这些段做额外超参搜索。这样回放成绩与实时成绩同口径。
- 输出 `ReplayScoreR27`：每段的 N_sched、N_act、hits、HR、Wilson区间、Brier、logloss、ECE（10箱）、最长连挂、720期分块最差命中率、与随机基线的配对超额 u 及其下界。
- 性能目标（中端手机，单线程）：线性/计数类候选在5000期上完整前推 ≤ 50ms；神经类（≤ 20k参数）≤ 2s。第01章工具在PC上线性候选 5000期×64个体×30代总计数十秒量级，手机按 5—10 倍估算仍可在数分钟内完成一代。

## 3.4 训练方式

| 家族类型 | 历史训练 | 实时续训 |
|---|---|---|
| 计数/统计类（F09 频率、F21 关系统计、F10 BOCPD 等） | 在 H_TRAIN 上一次累计充分统计量 | 每期开奖后增量更新 |
| 线性/对数几率类（F01、LogisticRidgeSU2） | H_TRAIN 上小批量（batch=64）Adam，L2，学习率余弦衰减，早停看 H_SELECT logloss | 每期1步、学习率=训练末学习率×0.1 |
| 神经类（F03—F07、AtomNet） | 同上，epoch ≤ 20，早停 patience=3 | 同上 |
| 符号程序类（F13/F14） | 结构由进化产生，常数在 H_TRAIN 上拟合 | 常数在线微调 |
| 组合/融合（F22/F24） | 成员权重在 H_TRAIN 上拟合，H_SELECT 验证 | 权重按登记规则缓慢更新 |

每个训练步写训练回执（沿用 `r26_training_step`）：样本序号区间、lossBefore/After、gradientNorm、stateDelta、checkpointHash。

## 3.5 实时与回放如何衔接

1. 候选出生（第04章）→ 立即进入回放队列。
2. 回放：H_TRAIN 训练 → H_SELECT 评估 → 进入淘汰赛（第05章）。
3. 存活者每代冠军 → H_HOLDOUT 配对比较 → 通过者进入 **实时影子池**（`r26_live_model`，上限 32，与报告"实时研究池排行 0/32"一致）。
4. 实时影子池每期：ResearchPool 在上一期结算后立即为每个影子准备预测 → P0 冻结 → 开奖结算 → 在线更新。
5. 实时成绩累积到第08章序贯检验 → 资格 → 证书 → 主链。
6. 实时影子表现持续不佳（序贯检验判"不优于基线"）→ 退出影子池，回到档案（不删除），腾位置给新冠军。

**效果：** 一个新候选从出生到有 5000 期回放成绩只要秒级—分钟级；进入实时后，实时样本按每天 1440 期累积（只要冻结准时）。用户"半天才跑20期"的情况不再出现。

## 3.6 回放与实时的区别必须写清楚（防误读）

- 界面与报告中，REPLAY / HOLDOUT / FUTURE 三种成绩 **分列显示，不得合并成一个"胜率"**。
- REPLAY 成绩高只代表"在看过的数据上拟合得好"。
- H_HOLDOUT 每查看一次就记一次曝光；同一块被查看超过 64 次后，该块降级并入 H_SELECT，等待新块（每720期产生一个）。这是防止"在留出段上反复挑选最终变成训练段"。

## 3.8 验收

| 指标 | 目标 |
|---|---|
| 新候选出生→获得完整 H_SELECT 成绩 | 线性类 P95 ≤ 10s，神经类 P95 ≤ 3min |
| 每小时完成回放评估的候选数 | ≥ 2,000（线性类为主时） |
| 泄漏测试 | 240个原子全部通过"改未来不影响当期特征" |
| 回放与实时同口径测试 | 同一策略在同一段数据上：回放逐期输出与实时冻结输出逐位一致（取最近 200 期已冻结样本对照） |
| 缺期 | `foundry-su1` 无 `SU1_HISTORY_NOT_CAUSAL_CONSECUTIVE`；`SKIPPED_GAP` 计数与缺口数一致 |
