# 05 动态迭代：进化、变异、融合、淘汰（R27-B05 下半）

用户要求：动态迭代进化变异融合，一代比一代强；太垃圾的算法要被淘汰；要能看到在哪里进化、怎么进化。

## 5.1 "一代比一代强"的可检验定义

第01章已证明：训练集上的代际曲线在打乱标签时也会上升。所以 R27 规定：

> **第 g 代冠军"强于"第 g−1 代冠军**，当且仅当：在同一个 H_HOLDOUT 封存块上（两者都未用它挑选过），配对超额 Δ_t = u_t(g) − u_t(g−1) 的单侧95%下界 > 0（u 定义见第01章1.4），且 g 代冠军的 HOLDOUT 命中率显著好于同块上的随机基线族 I00 冠军与"打乱标签进化"冠军。

满足时记一次 `VERIFIED_IMPROVEMENT`，冠军谱系线变为实线；不满足则：

- 新冠军仍可以接替（因为它在 H_SELECT 上更好），但谱系标 `UNVERIFIED`（虚线），并且 **不进入实时影子池**；
- 连续 N 代没有 `VERIFIED_IMPROVEMENT`，报告写"进化停滞：最近N代没有在留出数据上被证实的提升"，并列出最可能原因（见5.8）。

R26 的七计数保留并上图：attempts、uniquePolicies、structuralCandidates、behaviorNovel、researchAccepted、prospectiveQualified、verifiedImprovements。

## 5.2 种群结构：岛屿 + 多样性档案

- **岛屿**：每个思路族一个岛（I01—I13，共13个），岛内独立进化；每 5 代，各岛 H_SELECT 前2名迁移到相邻岛（环形）。防止所有算法收敛成同一个。
- **多样性档案（MAP-Elites）**：行为描述子三维格子
  - 出手率（5档：<5%，5—10%，10—15%，15—25%，>25%）
  - 主要信息源（频率/遗漏/转移/跨位置/状态/检索/神经/组合，8类）
  - 与当前冠军的预测相关度（4档）
  每格只留 H_SELECT 成绩最好的一个。共 160 格。融合与迁移优先从档案取成员。
- **冠军**：全局 H_SELECT 配对超额最高者为"本代冠军候选"，再过 5.1 的留出检验。

## 5.3 变异算子（每次变异记录算子名）

| 算子 | 作用 | 是否算"结构变化" |
|---|---|---|
| `M_CONST` | 常数高斯扰动（σ=0.1×|c|+0.01） | 否（参数变体） |
| `M_WINDOW` | 窗口尺度换到相邻尺度（8↔32↔128…） | 否 |
| `M_LEAF` | 替换一个叶子为同类型另一叶子 | 是 |
| `M_SUBTREE` | 随机子树替换为新生成子树（深度≤3） | 是 |
| `M_HOIST` | 用子树替换整棵树（简化） | 是 |
| `M_WRAP` | 在子树外包一层 sigmoid/rank/ema/ifGreater | 是 |
| `M_PRUNE` | 删除贡献 < 1% 的分支（按消融测量） | 是 |
| `M_FAMILY` | 把一个叶子替换为家族模型调用 `family(Fxx)` | 是 |
| `M_GATE` | 加/删状态门控（I06 风格） | 是 |
| `M_SELECTOR` | 只改出手阈值、位置规则 | 否（但单独记 `SELECTOR_VARIANT`） |
| `M_UPDATER` | 改在线学习率/遗忘率 | 否 |

`NO_OP` 检测：变异后在500期探针上的行为签名与父代一致 → 记 `NO_OP`，不计代、不进入回放。

## 5.4 交叉与融合

- **子树交叉 `X_SUBTREE`**：两个父代各取一棵子树互换（类型兼容才允许）。
- **输入交叉 `X_INPUT`**：子代继承 A 的模型 + B 的特征组。
- **融合 `F_STACK`**：从档案选 2—5 个成员，要求两两预测相关度 < 0.6；融合方式三选一：
  - 对数几率加权平均（权重在 H_TRAIN 上拟合，L2）；
  - 状态门控（I06 的 regime 决定用哪个成员）；
  - 投票＋校准（每位置取成员 K3 的并集频率，再用 H_TRAIN 拟合温度）。
  融合产物是 **新策略**（新 policyHash），成员保持不变；融合的权重、成员列表进谱系（多父代边）。
- 父代 **权重可继承**（warm start），父代 **成绩不可继承**：子代必须自己跑回放与留出。

## 5.5 淘汰：快速、分级、留档

用"连续减半"（successive halving）在回放上快速淘汰，资源集中给有希望的候选：

| 轮 | 样本 | 保留比例 | 淘汰规则 |
|---|---|---|---|
| R0 | H_SELECT 最近 500 期 | 50% | 按 H_SELECT 配对超额 u 均值排序；同时 **出手率 < 1% 或 > 60% 的直接淘汰**（无法执行或等于全买） |
| R1 | H_SELECT 最近 1500 期 | 50% | 同上 + Brier 不得比常数0.30预测差超过0.005 |
| R2 | H_SELECT 全段（≈1250—3000期） | 50% | 同上 + 720期分块最差命中率不得低于 22% |
| R3 | 进入种群（活跃上限256） | — | 种群满时，H_SELECT 成绩最差且不占档案格的个体移出 |

- 被淘汰者 **不删除**：spec、成绩、淘汰轮次与原因写入档案 `r27_policy.state='RETIRED'`，可被将来融合/迁移重新拿出来（但要重新跑回放）。
- 实时影子池（32个）内的策略：用第08章序贯检验，判定"不优于基线"即退出影子池，回到档案；判定"优于基线"进入资格流程。
- 这就是用户要的"太垃圾没用的算法公式应该被淘汰掉"：在回放上几秒到几分钟就能淘汰，不需要等120个实时标签。

**提醒（写进界面帮助）：** 在数据确实独立的情况下，淘汰赛选出来的冠军在 H_SELECT 上的优势主要来自运气（第01章 D 表）；所以晋升必须看 5.1 的留出检验和第08章的实时检验。

## 5.6 每代流程（`EvolutionLoopR27.step`，可中断、可恢复）

```
1. 读取当前数据集快照（datasetHash）；若 daily-close 滚动了分段 → 本代结束后切换
2. 出生：思路族生成 + 变异(60%) + 交叉(20%) + 融合(10%) + 专家提案(≤10%)  → 128 个
3. 可执行检查 + 行为去重
4. 回放：H_TRAIN 训练、H_SELECT 评估（并行，ResearchPool）
5. 连续减半淘汰 R0→R2；更新岛屿与档案
6. 冠军候选：H_HOLDOUT 配对检验（对上一代冠军、I00 冠军、打乱标签冠军）
7. 写谱系 r27_lineage、代际总结 r27_generation、七计数
8. 若 VERIFIED_IMPROVEMENT 且影子池有空位/可替换 → 晋升到实时影子池
9. 每 5 代岛间迁移；每 20 代运行一次消融（冠军每个分支删除后的 H_SELECT 变化）
```

断点：每一步完成写游标 `r27_evolution_cursor(generation, step, dataset_hash, rng_state)`；进程被杀后从最后完成的步骤继续，不重复登记出生。

## 5.7 负对照进化（必须同时运行）

`NullEvolutionR27`：与主进化 **完全相同** 的流程、相同算力配额的 10%，但训练与挑选所用的标签按片段随机打乱（每代重新打乱）。它的冠军在 H_HOLDOUT 与 LIVE 上的成绩与主冠军并排显示。

- 若主冠军显著好于负对照冠军 → 说明主进化找到的东西不只是噪声。
- 若两者无显著差异 → 报告与界面显示"当前进化成果与随机对照无差别"。

## 5.8 进化停滞时的自动诊断（写进报告"进化"章）

| 现象 | 可能原因 | 系统自动动作 |
|---|---|---|
| 训练段持续上升、留出无提升、负对照同样上升 | 拟合噪声；数据无可学信号 | 标"无证据提升"；降低复杂度上限（深度6→4）一个周期做对照 |
| 所有岛冠军行为相关度 > 0.9 | 多样性坍缩 | 提高迁移间隔、扩大档案格采样、给低存活族加名额 |
| 出生拒绝率 > 50% | 生成器/类型系统问题 | 按拒绝原因分布告警到对应思路族 |
| NO_OP 比例 > 30% | 变异算子无效 | 降低 M_CONST/M_WINDOW 比例 |
| 回放耗时占比 > 80% 且每代 > 30分钟 | 算力不足 | 报告容量缺口，减少每代出生数（不减少思路族数） |
