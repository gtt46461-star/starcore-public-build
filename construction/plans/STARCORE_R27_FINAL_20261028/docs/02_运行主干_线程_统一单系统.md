# 02 运行主干、线程模型与统一单系统（R27-B01、R27-B04）

## 2.1 目标

1. 用户开启软件后，P0（抓取→落库→结算→冻结）永远准时；研究（训练、回放、创造、进化、评估）在 P0 之外 **持续占满分配的CPU**，而不是只有3.8%。
2. 只保留 **一套** 研究系统、一个任务注册表、一套账本、一套图表数据源。
3. 每个任务每时每刻都能说清"在干什么 / 为什么没干"，不再有笼统的 DATA_NOT_READY。

## 2.2 线程与数据库连接模型

| 组件 | 线程 | 数据库连接 | 说明 |
|---|---|---|---|
| P0Executor | 1个专用线程，`THREAD_PRIORITY_DEFAULT` | 唯一写连接（经 `DatabaseCoordinator`） | 抓取解析、原始落库、`SettlementEngine` 唯一结算、`DecisionGateEngine` 唯一授权、冻结写入 |
| ResearchPool | `max(1, min(4, 可用核数−2))` 个线程，`THREAD_PRIORITY_BACKGROUND+1`；初值2，按第12章实测调整 | 每线程1个 **只读** WAL 连接（`SQLiteDatabase.openDatabase(...,OPEN_READONLY)`，`PRAGMA query_only=1`） | 全部计算在内存完成；不持有写锁 |
| ResearchWriteQueue | 不单独开线程；由 P0Executor 在空档或研究线程经协调器提交 | 共用唯一写连接 | 每个提交 ≤ 20ms、≤ 500行；超出则分块 |
| UI | 主线程 | 只读 | 图表经 `ChartsRepositoryR27` 读取，取消信号 50ms 内生效 |

要点：

- SQLite WAL 允许"一个写者＋多个读者"同时进行，研究读快照不会阻塞 P0 写入。
- 研究线程在计算期间 **不看** `RealtimePressureGateR811`。只有提交写入时，写队列在 P0 正在写或距冻结截止 < 3秒时等待（单次等待上限200ms，然后重排队）。这把"让路"从"整段分钟级"缩小到"毫秒级写窗口"。
- `RuntimeCoordinatorR26.preempt()` 的会话级 `BLOCKED:CRITICAL_DEADLINE` 删除；保留真实资源原因：`MEMORY_PRESSURE`（`lowMemory` 或堆 < 64MiB）、`THERMAL_SEVERE`、用户停止。
- 冻结截止前3秒到冻结提交完成：ResearchPool 降到1个线程（不是0），避免抢 CPU 导致冻结超时。

## 2.3 真实阻塞原因枚举（替换 DATA_NOT_READY）

每个任务每次执行后必须写入以下之一（新列 `r26_task.wait_kind`、`wait_detail`）：

| wait_kind | 含义 | 示例 detail |
|---|---|---|
| `PROGRESS` | 本片有产出 | `samples=4800` |
| `NO_NEW_EVENT` | 输入游标已追平，等待新开奖 | `cursor=3589230,latest=3589230` |
| `DEPENDENCY(<task>)` | 依赖的上游任务未产出 | `DEPENDENCY(replay-dataset)` |
| `DEADLINE_MISSED` | 赶不上本期截止 | `target=202610280752,lateMs=1820` |
| `RESOURCE(<kind>)` | 内存/热/存储 | `RESOURCE(THERMAL_SEVERE)` |
| `ERROR(<class>)` | 异常 | `ERROR(IllegalStateException:...)`，同时进入 `r27_task_error` 留全栈 |
| `DISABLED_BY_USER` | 用户停止 | — |

规则：

- 同一任务连续30分钟 `wait_kind ∉ {PROGRESS, NO_NEW_EVENT}` → 报告与界面红色告警"任务卡住"，显示 detail。
- 任务注册后60分钟游标仍为0 → "从未运行"告警（本次报告中的 legacy-replay、feedback、ablation 等就会被立刻点名）。
- `ERROR` 不重试超过5次/10分钟；第6次进入 `QUARANTINED`，界面可手动重试。

## 2.4 统一单系统：旧 R9xx 研究链并入 R26/R27

当前问题见00章0.5。处理原则：**新系统是唯一 Owner；旧系统的资产（算法、公式、权重、历史成绩）作为种子导入，旧调度全部退役。**

| 旧组件 | 处理 | 导入到 |
|---|---|---|
| `ResearchLearningContinuityR912` 22条 lane | 退役调度；保留只读查询供报告"历史"章 | — |
| R908 算法（43个，`TABLE_R908_ALGORITHM_PREDRAW` 等） | 每个算法的 AST/参数导出为 `PolicySpecR27`（第04章 DSL）；能复现的作为 F22/F23 家族种子；不能复现的标 `LEGACY_NOT_REPRODUCIBLE` 留档 | `r27_policy` |
| CP12 家族学习器 `r967_numeric_training_run` | 权重作为 warm start 导入；**旧未来样本不继承**，但可在第03章回放中立刻获得新的回放/留出成绩 | `r27_checkpoint` |
| `AtomicToolWorldR943` 原子网络 | 迁入第06章 `AtomNetR27`；240原子注册表 `GenesisSchemaRegistryR915.atoms()` 原样复用 | `r27_atom_*` |
| `AssetGenesisEngineR915` 进化事件表 `research_evolution_event_v41` | 停写；图表改读 `r27_lineage`/`r26_evolution` | — |
| `r974_model_lineage` | 停写；历史行一次性导入 `r27_lineage`（`origin='R974'`） | `r27_lineage` |
| R932 校准/固定窗口/证书 | 校准算法保留（第07章修正后复用）；固定窗口与证书统一由第08章 `QualificationR27` 负责 | — |
| `ProductionPredictionDispatcherR815` → `DecisionGateEngine` → `SettlementEngine` | **不动**。唯一REAL与唯一结算 Owner 保持 | — |

迁移顺序（避免中途两套都停）：

1. R27 新链跑通回放与影子冻结、图表显示新数据（B03、B05、B10 完成）。
2. 开关 `r27_legacy_research_enabled` 默认仍为1，旧链与新链并行一个观察期（≥ 1440期）。
3. 对照报告中"旧链产出 vs 新链产出"，新链覆盖全部功能后把开关置0；旧 lane 调度不再注册。
4. 旧表保留只读，按 `RetentionTableRegistryCP12` 规则定期归档，不删历史证据。

## 2.5 P0 主链的时间保证

- 开奖到达（firstSeen）→ 原始落库 → 结算：P95 ≤ 1s。
- 下一目标期冻结：目标在 **开盘前 ≥ 10s** 完成（每期60s，上期开奖后立即开始准备）。
- 冻结只读取"已准备好的预测"（`r26_prepared_forecast`），准备工作由 ResearchPool 在上一期结算后立刻做；冻结本身是一次小写入。这解决 `incumbent-forecast` 的 `INCUMBENT_MISSING_AFTER_OPEN`（00章0.4）和 lane0 的 `TARGET_DEADLINE_PASSED_NO_RETROACTIVE_CAPTURE`。
- 截止后不补冻结（保持现有正确规则），记 `DEADLINE_MISSED` 并计入机会分母。
